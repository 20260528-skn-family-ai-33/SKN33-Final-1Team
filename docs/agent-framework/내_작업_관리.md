# 내 대기 작업 취소와 이력 숨기기

2026-11-09 · AWS_TEST · 기존 PostgreSQL AF001–AF005와 데스크톱 프론트

## 사용자 동작

상단 **내 작업** 또는 `/review/tasks`에서 자신이 요청한 문서 분석·포스터 검수를 조회한다. 영상 API의 작업 목록은 이 화면에 포함하지 않는다.

- **대기 취소**: 아직 워커가 가져가지 않은 자기 작업만 취소한다. 문서·포스터 진행 화면에서도 서버 접수 후 대기 중이면 같은 취소 동작을 제공한다.
- **이력 숨기기**: 완료·실패·취소된 자기 실행을 기본 목록에서 숨긴다. **숨긴 이력 → 다시 표시**로 복원한다.
- 처리 중, 기준 확인, 포스터 등록, 담당자 승인, 수정본 대기, 결과 불명 상태는 숨길 수 없다. 사람이 해야 할 작업은 목록에 남긴다.
- 원본 문서·포스터, 결과, 기준 버전, 승인, 실행·감사 기록은 삭제하지 않는다. 숨긴 실행의 기존 링크도 유지한다.

문서 분석 취소 후에는 명시적으로 다시 업로드할 때 새 요청 키를 만든다. 취소된 실행을 자동 재접수하거나 추론을 재시도하지 않는다.

## API와 저장 방식

| 요청 | 동작 |
|---|---|
| `GET /api/framework/v1/my-tasks` | `visibility=visible\|hidden\|all`, `limit`(기본 30), `before` 실행 ID로 페이지 조회 |
| `POST /api/framework/v1/runs/{run_id}/cancel` | 대기 작업 취소. 이미 워커가 가져갔으면 HTTP 409 |
| `POST /api/framework/v1/runs/{run_id}/history-visibility` | JSON `{"hidden": true}` 또는 `{"hidden": false}` |

기존 로그인·CSRF·프로젝트 권한을 적용한다. `runs.actor_id`가 현재 사용자와 같고 프로젝트 멤버십이 유효해야 한다. 같은 프로젝트의 다른 소유자라도 다른 사람의 작업은 취소하거나 숨길 수 없다. 프로젝트 viewer는 자기 이력 표시만 바꿀 수 있고 취소는 할 수 없다.

취소는 워커와 같은 **프로젝트 → 실행 → 작업** 잠금 순서를 사용한다. 워커 선점이 먼저면 취소를 거부하고, 취소가 먼저면 워커가 해당 작업을 가져가지 못한다. 응답 유실 뒤 같은 취소를 재요청해도 중복 처리하지 않는다.

공유 DB의 기존 상태 제약과 구버전 워커 호환을 위해 취소는 기존 `failed` 종료 상태와 오류 코드 `USER_CANCELLED`로 저장한다. 내 작업 화면에서는 **취소됨**으로 표시한다. 기존 종료 이벤트와 별도로 `job.cancelled` 이벤트를 기록하며 운영 집계에서도 일반 모델 실패와 구분해야 한다.

숨김은 실행 데이터를 수정하지 않고 `history.visibility_changed` 이벤트에 요청 사용자와 `hidden` 값을 추가한다. 사용자별 최신 이벤트를 조회에 반영한다. 동일 상태의 재요청은 이벤트를 중복 생성하지 않는다. 스키마 마이그레이션은 없다.

## 검증 범위

- 일회용 PostgreSQL: 새 관리 기능과 기존 큐 통합 **30개 통과**. 선점/취소 경쟁, 다른 사용자 접근 차단, 멤버십 회수, 숨김/복원, 승인·원본 보존, 페이지 조회를 검사했다.
- 관련 A02·PostgreSQL 명령 검사 **49개 통과**. 앞서 수정한 A02 미정 필드 보정도 같은 AWS_TEST 코드에 보존했다.
- 프론트 단위 **126개**, 새 브라우저 UI **2개**, 기존 진입·메뉴 초기화 UI **6개** 통과. 타입 검사·배포 빌드도 통과했다.
- 실제 AWS_TEST: 로그인 계정의 목록 표시와 실패 실행 한 건의 숨김 → 숨긴 목록 조회 → 복원을 확인했다. 해당 실행은 다시 기본 목록에 표시되도록 복원했다.
- 실제 AWS에서 새 모델 작업을 생성해 취소하지는 않았다. 취소·선점 경쟁은 격리 PostgreSQL과 합성 API 브라우저에서 검증했다. 운영 데이터 전체를 정리하거나 모델 검수를 다시 실행한 것은 아니다.

## 복구와 다음 배포

- 정상적인 후속 배포에서는 커밋된 동일 코드로 API·워커 이미지를 함께 빌드하고 runtime 일치를 확인한다. `frontend/dist`와 프론트 소스도 함께 커밋한다.
- 테스트 API 롤백이 필요하면 API 호스트 `/etc/nginx/conf.d/creative-checker-framework-aws-test-map.conf.before-my-tasks` 백업을 검토하고 테스트 포트만 `8016`에서 기존 `8014`로 돌린 뒤 `nginx -t`와 reload를 수행한다. 이 파일의 비밀 라우팅 값을 로그·문서·Git에 출력하지 않는다.
- 이전 API로 돌아가도 새 runtime의 대기·실행 작업이 남아 있으면 새 워커는 유지한다. 조회·종료 여부를 확인하기 전 컨테이너·기록을 삭제하지 않는다.
- 이번 기능에는 데이터 삭제나 역마이그레이션 절차가 없다. 프론트를 되돌려도 기존 숨김 이벤트·취소 기록은 보존한다.
