# A06 검증 계약 3.0.0

A06은 별도 모델 호출 없이 승인 기준, A04/A05 관측, 고정 근거를 검증한다. 기존 `ReferenceValidator`와 `invoke_role`을 사용하며 DB 조회·사람 승인·모델 재검사를 수행하지 않는다.

## 입력과 결과

`Observation.observed`에는 관측 원문을 보존한다. `observation_status`는 다음 상태를 사용하며 생략하면 `unknown`이다.

| 상태 | 의미와 처리 |
|---|---|
| `observed` | 검사해 값을 관측함. 빈 관측 문자열은 `review` |
| `absent` | 검사 후 부재를 보고함. 문구·시각 존재 조건에서 충분한 근거와 `fail`이 함께 있을 때만 확정 위반 |
| `unreadable` | 판독 불가. `review` |
| `not_checked` | 미검사. `review` |
| `unknown` | 관측 상태 불명. `review` |

관측 단위는 `observed_unit`에 적는다. 기대 단위를 관측 단위로 복사하지 않는다. 숫자 관측이 없거나 부재 상태이면 0으로 추정하지 않는다. 위치를 모르면 기존 `ImageEvidence.bbox`를 비워 둔다.

`ValidatedItem`은 조건 ID·내용·종류·연산자·필수 여부, 기대값과 단위, 관측 원문과 단위·상태를 보존한다. 실제 비교값은 `comparison_expected`, `comparison_observed`, `comparison_unit`에 담고 비교하지 못했으면 비워 둔다. 기존 `issues`는 판정 사유이며 `evidence_ids`와 `image`는 입력 근거를 그대로 연결한다. A07은 이 구조화된 결과를 받아 설명을 작성한다.

## 판정 규칙

- 프로젝트·실행·버전·해시·인용 관계가 잘못되면 입력 오류로 거부한다. 승인 조건은 빠짐없이 결과에 포함한다.
- 항목의 근거가 불완전하거나 관측이 불확실하면 값이 달라도 `review`다. 다른 필수 항목에 충분한 근거를 갖춘 확정 위반이 있으면 전체 `fail`은 유지한다.
- 문구는 `equals`·`contains`로 원문 그대로 비교한다. 공백·줄바꿈·문장부호와 의미 유사도를 자동 보정하지 않는다. 빈 기대값은 `review`다.
- 문구·시각 존재 조건에서 `absent`를 보고해도 비어 있지 않은 기대값과 관측 원문이 같으면 `verdict_conflict`와 `review`다. 문구의 `contains` 조건을 관측 원문이 충족하는 경우도 같다. 부재 보고와 모순된 관측으로 확정 위반을 만들지 않는다.
- 숫자는 부호·소수점·정상적인 세 자리 쉼표와 단위 접미 표기를 처리한다. `10,000원`과 `10000 원`은 비교할 수 있다. 숫자와 단위를 별도 필드로 전달해도 된다. 접미 단위와 선언 단위가 다르면 `review`다.
- 쉼표로 묶은 숫자의 첫 묶음은 0으로 시작하지 않는 1~3자리여야 한다. `0,001`·`0,500`·`001,000`은 기대값과 관측값 모두 `review`로 처리하고, 소수점 표기로 추정하지 않는다. `0.001`·`1,000`·`1,000,000`은 지원한다.
- 단위는 정확히 같아야 한다. 단위 변환·별칭 변환, 통화 기호 접두 표기, 지수 표기, 숫자가 섞인 설명문, 날짜 형식 변환은 지원하지 않는다. 잘못된 숫자·단위 누락·단위 불일치는 `review`다. 단위 없는 순수 수치는 양쪽 모두 단위가 없을 때 비교한다.
- 시각 조건은 `visual/present`만 지원한다. 존재 상태와 `fail`, 부재 상태와 `pass`처럼 모순된 결과는 `review`다. 비율·색상·배치 등 지원하지 않는 조건은 추출·기준 승인 단계에서 `manual` 또는 `unsupported`로 표시한다. A06이 조건 문장의 의미를 다시 분류하지 않는다.
- 전체 판정은 필수 조건만 집계한다. 확정 위반이 있으면 `fail`, 그 외 보류가 있으면 `review`, 적용 필수 조건이 있고 모두 충족하면 `pass`다. 필수 조건이 없으면 `review`다. 권장 조건의 결과도 보고 입력에 남긴다.

사용자 정의 A06도 보류를 임의로 통과·위반으로 바꾸거나 확정 위반을 숨길 수 없다. 비교값·필수 여부·근거를 입력과 다르게 반환하면 공통 출력 경계에서 거부한다. 기존 사람 승인 정책은 유지한다. 새 사유 `observed_absence`는 자동으로 예외 승인 허용 사유가 되지 않는다.

같은 입력에 대해 참조 검증기가 `pass`로 판정한 항목을 사용자 정의 A06이 `fail`로 바꾸면 `VALIDATOR_UNSUPPORTED_FAILURE`로 거부한다. 승인 기준과 관측으로 뒷받침되지 않는 위반을 확정하지 않기 위한 규칙이다. 추가 확인이 필요하면 `review`로 낮추고 사유를 덧붙일 수 있다. 참조 검증기의 사유를 삭제하거나 사유가 남은 항목을 `pass`로 반환할 수 없다.

## 팀 전환

계약 1.0.0·2.0.0 요청과 설정은 거부한다. A02·A04/A05·A07·공통 담당자가 새 계약을 함께 적용하고 생성된 `examples/agent_framework/`의 설정·JSON·스키마를 기준으로 연결한다. HTTP 경로 `/api/framework/v1`은 유지한다. 구버전 저장 실행은 자동 변환하거나 새 코드로 재개하지 않으며 기존 기록을 보존한다.

계약 산출물은 `uv run python -m scripts.export_agent_framework`로 재생성한다. 코드와 연결된 흐름도·소스 보기는 `uv run python -m scripts.build_agent_flow_html`로 갱신한다. 기존 공유 ZIP·코드 그래프·다른 설명 HTML은 이전 시점의 자료이며 이 변경으로 재생성하지 않는다.

## 검증 범위

`uv run pytest tests/agent_framework -q`로 독립 판정, 공통 호출 경계, A07 전달, 생성 계약의 일치를 검사한다. 기본 설정은 실제 PostgreSQL 통합 검사를 제외한다.

독립 계약 검증과 실제 A04/A05→A06→A07 모델 연동 검증은 별개다. 합성 사례 통과는 이미지 인식 정확도나 운영 배포의 증거가 아니다. A06은 모델의 관측 자체와 A07 자유서술의 의미적 정확성을 독립적으로 보장하지 않는다.
