COMMON CONTRACTS / INDEPENDENT ADAPTERS

개발 시작하기.

HTML만 읽을 때는 설치가 필요 없습니다. 합성 데모와 테스트를 실행하려면 Python 3.12 또는 3.13과 uv를 준비하세요.

Git 저장소의 프로젝트 루트가 개발 기준입니다. 담당자별 연결 가이드에서 수정할 파일과 테스트 명령을 확인하세요.

1. 공통 의존성 설치

터미널에서 pyproject.toml과 uv.lock이 있는 프로젝트 루트로 이동합니다.

uv sync --locked --group dev

의존성을 처음 설치할 때는 인터넷이 필요합니다. 아래 명령은 가상환경을 별도로 활성화하지 않아도 실행됩니다.

2. macOS 터미널

.venv/bin/python -m backend.agent_framework demo
.venv/bin/python -m pytest tests/agent_framework -q

3. Windows PowerShell

.\.venv\Scripts\python.exe -m backend.agent_framework demo
.\.venv\Scripts\python.exe -m pytest tests/agent_framework -q

4. 담당 역할 연결

공통 포트에 맞춘 어댑터를 만든 뒤 factory를 지정합니다. A02, A03, A04_A05, A06, A07 단독 실행과 합성 예제를 제공합니다.

  • 전체 개발 가이드와 역할·계약 규칙
  • 입출력 포트와 어댑터 연결 규격
  • 합성 JSON 예제 안내
  • 기존 로컬 검증 기록

5. 역할별 설정과 개발 API

전체 역할을 한 factory에 묶지 않고, 담당 역할의 factory만 설정할 수 있습니다. 설정을 검사하는 doctor는 모듈을 import하거나 모델·DB에 연결하지 않습니다.

# macOS
.venv/bin/python -m backend.agent_framework doctor --config examples/agent_framework/team_config.synthetic.json
.venv/bin/python -m backend.agent_framework role A03 --input examples/agent_framework/A03.json --config examples/agent_framework/team_config.synthetic.json
.venv/bin/python -m backend.agent_framework serve --config examples/agent_framework/team_config.synthetic.json --port 8012

# Windows PowerShell
.\.venv\Scripts\python.exe -m backend.agent_framework doctor --config examples/agent_framework/team_config.synthetic.json
.\.venv\Scripts\python.exe -m backend.agent_framework serve --config examples/agent_framework/team_config.synthetic.json --port 8012

serve는 별도 개발 API를 127.0.0.1에서 실행합니다. 구성 파일의 factory는 신뢰된 로컬 코드만 지정하세요. 역할 단독 실행은 선택한 역할만 초기화하고, API 시작은 전체 역할을 초기화합니다. 자동 승인이나 실서비스 연결 확인을 수행하지 않습니다.

  • 합성 전체 구성
  • 미설정 역할 템플릿
  • 역할별 factory 시작 코드

demo의 사람 승인은 테스트 값이고 실행 상태는 메모리에만 저장됩니다. 실제 모델·DB 연결이나 운영 권한·복구를 검증하는 명령이 아닙니다.

6. 담당 어댑터의 계약 검사

check는 선택한 역할에 여러 요청 예제를 넣고 기대한 결과와 비교합니다. 정상 불합격·확인 필요 판정도 유효한 결과로 검사하며, 호출 결과가 불명확하면 후속 사례를 중단합니다.

# macOS
.venv/bin/python -m backend.agent_framework check A06 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A06.suite.json

# Windows PowerShell
.\.venv\Scripts\python.exe -m backend.agent_framework check A06 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A06.suite.json

기본 묶음은 5개 역할의 합성 사례 17개입니다. 실제 PDF·포스터 파일은 포함하지 않으므로 실서비스 어댑터에는 별도의 개발 입력을 준비하세요. 상대 입력 경로는 suite 파일 기준이며, --output 보고서.json을 지정하면 실패 결과도 저장합니다. 보고서의 passed는 기대와의 일치이고 실모델 정확도나 DB 연결 증명이 아닙니다.

7. 실제 파일 읽기 연결부 확인

FileAccess는 기존 파일·버전·권한 조회와 저장소를 재사용하고 실제 바이트의 해시·형식·치수를 검사합니다. 아래 예제는 생성 PDF·PNG를 기존 파일 서비스로 임시 저장한 뒤 읽으며, 운영 DB·모델에 연결하지 않습니다.

# macOS
.venv/bin/python -m examples.agent_framework.file_access_demo

# Windows PowerShell
.\.venv\Scripts\python.exe -m examples.agent_framework.file_access_demo

재구축 creative_checker 경로는 PDF·포스터, M008 경로는 포스터를 지원합니다. M008의 기존 POSIX 저장소는 Windows 지원 대상이 아닙니다. 제품 API에 자동 연결하지 않으며 인증이 확인된 주체와 기존 저장소를 호출자가 주입합니다. 원본 바이트와 EXIF 표시 좌표는 구분합니다.

8. 단계별 실행 기록

demo 출력의 runs[].step_records 또는 같은 Workflow 객체의 get_steps(run_id)에서 역할별 상태·UTC 시작/종료 시각·소요 시간·오류 코드를 확인합니다. 개발 API는 GET /api/framework/v1/runs/실행ID/steps를 제공합니다. 어댑터가 실행 중이어도 조회할 수 있으며 시작·승인 요청은 동기식으로 완료를 기다립니다.

상태는 running·completed·failed·outcome_unknown·reused로 구분합니다. 재검수의 A02는 부모 실행의 조건 재사용을 표시하며 새로운 호출 시간이나 소요 시간을 만들지 않습니다. 오류 뒤에는 후속 역할을 실행하지 않고 자동 재시도도 하지 않습니다. 사람 승인 대기는 역할 소요 시간에 포함하지 않습니다. 단계 completed는 검수 통과나 최종 승인이 아닙니다.

기록은 메모리에만 존재하며 프로세스 재시작 후 사라집니다. CLI와 별도로 실행한 API는 기록을 공유하지 않습니다. 역할 단독 role/check 명령은 Workflow 이력을 만들지 않습니다. PostgreSQL 영속 기록·worker·운영 인증은 후속 단계입니다.

9. 설정한 어댑터의 전체 흐름 검증

check-flow는 구성한 다섯 역할로 조건 승인→검사·보고→수정 승인→새 버전 전체 재검수→최종 테스트 승인을 확인합니다. 오류·기대 불일치·결과 불명 뒤에는 후속 동작을 건너뛰며 자동 재시도하지 않습니다.

# macOS
.venv/bin/python -m backend.agent_framework check-flow --config examples/agent_framework/team_config.synthetic.json --case examples/agent_framework/workflow.synthetic.json
.venv/bin/python -m examples.agent_framework.file_flow_demo

# Windows PowerShell
.\.venv\Scripts\python.exe -m backend.agent_framework check-flow --config examples/agent_framework/team_config.synthetic.json --case examples/agent_framework/workflow.synthetic.json
.\.venv\Scripts\python.exe -m examples.agent_framework.file_flow_demo

--output 보고서.json으로 상태·판정·단계 시간·오류·정규 JSON 해시를 남깁니다. 전체 기대 일치 0, 실행 실패·불일치 1, 입력·설정 오류 2를 반환합니다. 기본 사례는 실제 미디어가 없는 합성 참조이므로 담당 어댑터에는 별도 개발 입력을 준비하세요.

file_flow_demo는 생성 PDF·두 PNG를 기존 파일 저장소와 임시 SQLite에 등록하고 설정 factory·파일 검증·텍스트/픽셀 테스트 콜백으로 불합격→수정본 통과→테스트 최종 승인을 확인합니다. 모델 호출은 0회이며 합성 검색·보고·테스트 승인을 사용합니다. 예제의 임시 factory 의존성은 상시 서비스 설정용이 아닙니다.
