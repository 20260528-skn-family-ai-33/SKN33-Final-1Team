# A02 실제 연결 검증 기록

2026-11-04 · Mac Docker API·worker → RunPod Qwen → 기존 PostgreSQL AF004

## 확인 범위

사용자가 새 이미지를 빌드하고 기존 DB를 백업한 뒤 AF004를 적용했다. 마이그레이션과 app 계정 검사 응답은 모두 `AF004`, `public_schema="M008 unchanged"`였다. 자유 입력·PDF 원문 등록/재조회, 실제 Qwen 추론, worker의 초안 저장, API 재조회까지 확인했다.

입력은 개발용 예시다. PDF에도 가상 클라이언트 의뢰서라고 명시되어 있다. 모델·DB 연결은 실제 개발 환경에서 실행했고 두 응답의 `synthetic=false`를 확인했다. 실제 발주, 클라이언트의 기준 승인, 포스터 검사·최종 승인은 별도 단계다.

두 결과 모두 `mode=qwen`, `policy=a02-semantic-v3`, 모든 반환 조건의 `origin=model_structured`다. PDF·자유 입력의 모델 프롬프트 해시도 현재 코드와 일치했다. 두 실행의 승인 목록은 비어 있다.

자유 입력에서는 행사명·시작일·종료일·장소·로고를 분리했다. `2026.10.23 ~ 10.25`의 원문을 보존하고 시작일·종료일의 정규화 값은 각각 `2026-10-23`, `2026-10-25`였다.

PDF에서는 제목 두 구절, 연도, 개막일, 요일, 장소, 사진 콜라주, 색상 조합, 파일 형식, 가로·세로 크기, 색상 모드, 미정 관람시간이 반환됐다. 포스터 문구·시각 조건·파일 메타데이터를 구분하고 날짜의 원문 근거와 허용 범위를 보존했다.

## 원문 대조와 사람 검토 경계

- PDF 2쪽에 `관람시간 - 확인 중`과 담당자 회신 후 반영하라는 안내가 있다. 실제 관람 요일·시작/종료 시각·휴관일 값은 없다.
- `c013`은 원문과 함께 미정 항목으로 유지하고 사람에게 확인 필요를 알린다. 앞서 안내한 ‘제외 사유를 남긴 12개 보완 버전 저장’은 작성자의 제안이었으며 사용자의 제외 결정이나 기획서의 지시가 아니다. 제외 버전과 승인 API는 접수하지 않았다. 화면의 값이 있는 문단 12개와 미정 안내 1개 구분은 표시 방식이며 기준 변경·제외·승인이 아니다.
- PDF 1쪽의 `디지털 포스터 파일 1점`과 `제목과 안내 정보를 구분해 주세요`는 이번 목록에서 독립 조건으로 반환되지 않았다. 검수 범위를 대조할 후속 검토 항목이다. 조건 수 13개가 전체 요구사항의 완전한 추출을 증명하지는 않는다.
- `file_format`의 값은 `JPEG (.jpg 또는 .jpeg)`이고 일부 `qualifiers`에는 일반 원문도 반복됐다. 원문은 보존됐으나 최종 판정에 사용할 형식 식별자·허용 범위는 기준 검토와 후속 검사 연결에서 확인해야 한다.

확정값을 만들어 채우거나 기존 미정 초안·승인 차단을 일괄 해제하지 않는다. 수정·제외는 사람이 명시적으로 결정한 뒤에만 원본과 분리한 새 버전에 사유·출처를 남긴다. 문서에 없는 내용을 필수 요구사항으로 임의 추가하지 않는다. 이 두 사례로 일반 추출 정확도·모든 조건의 누락 없음·관계 검색·실제 포스터 판정 완료를 주장하지 않는다.

## 실행 시 유지할 프로세스

1. RunPod Qwen 서버: 컨테이너 안 `127.0.0.1:8015`.
2. Mac SSH 터널: `127.0.0.1:18015`에서 Qwen으로 전달. `ssh -N`은 연결 후 출력 없이 대기한다.
3. 프레임워크 API: Mac `127.0.0.1:8012`에 공개한 Docker 프로세스.
4. 별도 프레임워크 worker: 같은 app env·600초 Qwen 설정·저장 볼륨 사용.

현재 명령은 전경 실행이다. 터미널을 종료하면 해당 프로세스도 종료되므로 API·worker·SSH 터널은 각 전용 창에서 유지한다. worker의 `ready`는 접수 대기 상태이며, 실제 추출의 확인 근거는 실행 결과·모델 trace·저장 후 재조회다.

다음 단계는 원문 대조·검수 범위 정리 → 새 기준 버전 → 사용자의 명시적 승인 → 승인 버전 재조회다. 단독 `1`이나 이번 추출 결과의 전달을 기준 승인으로 기록하지 않는다.

## 후속 v4 문단 출력과 사용자 화면 확인

사용자가 presentation 설정으로 Docker 이미지를 빌드하고 API·worker·Vite를 다시 실행했다. 프론트 5173·A02 프록시 health·Qwen 터널 18015에서 HTTP 200, API의 `pdf_extraction_mode=qwen`, `requirements_presentation=true`를 읽기 전용으로 확인했다.

사용자는 전시 제작의뢰서 PDF를 올린 뒤 완료를 알렸다. 진행 중 화면에서 `extracting` 단계의 60%와 경과 시간을 확인했고, 후속 크롬 화면에서 `poster.jpg`와 12개 기준을 확인했다. 이 절에서는 해당 새 실행의 전체 모델 trace·DB 승인 기록을 별도로 재조회한 것으로 기록하지 않는다. 원본 PDF·포스터의 경로와 재실행 명령은 [A02 실행·사용 가이드](A02_실행_사용가이드.html)에 정리했다.

사용자는 이후 포스터 검수를 실행한 상태였으며 화면에는 HTTP 500이 표시됐다. 이번 A02 전용 API·worker·프론트 구성의 문단 반영과 A04·A05 실제 포스터 검사 성공은 구분한다. 오류 원인을 이 화면만으로 확정하거나 재시도하지 않았으며, 기준의 DB 승인·최종 승인·AWS 배포 완료를 주장하지 않는다.
