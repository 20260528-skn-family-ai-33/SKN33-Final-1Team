01. 최신 기준과 변경 사항

11월 2일 프로젝트 통합문서의 10/30 역할 결정을 적용한다. 독립 A03 검색·근거 에이전트는 폐기한다. 설정·factory·CLI·worker 단계에 A03을 추가하지 않는다. A01–A08은 과거부터 사용한 추적 번호이며 현재 여덟 개 에이전트를 뜻하지 않는다.

현재 구성 가능한 역할은 A02, A04_A05, A06, A07 네 개다. A01 실행 조정과 A08 재검수 연결은 공통 코드이며 별도의 모델 factory가 없다. A04·A05는 동일 Qwen3.5-4B를 사용하는 통합 검사 포트다. 별도 OCR 기본·보조·실패 대체 경로와 벡터DB는 제외한다.

최신 통합문서는 영상도 최종 제품 범위로 다룬다. 이 프레임워크의 1차 연결은 기존 합의대로 PDF·포스터에 한정한다. DOCX/HWPX·영상 처리까지 구현한 것으로 해석하지 않는다. 기존 front-v2와 운영 DB를 이 문서 갱신으로 변경하거나 배포하지 않는다.

02. 전체 흐름과 공통 근거 준비

PDF·포스터 참조 접수 → A02 조건 초안 → 사람이 기준 승인 → 승인 입력·근거 고정 → A04_A05 통합 검사 → A06 결과 검증 → A07 보고 → 사람의 검토로 이어진다.

  • 변경 없는 pass는 수정 요청 승인 없이 최종 승인으로 직접 연결한다.
  • 수정이 필요할 때만 수정 요청 승인 → 새 산출물·새 실행 → 조건 초안 재사용 → 새 실행에서 기준 재승인 → 승인 조건 전체 재검사를 수행한다.
  • 부모의 기준 승인·최종 승인은 새 실행으로 자동 복사하지 않는다. 문서·조건 변경은 A02 새 추출·새 기준 확정이 필요하다.
  • review는 최종·예외 승인할 수 없다. 예외 승인은 현재 구현의 완전한 근거와 확정 fail·value_mismatch 요건을 모두 만족해야 하며 기계 판정을 pass로 바꾸지 않는다.

근거가 사라지는 것은 아니다. context.py의 freeze_approved_context는 승인 조건의 원문 인용·해시·문서 버전을 복사해 고정 EvidenceBundle을 만든다. 모델·검색·DB 호출을 하지 않는 공통 함수이며 역할 실행 기록도 만들지 않는다. 조건 승인과 같은 상태 저장에서 근거 묶음을 고정하고 검수 단계가 이를 사용한다.

현재 코드와 후속 목표를 구분한다. 현재 complete는 승인된 기준 출처 묶음을 완성했다는 뜻이며 관계 검색 성공을 뜻하지 않는다. warnings에 외부 조회를 하지 않았음을 남긴다. 최신 문서 13.2에서 채택한 PostgreSQL 권한·승인 조건·원문 확인 → Neo4j 관계 조회 → PostgreSQL 원본·권한·버전 재확인 → 근거 묶음 고정은 후속 공통 문맥 준비 기능이다. 이 조회 기능을 독립 A03으로 만들지 않으며 별도 GraphDB 에이전트 배치는 미확정이다. 검색 결과로 검사할 승인 조건을 줄이지 않는다.

04. 설치와 설정

프로젝트 루트에서 Python 3.12 또는 3.13과 uv를 사용한다. 공통 의존성 정본은 pyproject.toml·uv.lock이며 모델 패키지를 추가할 때 함께 갱신한다.

TERMINAL
uv sync --locked --group dev
cp examples/agent_framework/team_config.template.json examples/agent_framework/team_config.team.json
.venv/bin/python -m backend.agent_framework doctor --config examples/agent_framework/team_config.team.json

설정에는 네 역할을 모두 선언한다. 담당 역할만 factory로 바꾸고 A06은 reference를 유지한다. 단독 role/check는 선택한 역할만 초기화하므로 다른 역할은 unconfigured여도 된다. 전체 실행은 네 역할 모두 구현 또는 명시적인 합성 구성이 필요하다.

A02 설정 항목 예시:

JSON
{
  "kind": "factory",
  "factory": "examples.agent_framework.team_adapters:create_extractor"
}

factory는 인자 없는 동기 함수로 해당 역할 어댑터 하나를 반환한다. import 시 모델 로드·네트워크 연결을 수행하지 않는다. 실제 키·비밀번호·세션·개발 원문은 Git에 넣지 않는다. 역할 내부의 자동 재시도나 합성 fallback으로 호출 결과 불명을 숨기지 않는다.

계약 1.0.0 설정·요청·생성 fixture는 그대로 재사용할 수 없다. 2.0.0 template을 복사하고 A03 binding을 제거한다. RetrieveRequest와 retriever port/factory는 삭제되었고 EvidenceBundle.retrieval_id는 context_id, 검증 이슈 retrieval_incomplete는 context_incomplete로 바뀌었다. 기존 저장 실행을 새 코드로 자동 이관하지 않는다. HTTP 경로 /api/framework/v1의 v1은 전송 경로 버전이고 JSON의 contract_version은 2.0.0이다.

05. A02 — PDF 조건 추출

동기 extract(request)에서 PDF 전체 처리 범위와 누락 경고, 조건 ID·기대값·연산자, 페이지·블록·원문 인용·인용 해시를 보존한다. 입력 문맥과 문서 버전을 모델이 새로 만들지 않도록 한다.

FileBackedExtractor에 공통 FileAccess와 (request, VerifiedDocument) 콜백을 주입한다. 검증된 document.content 바이트를 사용한다. 파일 전체 SHA-256과 인용문 SHA-256을 구분한다. 읽기 검증 실패 시 모델은 호출하지 않는다.

TERMINAL
.venv/bin/python -m backend.agent_framework check A02 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A02.suite.json
.venv/bin/python -m pytest tests/agent_framework/test_files.py tests/agent_framework/test_project_files.py tests/agent_framework/test_invocation.py -q

개인 모델 테스트는 tests/agent_framework/test_team_a02.py로 추가한다. 실제 개발 PDF에서 전체 조건과 출처를 반환하고 버전·해시 위조를 거부하는 실행 증거를 제출한다.

06. A04·A05 — Qwen 통합 검사

동기 inspect(request)는 승인 조건 전체·고정 근거 묶음·현재 포스터로 조건별 Observation을 반환한다. 문구·시각 조건을 하나의 포트로 연결하며 과거 통과 기록으로 현재 관측을 대신하지 않는다.

FileBackedInspector의 (request, VerifiedPoster) 콜백을 사용한다. 현재 산출물 버전·해시, EXIF 적용 좌표계, 정규화 bbox를 맞춘다. 위치를 모르면 좌표를 추측하지 않고 불확실성을 표시한다. 수정본은 새 이미지에서 승인 조건 전체를 다시 검사한다.

TERMINAL
.venv/bin/python -m backend.agent_framework check A04_A05 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A04_A05.suite.json
.venv/bin/python -m pytest tests/agent_framework/test_files.py tests/agent_framework/test_invocation.py tests/agent_framework/test_validation.py -q

개인 모델 테스트는 tests/agent_framework/test_team_a04_a05.py로 추가한다. 지원·미지원 조건과 실제 이미지·근거 연결을 확인한다.

07. A06 — 공통 검증과 판정

ReferenceValidator가 조건 커버리지·관측·수치 비교·문맥·인용·버전·근거 상태를 검증한다. fail/review도 정상 결과다. 누락·불확실·불완전 근거는 review로 유지하고 명확한 필수 위반을 pass로 바꾸지 않는다.

TERMINAL
.venv/bin/python -m backend.agent_framework check A06 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A06.suite.json
.venv/bin/python -m pytest tests/agent_framework/test_validation.py tests/agent_framework/test_runtime.py tests/agent_framework/test_context.py -q

text의 equals·contains는 빈 문자열·공백뿐인 기대값을 missing_expected_value와 review로 처리한다. 해당 필수 조건의 정상 최종 승인과 미확정 기대값의 예외 승인은 차단한다. 값이 있는 기대값의 공백은 그대로 비교하며, visual/present에는 이 텍스트 제약을 적용하지 않는다.

기계 판정, 실행 상태, 사람 승인 상태를 각각 유지한다. 복합·의미 조건의 실제 모델 검증은 현재 기초 참조 규칙과 구분한다.

08. A07 — 보고와 수정 요청 초안

동기 report(request)는 검증 판정을 보존한 설명·근거 ID·수정 요청을 반환한다. 다른 프로젝트·문서·산출물 근거를 섞지 않고, 사람의 승인을 생성하거나 판정을 변경하지 않는다. 요청 계약 밖의 파일을 추측해 다시 읽지 않는다.

TERMINAL
.venv/bin/python -m backend.agent_framework check A07 --config examples/agent_framework/team_config.synthetic.json --cases examples/agent_framework/checks/A07.suite.json
.venv/bin/python -m pytest tests/agent_framework/test_report_boundary.py tests/agent_framework/test_invocation.py -q

개인 모델 테스트는 tests/agent_framework/test_team_a07.py로 추가한다. pass/fail/review와 근거·관측 한계를 유지한 보고서를 제출한다.

09. 공통 실행과 PostgreSQL worker

PostgreSQL 실행가이드의 API·독립 worker는 기존 M008 DB·사용자·프로젝트·세션·CSRF를 재사용한다. 메모리 demo/serve/check-flow와 구분한다. API는 접수·승인·조회를, worker는 A02 추출 또는 A04_A05→A06→A07 검수 phase를 처리한다. 기준 승인·근거 고정·검수 작업 접수는 같은 상태 저장에서 확정한다.

완료 단계는 재개 시 재사용한다. 호출 여부가 불명확하면 outcome_unknown으로 끝내고 자동 재호출하지 않는다. lease·heartbeat·token과 실행 시 권한 재확인으로 오래된 worker의 늦은 저장을 막는다. API·worker·저장 실행의 설정과 코드 revision이 달라지면 새 코드로 임의 재개하지 않는다.

AF001은 아직 운영 DB에 적용하지 않은 개발 DDL이다. 이번 역할 제거를 미배포 AF001 정의에 반영했다. 이전 해시의 AF001을 별도 환경에 적용했다면 기존 SQL을 덮어써서 맞추지 말고 스키마와 저장 실행을 확인한 후 명시적 후속 마이그레이션을 준비한다. 현재 readiness 검사는 해시 불일치를 거부한다.

TERMINAL

demo와 check-flow의 사람 승인은 스크립트가 넣은 테스트 값이다. 메모리 결과는 재시작 시 사라진다. 파일 예제는 임시 PDF·PNG·DB를 사용하며 Qwen·Neo4j를 호출하지 않는다. 합성 테스트 통과를 실모델 정확도·제품 통합·실제 사람 승인 증거로 표시하지 않는다.

Windows PowerShell에서는 .venv/bin/python을 .\.venv\Scripts\python.exe로, cp를 Copy-Item으로 바꾼다. HTML 오른쪽 위 운영체제 버튼으로 명령을 전환할 수 있다. HTML은 외부 자원 없이 상대 링크로 열리지만 실제 Windows 실행은 별도 확인 대상이다.

각 담당자는 수정 파일·factory 참조·의존성·입출력 예제·정상/실패/불확실 테스트 명령·실제 실행 증거·남은 한계를 전달한다. 공통 담당자는 계약 검사 → 파일 검증 → 전체 승인·재검수 → PostgreSQL 영속 기록·복구 → 제품 front-v2 연결 순서로 인수한다. 실제 Qwen·Neo4j 공통 문맥 준비·front-v2 업무 연결은 아직 후속 작업이다.
