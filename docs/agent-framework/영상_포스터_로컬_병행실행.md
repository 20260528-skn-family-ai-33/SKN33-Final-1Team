# 영상·포스터 로컬 병행 실행

프레임워크 포스터 API(`8012`)와 별도의 기존 영상 처리 서비스(`8013`)를 프론트 한 화면에서 사용하는 개발 구성이다. 영상 API는 기존 PostgreSQL 계정·세션·CSRF 설정을 재사용하며 `127.0.0.1`에만 바인딩한다. 포스터 API·worker와 Qwen·Neo4j 설정은 바꾸지 않는다. AWS나 인터넷 공개 배포용 구성은 아니다.

영상 작업은 `.runtime/framework-video-local/reviews`, 영상 로고는 `.runtime/framework-video-local/logos`에 저장한다. 예전 `.runtime/video-reviews`, `.runtime/video-logos` 이력과는 별도다. 같은 저장소로 여러 프로세스를 실행하지 않도록 잠금을 사용한다. 현재 영상 기록은 프로젝트별 권한으로 분리되지 않으므로 **단일 사용자 로컬 개발에만 사용**한다.

## 1. 필수 환경과 FFmpeg

포스터·영상은 루트 `.env`를 `--env-file .env`로 선택한다. `CC_ENV_MODE=local_unified`인 개발용 파일에는 관리자 값을 함께 보관할 수 있으며 서비스 실행기가 이를 제외한다. 기존 `.runtime/framework-desktop-full-review.env`도 보존한다. FFmpeg가 없다면 잠금 파일의 버전과 일치하는 `imageio-ffmpeg`만 독립 폴더에 설치한다. 기존 `.venv`와 다른 패키지는 변경하지 않는다. 설치는 한 번만 명시적으로 수행한다.

Mac:

```bash
.venv/bin/python -m pip install --no-deps --target .runtime/framework-video-deps imageio-ffmpeg==0.7.0
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps --target .runtime/framework-video-deps imageio-ffmpeg==0.7.0
```

실행기는 이 폴더가 있을 때만 로드한다. 이미 폴더가 있다면 먼저 내용을 확인하고 설치 명령을 반복하거나 덮어쓰지 않는다. 기존 시스템 FFmpeg 또는 `FFMPEG_BIN`도 사용할 수 있다.

## 2. 영상 모델 워커

현재 영상 자막·로고 경로는 기존 영상 워커를 사용한다. 포스터와 PDF의 Qwen 서버와 별개다. 기존 영상 Pod의 `127.0.0.1:8791`에 워커를 띄우고 PC의 `127.0.0.1:18791`로 SSH 터널을 연다. 로컬 `.env`에는 `VIDEO_LOGO_WORKER_URL=http://127.0.0.1:18791`을 지정한다. 인증 토큰을 쓰는 워커라면 동일한 `VIDEO_LOGO_WORKER_TOKEN`도 넣는다. 인증값을 커밋하거나 채팅에 출력하지 않는다. 실제 주소·포트·사용 가능 메모리와 기존 워커 상태를 먼저 확인한다. 상세 워커 구성은 [영상 로고 API](../video-logo-flow-api.md)를 참고한다.

워커가 없을 때 API 화면을 열 수는 있지만, 실제 준비 상태는 서버가 보고하는 값으로 확인해야 한다. 기존 코드는 워커 URL을 생략하면 로컬 모델 준비 상태를 확인한다. Qwen과 영상 모델을 같은 GPU에서 동시에 올릴 수 있다고 가정하지 않는다.

## 3. 영상 API

프로젝트 루트에서 실행한다. env는 포스터 프레임워크와 같은 DB·세션·CSRF 비밀값을 사용해야 한다. 실제 모델 워커가 준비되면 `.env`의 `VIDEO_LOGO_WORKER_URL`을 해당 터널 주소로 맞춘다.

Mac:

```bash
.venv/bin/python scripts/framework_video.py --env-file .env
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/framework_video.py --env-file .env
```

`Uvicorn running on http://127.0.0.1:8013`이 나오면 터미널을 켜 둔다. 종료 또는 재시작 시 진행 중이던 영상 작업은 기존 영상 로직에 따라 중단 처리될 수 있다.

## 4. 프론트 프록시

루트 `.env`에서 `API_PROXY_TARGET`과 `FRAMEWORK_API_PROXY_TARGET`을 `http://127.0.0.1:8012`, `VIDEO_API_PROXY_TARGET`을 `http://127.0.0.1:8013`으로 지정한다. Vite는 이 주소만 읽고 서버 비밀값은 브라우저에 전달하지 않는다. Vite를 재시작하면 세션 발급과 포스터 API는 `8012`에 남고 영상 API 두 경로만 `8013`으로 간다.

Mac:

```bash
npm --prefix frontend run dev -- --port 5173 --strictPort
```

Windows PowerShell:

```powershell
npm --prefix frontend run dev -- --port 5173 --strictPort
```

영상 화면에서 `Not Found` 대신 준비 상태가 표시되는지 확인하고, 워커·FFmpeg 준비 완료 후 짧은 영상을 직접 검수한다. API 응답이나 합성 테스트 통과만으로 실모델 영상 검수 성공을 의미하지 않는다.
