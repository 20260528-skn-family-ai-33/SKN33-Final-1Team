# PostgreSQL·Neo4j 근거 연결 구현·검증 기록

2026-11-04 · `feat/37-framework-neo4j-rag` · 역할 계약 3.0.0 · AF005

## 구현한 동작

PostgreSQL을 권한·원문·버전·승인의 원장으로 유지하고 Neo4j에는 재구축 가능한 관계를 저장한다. 독립 A03·벡터DB·추가 LLM을 만들지 않았다. 기존 front-v2 변경과 실제 A02 미승인 기록은 보존한다.

| 파일 | 책임 |
|---|---|
| `backend/agent_framework/AF005.sql` | 프로젝트 graph revision·outbox·실행별 불변 근거 기록 |
| `graph_projection.py` | 업무 저장과 같은 트랜잭션의 outbox, 독립 worker의 lease·재시도·revision별 완료 확인 |
| `graph_store.py` | AF 전용 이름 공간, 프로젝트 원자 교체, 중복·역순 전달 방어, 고정 관계 조회 |
| `evidence_context.py` | A04·A05 직전 PG→Neo4j→PG 재검증, 전체 승인 조건의 원문·보완 출처 고정, A07 재사용 |
| `graph_commands.py` | 명시적 graph-init·graph-projector·프로젝트별 graph-rebuild |

조회 API는 graph-status·evidence-context·criteria-impact다. 기존 세션·프로젝트 권한을 적용하고 GET에서 모델을 호출하지 않는다. 조건 ID는 프로젝트·기준 버전과 함께 식별한다. 과거 검수·승인 관계는 조회 추적 정보이며 현재 포스터의 관측·판정을 대신하지 않는다.

`freeze_approved_context`는 순수 함수로 유지했다. 승인 트랜잭션에 Neo4j 호출을 넣지 않았으며 승인 기록도 변경하지 않는다. RAG는 `context_preparation`을 명시한 registered-poster 설정에서만 사용한다. 역할 입출력은 계속 3.0.0이다.

핵심 통합 검사에서 확인한 항목:

- 실제 두 DB를 거친 원문·보완 출처가 A04·A05와 A07에 동일하게 전달된다.
- 그래프 미접속·지연 revision·변조된 출처는 전체 조건을 유지하는 SQL 대체로 기록한다. 실제 Neo4j 드라이버의 연결 실패도 확인했다.
- 중복·역순 revision, 동기화 도중 새 변경, Neo4j 반영 후 완료 응답 유실과 재시도를 검증했다.
- 불변 근거 기록·새 저장소 객체의 재조회·타 프로젝트 및 잘못된 조건 접근 차단을 확인했다.
- 조회 도중 권한이나 PostgreSQL 원문 정보가 변하면 모델 호출 전에 중단하고 근거 기록을 저장하지 않는다.
- 실제 PDF 파일이 바뀌면 등록 파일 검증에서 실패하며 모델 공급자를 호출하지 않는다. 이 경우 실패 단계가 기록될 수 있고 PostgreSQL에서 고정한 출처는 실패 실행의 감사 자료로 남을 수 있다.

승인·검사 어댑터 입력은 **명시적 합성 시험 자료**다. 실제 Qwen 전체 포스터 검수 성공이나 정확도·사람의 최종 승인을 증명하지 않는다. 폐기용 PostgreSQL과 생성한 시험 DB는 정리했다. 기존 PyMuPDF 관련 경고는 별도로 남았다.

## 기존 로컬 DB 적용

로컬 `creative_checker` DB의 public M008을 유지하고 agent_framework만 AF004→AF005로 올렸다. 먼저 전체 백업을 생성하고 `pg_restore --list`·SHA-256을 확인했다.

- 백업: `.runtime/backups/creative_checker_pre_AF005_20261104_152921_26288be9.dump` (801,588 bytes)
- app 계정의 AF005 구조·최소 권한 검사 통과.
- 기존 runs/jobs/steps 각 9건, approvals 0건, events 45건, document_versions 3건, criteria_versions/criteria_approval_bindings 각 0건의 **전체 행 개수·해시가 동일**.
- 개인 설정·키·백업·원문 응답은 Git에 포함하지 않는다.

실제 전시 PDF는 조건 13개·표시 문단 12개·미정 안내 1개, `waiting_criteria`, 승인 0건을 유지한다. 승인 기준이 없으므로 승인 조건 노드를 임의 생성하거나 합성 승인으로 바꾸지 않았다.

기존 실험용 Neo4j·볼륨은 변경하지 않았다. 이 채팅에서 만든 이전 AF004 점검용 18012 API는 새 AF005 API 확인 후 종료했다. 기존 파일 볼륨 `cc-framework-data`를 계속 사용한다.

전시 PDF 프로젝트를 지정해 투영한 결과 **노드 13개·관계 21개**가 PostgreSQL 스냅샷과 일치했다. 최초 revision은 1/1, 미처리 outbox는 0건이었다. 원문 본문은 그래프에 복사하지 않았다.

이후 새 projection worker를 종료하고 개발 Neo4j 컨테이너를 실제 재시작했다. 같은 프로젝트만 재구축 요청해 새 worker 프로세스로 전달한 결과 revision **2/2**, 미처리 outbox 0건, 노드·관계 해시가 재시작 전과 동일했다(`89394572386a868bd880fefe78fda661697268767c8b4eb46c1e693c4185f7ee`). 기존 PostgreSQL 기록도 동일했다. 이후 지속 동기화 worker를 다시 실행했다.

새 API는 AF005·Qwen PDF·화면용 문단·graph projection 사용 가능을 응답한다. 무인증 graph-status는 401이며 API의 임시 설정 파일·프로세스 환경에서 Neo4j 키가 제외됨을 확인했다.

이 API는 **기존 A02 전용 프로필**이므로 `context_preparation=approved_sources`, `poster_reviews=false`다. 실제 미승인 PDF를 RAG 검수로 자동 전환하지 않는다. RAG 역할 연결은 격리 DB의 승인 합성 자료로 검증했으며 실제 검수에는 사람이 승인한 기준과 담당자의 실제 포스터 어댑터 설정이 필요하다. 이번 적용에서 새 모델 호출이나 사용자 DB의 합성 승인은 만들지 않았다.

## 실행과 남은 경계
