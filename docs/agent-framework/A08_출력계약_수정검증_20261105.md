# A08 요청 단계 출력 계약 수정·실모델 검증

2026-11-05 · `feat/37-framework-neo4j-rag` · 공통 역할 계약 3.0.0 유지

## 문제와 수정

수정 승인이 없는 부모 실행의 재검수 요청을 거절할 때, Qwen은 `rereview_requested=false`로 판단했지만 `unresolved`에 `human_decision != 'changes_approved'`라는 이유 문장을 넣었다. JSON 문법은 맞아도 조건 ID 목록의 타입·형식 계약에 맞지 않아 `AGENT_OUTPUT_INVALID`가 발생했다. 이전 서버 HTTP 400과는 별개 문제다.

A08은 같은 초안 형태를 요청 판단과 전후 검사 비교에서 사용한다. 요청 단계에서는 아직 비교하지 않으므로 `resolved`, `unresolved`, `new_violations`가 모두 비어야 한다. 이 구분을 시스템 안내와 요청 안내에 명확히 추가했고, 승인 누락·거절 이유·실행 상태는 `summary`에만 쓰도록 했다.

공통 에이전트 루프에 선택적인 내부 `format_guidance`를 추가했다. A08 요청 응답이 잘못된 경우 기존의 **최대 한 번** 형식 수정 요청에도 위 문맥을 전달한다. 다른 호출자는 이전 기본 안내를 유지한다. HTTP 재시도·도구 쓰기 재실행을 추가한 것은 아니다.

공통 계약·ID 검증·`_consistent` 사실 대조·사람의 수정 승인 조건은 유지한다. 잘못된 목록을 자동 삭제하거나 문자열로 바꿔 통과시키지 않는다. 거절 이유가 반복되거나 ID처럼 보이는 상태 코드가 목록에 들어가도 실패 처리한다. 승인·새 포스터 버전·자식 실행 생성과 결과 불명 쓰기의 중복 방지 규칙도 유지한다.

네 실모델 테스트의 기대값은 바꾸지 않았다. 기존 RunPod의 인증된 `Qwen/Qwen3.5-4B`와 도구 호출 설정을 사용했다. worker와 같은 `CC_QWEN_BASE_URL`·`CC_QWEN_API_KEY`를 시험 프로세스에 전달했으며 별도 테스트 전용 환경변수나 개인 env 항목을 추가하지 않았다.

확인한 결과는 실제 LLM이 합성 Workflow의 도구와 출력 계약을 따르는 네 시나리오다. 전체 포스터 모델의 품질·운영 API/HTTP MCP를 포함한 전체 연결·사람의 실제 승인을 증명하지 않는다. 이번 작업에서 실제 DB·RunPod 서버 설정·모델 가중치·프론트는 변경하지 않았다.
