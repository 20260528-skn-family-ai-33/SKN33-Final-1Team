# main 머지 전 AWS 반영 기록

2026-11-09 · 배포 소스 `AWS_TEST`의 `ca7f01c` · 기존 데이터 유지

후속 상태: [2026-11-10 AWS 운영 현황](AWS_인프라_운영현황_20261110.md). 이 문서의 건수·해시·준비 상태는 아래 배포 시점의 기록이며 현재 상태를 자동 갱신한 값이 아니다.

사용자 요청으로 main 프론트 머지에 앞서 포스터 API·워커, 영상 API의 두 워커 연결과 main CloudFront 새로고침 처리를 적용했다. Git main 머지·push와 main 프론트 번들 교체는 수행하지 않았다. 이 문서는 아래 시점의 실제 인프라 확인 기록이다.

포스터 API의 `/api/framework/v1/` 기본 라우팅만 새 포트로 전환했다. AWS_TEST의 같은 경로는 기존 8016을 유지한다. 일반 `/api/` 인증 경로와 이전 API·이전 runtime 워커는 보존했다. API의 `task_controls=true`, `poster_review_ready=true`를 main·테스트 공개 주소에서 확인했다.

새 이미지들은 커밋된 backend를 기존 호환 실행 이미지 위에 복사해 빌드했다. 개인 환경 파일·패키지·가중치·DB 스키마는 변경하지 않았다. 포스터 API와 최신 워커의 일치 값은 다음과 같다.

- runtime SHA256: `98a47974fbcd25051ca93c52ac2de0128e10c14ad9a301bebd2fe272a7860e53`
- configuration SHA256: `8e95749c371a782d29a48d9e6a65483b9c63d34dd91a567f0d25c257c6a6b0f1`

영상 API 교체 시 영상 POST만 잠시 503으로 막고 GET 조회는 유지했다. 처리 중 작업이 없는지 재확인한 후 이전 컨테이너를 정지·보관하고 새 컨테이너를 기동했다. 준비 확인 후 POST 제한을 제거했다. EFS `/mnt/creative-checker-efs/video-aws-test`를 계속 사용하며 저장소 잠금을 가진 API는 하나만 실행한다.

## CloudFront

main 배포 `E1LYR5RFZBQOT8`에 다음을 적용했다. 기본 S3 원본·OAC·기존 인증 헤더는 유지했다.

- 기존 테스트와 같은 영상 원본 연결을 main의 `creative-checker-video-main` 원본으로 추가했다. 비밀 헤더 값은 서버·비공개 백업에만 보관한다.
- `/api/video-reviews`, `/api/video-reviews/*`, `/api/video-logos`, `/api/video-logos/*`를 기존 `/api/*`보다 앞에 연결했다. API 캐시는 비활성화 상태를 유지한다.
- `main-spa-rewrite` Function을 LIVE로 게시하고 기본 동작의 `viewer-request`에 연결했다. 코드 정본은 기존 `deploy/agent-framework/aws-test-spa-rewrite.js`와 동일하다.
- GET/HEAD의 `/login`, `/review/new`, `/review/tasks`, `/video`, `/video/logo`, `/modeltest`만 `/index.html`로 바꾼다. 마지막 `/`도 허용하며 query string은 유지한다. API·정적 파일·POST는 바꾸지 않는다.
- 배포 상태 `Deployed`, 무효화 `I4FTUSFCEDFL3SGZ3A8JL1Y8CS` 상태 `Completed`를 확인했다.
- AWS_TEST 배포 `ESI2WHFLU88QT`는 ETag와 설정이 유지됐다. 비교 시 순서에 의미가 없는 Origins·CustomHeaders 목록은 정렬했다.

## 검증과 보존

- AWS Function 테스트 6개: GET/HEAD 화면 경로 변경, API·정적 파일·POST 미변경 확인.
- main·테스트에서 루트와 위 화면 6개를 직접 GET해 모두 HTTP 200 HTML 응답 확인. `/review/new`의 framework query가 있는 주소도 포함했다.
- 양 사이트의 포스터 health는 HTTP 200. 비로그인 영상·로고 status는 애플리케이션의 `AUTHENTICATION_REQUIRED` JSON 401로 응답해 원본 라우팅과 인증 유지 확인.
- 존재하지 않는 정적 파일은 기존 S3 403을 유지한다. 모든 오류를 HTML 성공으로 바꾸지 않았다.
- 영상 API 컨테이너 안의 실제 `WorkerPool`로 `video-1`, `video-2`, 준비 `2 / 2` 확인. 각 터널의 인증 health도 `ready=true`, `busy=0` 확인.
- 영상 이력 JSON 136개의 SHA256이 유휴 상태 교체 전후 모두 일치했다.
- PostgreSQL 읽기 전용 비교: runs 48, jobs 48, steps 75, approvals 20, events 339로 배포 전후 동일. 확인 시 queued/running 0건.
- 기존 PDF·포스터 EFS, 영상 EFS, PostgreSQL, Neo4j, 사용자·승인 기록과 개인 `.env`를 삭제·초기화하지 않았다.

이번 확인은 인프라 연결·인증 경로·준비 상태와 보존 검증이다. main에서 새 PDF/영상 업로드부터 최종 결과까지 다시 실행하거나 사람의 승인을 생성하지 않았다. 기존 두 영상의 실제 OCR·로고 검증은 [영상 API 기록](../video-logo-flow-api.md)의 이전 시험이며 이번 배포 후 재실행 결과와 구분한다. `production_ready=false`도 전체 운영 품질 완료를 주장하지 않기 위한 기존 값이다.

## 복구 위치와 순서

백업은 비밀값을 포함할 수 있어 root 전용으로 유지하며 Git·PR·채팅에 원문을 복사하지 않는다.

- API 호스트: `/var/backups/creative-checker/main-ca7f01c-3pp4b8y3`에 이전 컨테이너 inspect·Nginx 설정·영상 JSON 해시 목록과 CloudFront 변경 전/적용 설정·검증 결과.
- worker 호스트: `/var/backups/creative-checker/main-ca7f01c-6xo5zrwb`에 이전 Compose·컨테이너 설정.
- 로컬 비공개 CloudFront 설정 사본: macOS 임시 디렉터리의 `cc-main-promotion-wx7nks69`. 복구에 필요한 사본은 위 API 호스트 root 전용 백업에도 보관했다.
- 이전 영상 컨테이너: `creative-checker-video-aws-test-before-main-ca7f01c`를 정지 상태로 보관한다.
- 새 worker overlay: worker 호스트 `/home/ubuntu/creative-checker-worker-deploy/compose.main-ca7f01c.yaml`. 기존 Compose와 테스트 overlay들을 함께 사용한다.

포스터 API 롤백은 현재 Nginx map의 기본 포트를 8018에서 이전 8012로 되돌리고 `nginx -t` 후 reload한다. 새 runtime의 대기·실행 작업이 남으면 새 워커를 유지해야 한다. DB 역마이그레이션·데이터 삭제는 필요하지 않다.

영상 롤백은 새 POST 접수를 잠시 막고 자막·후보 탐색·정밀 대조 작업이 모두 유휴인지 확인한 뒤 새 API를 정지하고 보관한 이전 API를 복원한다. 같은 EFS에 API 두 개를 동시에 띄우지 않는다. 이전 API는 테스트 Origin만 허용하므로 main 영상 CloudFront 변경도 함께 검토한다. 복구 후 health·인증 경로를 확인하고 POST 제한을 해제한다.

CloudFront 롤백은 그 시점의 설정·ETag를 새로 읽고 이번 변경 외 수정이 없는지 비교한 뒤 비공개 이전 설정을 적용한다. 이미 추가된 다른 운영 변경을 과거 전체 설정으로 덮어쓰지 않는다. 전파·무효화 완료 후 직접 페이지 GET을 다시 확인한다.

## main 머지 후

기존 `AWS 메인 프론트 배포` Actions가 main push를 계기로 프론트 빌드·S3 업로드·index 무효화를 수행한다. 이번 인프라 준비가 프론트 배포 성공을 대신하지 않는다. 해당 Actions 성공 후 main에서 로그인·내 작업·PDF/포스터·영상 화면을 확인한다. `/review/tasks`의 HTML 전달은 준비됐지만 실제 최신 화면은 새 프론트 번들이 반영돼야 한다.

현재 Actions는 API·워커 이미지 또는 CloudFront Function을 자동 갱신하지 않는다. 이후 backend·새 화면 경로 변경에도 이 부분을 별도로 배포해야 한다. 이번 대상 `ca7f01c` 코드가 그대로 머지된다면 위 인프라 작업을 다시 수행할 필요는 없다.
