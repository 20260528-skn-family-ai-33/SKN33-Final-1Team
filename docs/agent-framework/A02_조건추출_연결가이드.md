# A02 PDF 조건 추출 연결

2026-11-03 · 5단계 · `feat/37-a02-pdf-registration`

후속 갱신: [6단계 기준 보완·승인 가이드](기준_보완승인_가이드.html)에 따라 AF003을 명시적으로 적용하면 보완 버전·정확한 기준 승인·재조회를 사용할 수 있다. 아래 5단계 당시의 미구현 표기는 당시 범위를 설명한다. 실제 Qwen은 계속 미연결이다.

## 01. 이번에 연결한 흐름

**기존 프로젝트의 PDF 등록 → PDF-only 추출 접수 → 별도 A02 worker → 원문 출처 검증 → 같은 PostgreSQL에 초안·단계·출처 저장 → 새 API 인스턴스에서 재조회**를 연결했다. 포스터 참조를 만들어 넣지 않으며 `asset_version_id`와 저장된 `asset`은 null이다. 초안 저장 뒤 `waiting_criteria`에서 멈춘다. 이번 단계는 보완 답변·기준 승인·포스터 검수를 실행하지 않는다.

기존 AF001의 `runs`, `jobs`, `steps`와 4단계 AF002 PDF 등록 테이블을 재사용한다. 새로운 public 테이블이나 AF003은 추가하지 않았다. 기존 PDF+포스터 검수·승인·재검수 경로는 회귀 테스트로 함께 확인했다. `front-v2` 화면과 운영 DB는 변경하지 않았다.

Qwen 서버 주소가 아직 없으므로 실제 모델 호출·정확도 측정은 하지 않았다. **DB 흐름은 명시적인 mock 설정**, HTTP 프로토콜은 가짜 HTTP transport로 시험했다. 이 결과를 Qwen 추론 성공으로 해석하지 않는다.

## 02. mock과 Qwen의 차이

| 설정 | 동작 | 결과 표시 |
|---|---|---|
| `team_config.pdf-mock.json` | 실제 PDF의 일부 요청 문장을 고르는 개발용 선별 규칙. 모델·네트워크·검토표·정답 파일을 사용하지 않음 | `synthetic=true`, `extraction.mode=mock`, 수동 검토 후보 |
| `team_config.pdf-qwen.example.json` | 명시한 Qwen3.5-4B 호환 endpoint에 한 번 요청. 서버가 준비된 뒤 복사·수정하여 사용 | `extraction.mode=qwen`, 모델 필드는 요청한 모델명 |

mock은 완성된 조건 추출기가 아니다. 문장 일부가 줄바꿈으로 나뉘거나 표·예외·권장 수준이 있으면 정확하게 해석하지 못할 수 있다. 따라서 기대값은 비우고 `unsupported/manual` 후보를 만든다. 기존 검토표의 36개 조건과 일치하는 추출 성능을 주장하지 않는다. 실제 모델이 반환한 문자·숫자·시각 조건도 원문 인용을 대조한 **미승인 초안**이며 의미 정확도·누락 여부는 사람이 확인해야 한다.

Qwen 실패 때 mock으로 바꾸거나 JSON 보정 호출을 하지 않는다. 호출 결과가 불명확하면 `outcome_unknown`으로 닫고 자동 재호출하지 않는다. 예시 URL `127.0.0.1:8001`은 실제 구축된 서버 주소가 아니다. 이 작업은 GPU 생성·모델 다운로드·서빙 설치를 수행하지 않았다.

## 03. PDF 입력과 출처 검증

1. worker가 활성 사용자·프로젝트·editor/owner 권한을 다시 확인하고, 등록된 PDF 버전·파일·해시를 조회한다. 기존 작업은 로그인 세션보다 오래 실행될 수 있으므로 새 세션을 만들어 대신하지 않는다.
2. 기존 LocalStorage에서 실제 원본 바이트를 읽고 크기·SHA-256·페이지 수를 확인한다. 이때 DB 트랜잭션을 닫은 뒤 파일을 읽는다.
3. PyMuPDF **1.28.2**로 페이지별 텍스트를 원래 추출 순서와 공백 그대로 준비한다. 페이지 한 개를 `p1-text` 같은 블록 한 개로 다룬다. 등록 상한 20MiB·50쪽 외에 모델 입력은 기본 **32,000자**, 설정 최대 60,000자로 제한한다. 초과하면 자르거나 분할 호출하지 않고 실패한다.
4. 텍스트가 없는 페이지, 읽기 불가능한 문자, 이미지가 포함된 페이지는 첫 텍스트 경로에서 거부한다. 스캔·혼합 이미지 PDF 지원을 완료한 것이 아니며 별도 OCR fallback을 사용하지 않는다. 본문 문자열 확인만으로 표의 시각적 열 관계를 검증했다고 보지 않는다.
5. 공급자는 actor/project/run/criteria ID나 승인 여부를 반환할 수 없다. 서버가 고정한 문맥으로 Criterion·SourceRef를 만든다. 반환한 페이지·블록·인용문이 실제 본문과 일치해야 한다.
6. 조건 문장은 인용문과 같아야 하며 비어 있지 않은 기대값과 지정한 단위는 그 인용문의 문자 부분이어야 한다. 문서에 없는 값·인용문·다른 페이지 출처·모호한 값을 임의로 채우면 실패한다. 문자 포함 검증은 조건의 의미·그룹·예외 해석을 보증하지 않는다.
7. 초안의 `extraction`에 원문 PDF 해시, 페이지 본문과 해시, parser·정책·prompt hash·응답 hash, 요청 모델, 모의/실제 모드, 미정 조건 ID를 보존한다. 공급자 원시 HTTP 응답·추론 과정·API 키는 저장하지 않는다.
8. 공통 역할 경계와 DB 저장 직전에도 출처 구조·해시·문맥·설정 모드를 검증한다. 초안·단계 결과·해시·작업 완료는 같은 짧은 DB 트랜잭션으로 확정한다. HTTP 호출 동안 DB 연결이나 실행 행 잠금을 유지하지 않는다.

`CriteriaDraft.extraction`과 `TeamConfiguration.pdf_extraction`은 선택적 확장이다. 기존 어댑터에는 필수로 요구하지 않고 설정/trace가 없는 기존 JSON에는 새 null 필드를 추가하지 않는다. 최신 공통 JSON Schema를 재생성했다. 새 PDF 기능을 사용하는 팀원은 갱신한 계약을 사용해야 한다.

## 04. API와 worker 실행

먼저 [4단계 등록 가이드](PDF_등록_버전저장_가이드.html)에 따라 M008+AF002와 전용 PDF root를 준비한다. 기존 app-only 설정의 허용 host/origin을 실행 주소와 맞춘다. owner 설정은 서버·worker에 넘기지 않는다. 이미 초기화한 root를 다시 초기화하지 않는다.

터미널 A — API:

```bash
.venv/bin/python -m backend.agent_framework postgres-serve --env-file .runtime/framework-app.env --config examples/agent_framework/team_config.pdf-mock.json --pdf-storage-root "$PWD/.runtime/framework-pdf" --port 8012
```

터미널 B — worker:

```bash
.venv/bin/python -m backend.agent_framework worker --env-file .runtime/framework-app.env --config examples/agent_framework/team_config.pdf-mock.json --pdf-storage-root "$PWD/.runtime/framework-pdf"
```

`--once`를 붙이면 복구 검사 후 접수된 작업을 최대 한 건 처리하고 종료한다. API와 worker는 같은 신뢰한 설정을 사용한다. 설정·공통 코드 해시가 바뀐 이전 실행은 자동으로 새 설정에서 재개하지 않는다. 기존 기록을 보존하고 변경된 설정으로 새 요청 키·새 실행을 만든다.

| 경로 (`/api/framework/v1` 아래) | 용도 |
|---|---|
| POST `/projects/{project_id}/document-versions/{version_id}/extractions` | 등록된 PDF로 A02-only 실행 접수. `202 queued` |
| GET `/runs/{run_id}` | 상태·CriteriaDraft·출처 trace·오류 재조회 |
| GET `/runs/{run_id}/steps` | A02 시작·완료·실패·결과 불명 단계 기록 |
| GET `/runs/{run_id}/approvals` | 이번 단계의 새 PDF 실행에는 빈 승인 목록 |

접수에는 기존 로그인 세션 쿠키, `X-CSRFToken`, `Origin`, `Idempotency-Key` UUID를 사용한다. **본문은 비운다.** 클라이언트 정답·모델 주소·actor/run/criteria ID를 받지 않는다. 서버가 run/criteria ID와 DocumentRef를 만든다. 같은 프로젝트·키·사용자·문서·설정의 재전송은 같은 실행을 돌려준다. 같은 키에 다른 문서·사용자·설정을 넣으면 409다.

기존 이메일 계정 로그인 후 등록된 문서로 접수하는 Python 요청 부분:

```python
from uuid import uuid4
# client는 기존 세션 쿠키와 허용 Origin을 보유한 httpx.Client다.
token = client.get("/api/v1/auth/csrf").json()["csrf_token"]
request_key = str(uuid4())  # 응답을 못 받으면 같은 키를 보존하여 확인
response = client.post(
    f"/api/framework/v1/projects/{project_id}/document-versions/{version_id}/extractions",
    headers={"X-CSRFToken": token, "Idempotency-Key": request_key},
)
response.raise_for_status()
run_id = response.json()["context"]["run_id"]
```

기존 로그인 예제는 [PostgreSQL 가이드](에이전트_프레임워크_PostgreSQL_실행가이드.html)를 따른다. 현재 PDF 전용 초안에 승인 명령을 보내면 409다. 보완·기준 확정·승인 버전 조회는 6단계에서 구현한다. 포스터 없는 상태에서 검수 job을 생성하지 않는다.

## 05. 실제 Qwen 연결 준비

실제 서버가 생기면 Qwen 예시 설정을 로컬 신뢰한 파일로 복사하고 `endpoint`, 요청 모델명, 입력·출력 제한을 맞춘다. 필요한 API 키는 별도 app-only env 파일의 `A02_QWEN_API_KEY`에 두고 Git·채팅·JSON 설정에 넣지 않는다. endpoint는 사용자 업로드에서 받지 않으며 URL에 비밀번호·query·fragment를 넣을 수 없다.

클라이언트는 HTTP redirect·환경 proxy·재시도·형식 보정·대체 모델을 사용하지 않는다. read/write timeout 또는 5xx는 보수적으로 결과 불명으로 기록한다. 완성되지 않은 출력, 과대한 JSON, 중복 키, 스키마·출처 불일치는 실패로 닫는다. 실패 뒤에는 후속 역할을 실행하지 않는다.

요청 경계는 Qwen의 [공식 vLLM API 설명](https://qwen.readthedocs.io/en/latest/deployment/vllm.html)에 맞춘 chat completions 형태다. HTTP 호출과 fake transport 검증에는 [HTTPX 공식 transport 문서](https://www.python-httpx.org/advanced/transports/)를 참고했다. 실제 Qwen3.5-4B 서버의 structured output 지원, 모델 가중치/revision, 시간·정확도는 해당 서버가 준비된 뒤 별도로 확인해야 한다. 응답의 모델명만으로 실제 가중치를 검증했다고 보지 않는다.

## 06. 로컬 확인과 담당 파일

DB 없이 명시한 PDF 한 건으로 mock 배선만 확인:

```bash
.venv/bin/python -m examples.agent_framework.a02_mock_demo --pdf docs/poster-baselines/2026-11-03/workflow/client-inputs/EXH-NEW004/전시_포스터_제작의뢰서_v0.2.pdf
```

이 로컬 명령은 UUID를 임의로 만든 개발용 결과이며 DB 등록·운영 인증·실모델 검증이 아니다. `--output`으로 UTF-8 파일을 저장할 수 있고 상위 폴더는 먼저 준비한다. 기존 POSIX LocalStorage 기반 PostgreSQL worker의 Windows 네이티브 실행은 검증하지 않았다. 위 로컬 mock 명령의 Windows 실행도 실제 기기 검증과 구분한다.

| 파일 | 책임 |
|---|---|
| `backend/agent_framework/a02.py` | PDF 본문 준비, 모의/실제 공급자, 응답·출처 검증, worker 파일 접근 |
| `backend/agent_framework/a02_configuration.py` | 신뢰한 모드·모델·endpoint·parser·호출 제한 |
| `backend/agent_framework/contracts.py` | 선택적 ExtractionTrace·PDFTextSource |
| `backend/agent_framework/postgres.py` | 서버 ID·등록 PDF 참조 고정·접수·조회 |
| `backend/agent_framework/durable_worker.py` | lease, 단일 역할 실행, 결과/출처·단계 원자 저장 |
| `backend/agent_framework/postgres_api.py` | 인증·CSRF 기반 PDF-only 접수 |

```bash
.venv/bin/python -m pytest tests/agent_framework -q
TEST_DB_ENV_FILE=/absolute/path/to/test-only.env .venv/bin/python -m pytest tests/agent_framework/test_a02_postgres_integration.py tests/agent_framework/test_pdf_postgres_integration.py tests/agent_framework/test_postgres_integration.py -m db_integration -q
```

통합 테스트는 격리 PostgreSQL 17에서만 실행하며 무작위 테스트 DB를 만든 뒤 제거한다. 새 API 인스턴스 재조회, 별도 worker CLI 프로세스, 실제 파일 변조, 모호한 공급자 실패 후 자동 재호출 없음, 불법 출처 저장 차단을 확인했다. 실제 모델 품질·사람의 정답 검토·보완 답변·기준 승인·운영 적용·원격 CI는 후속이다.
