# A02 요구사항 구조화 · 자유 입력과 PDF

2026-11-04 · `a02-semantic-v3` · `feat/37-a02-pdf-registration`

현재 구현은 아래 Qwen 의미 구조화 절을 따른다. [기준 보완·승인 가이드](기준_보완승인_가이드.html)의 기존 승인 흐름을 유지하며 자유 입력 등록에는 AF004가 추가로 필요하다. 뒤쪽의 5단계 및 v1/v2 점검은 이전 구현의 기록이다.

## 현재 기본 — Qwen 의미 구조화 · 2026-11-04

**자유 입력 또는 텍스트 PDF → 같은 Qwen3.5-4B가 의미·유형·기대값 구조화 → 출처/형식 검증 → 기존 PostgreSQL 초안·단계 저장 → 사람의 기준 보완·승인 → 재조회**로 연결했다. 기본 설정은 `pdf_extraction.structuring="semantic"`, 정책은 `a02-semantic-v3`다. 이 경로에서 `compile_requirements`나 규칙 기반 값 분리를 호출하지 않는다. 이전 규칙 프로필은 기록 재현용 `literal_legacy`로 명시한 경우에만 사용한다. 모델 실패 시 그 프로필로 자동 전환하지 않는다.

Qwen은 각 조건의 `target`, `field`, `kind`, `operator`, `expected`, `unit`, 필수/미정 여부, 허용 범위의 출처를 직접 반환한다. 일반적인 필드 외에도 의미 있는 snake_case 항목명을 사용할 수 있다. 알려진 메타데이터 필드에는 숫자/문자 유형을 검증하고, 새 파일 메타데이터 항목은 `custom_` 접두사를 사용한다. 서버는 모델이 고른 값을 임의로 다시 만들지 않는다.

| 입력 예시 | 실제 Qwen 자유 입력 검증에서 생성된 조건 |
|---|---|
| 행사명: 김천김밥축제 | `poster_text / event_name`, 값 `김천김밥축제` |
| 기간: 2026.10.23 ~ 10.25 | `start_date=2026.10.23`, `end_date=10.25`로 분리. 각 조건에 전체 기간 원문을 연결 |
| 장소: 직지문화공원 | `poster_text / venue`, 값 `직지문화공원` |
| 김천시 로고가 포함되어야 합니다 | `poster_visual / logo / present`, 값 `김천시 로고` |

`Criterion.details.compiler="qwen-semantic-v1"`, `origin="model_structured"`가 모델의 의미 결정을 표시한다. 코드가 맡는 보조 기능은 JSON 계약·해시·버전·출처 범위·값/단위 근거 검증, 명시적 미정 표현과 누락된 허용 범위의 보존이다. 규칙으로 유지한 검토 항목은 `retained_unresolved_source`로 구분한다. 모든 원문 조건을 빠짐없이 이해했음을 보증하지 않으므로 사람의 대조가 필요하다.

**날짜와 원문:** 일반 문구·숫자·단위는 원문에 그대로 존재해야 한다. 날짜에는 모델이 제안한 `normalized_expected`를 선택적으로 저장한다. ISO 날짜가 비교값으로 반환된 경우에도 원문의 날짜 표기를 `expected_source`에 따로 보존하며, 같은 날짜임을 검증할 수 있을 때만 수용한다. 예: 비교값 `2026-05-14`, 원문 근거 `2026년 5월 14일`. 생략된 연도는 같은 명시적 날짜 범위에서 유일하게 확인될 때만 검증한다. 서버가 현재 연도나 임의의 1월 1일을 만들어 넣지 않는다. 정규화 값이 없으면 원문 값을 유지한다. 날짜·허용 범위의 실제 판정과 파일 메타데이터·시각 검사는 A04·A05/A06 연결 범위이며 현재 지원하지 않는 해석은 `review`로 유지한다.

현재 A06 참조 정책은 날짜 항목을 정규화 값의 유무와 관계없이 `date_comparison_review_required`로 남긴다. `10.25`가 `2027.10.25`의 일부라는 이유만으로 다른 연도의 날짜를 통과시키지 않는다. 날짜 의미 비교를 연결하기 전에는 사람의 검토가 필요하다.

### 저장과 승인 호환성

자유 입력은 UTF-8 원문을 실제 `text/plain` 파일로 보존하고 기존 `agent_framework.document_versions`의 불변 버전·해시·생성자·요청 키를 재사용한다. PDF로 변환하거나 가상의 PDF라고 표시하지 않는다. 자유 입력의 `page_count=1`과 출처 1쪽은 논리적 원문 블록이며, trace의 `input_kind="free_text"`, parser `utf8-source-v1`로 구분한다. PDF는 기존 PyMuPDF 텍스트 경로를 유지한다.

**AF004는 자유 입력 활성화에 필요한 명시적 추가 마이그레이션이다.** 기존 문서 테이블의 매체/크기 CHECK만 텍스트까지 확장한다. 기존 PDF의 20MiB/50쪽 제한·봉인 trigger·FK·앱 권한·public M008은 유지한다. 텍스트는 최대 60,000자/240,000바이트이며 요청 JSON은 기존 256KiB 제한, 실제 모델 입력은 설정의 문자 상한을 함께 적용한다. AF003에서는 새 PDF 의미 추출을 사용할 수 있고 자유 입력 등록은 준비 상태 오류로 거부한다. 기존 DB를 자동으로 업그레이드하지 않는다.

기존 이미지 빌드 → DB 백업 확인 → owner 전용 설정으로 AF004 적용 → API·worker 재시작 순서다. Mac·Windows 모두 기존 Docker Linux 실행기를 사용한다. 현재 앱 env·키·원본 파일·볼륨을 재생성하지 않는다.

```bash
# Mac · 프로젝트 루트에서. DB 백업을 확인한 뒤 실행.
python3 scripts/framework_desktop.py build
python3 scripts/framework_desktop.py migrate --env-file .runtime/framework-owner.env --revision AF004
```

```powershell
# Windows PowerShell · 프로젝트 루트에서. DB 백업을 확인한 뒤 실행.
py -3.12 scripts/framework_desktop.py build
py -3.12 scripts/framework_desktop.py migrate --env-file .runtime/framework-owner.env --revision AF004
```

실제 RunPod용 `deploy/qwen-a02/worker-config.example.json`은 의미 구조화와 600초 제한을 사용한다. 이미 만든 `.runtime/team_config.qwen-600s.json`에 `structuring`이 없으면 새 기본값 semantic이 적용된다. 명시적으로 `literal_legacy`를 설정한 파일은 자동 변경하지 않는다. 새 코드·설정은 **새 Idempotency-Key의 새 실행**으로 접수하며 기존 초안·실패·승인을 덮어쓰지 않는다.

### API 사용

모든 경로는 `/api/framework/v1` 아래에 있고 기존 로그인·CSRF·Origin·프로젝트 권한을 요구한다. 요청 키는 전송 전에 보관하며 같은 요청의 재확인에는 같은 키를 사용한다.

| 경로 | 동작 |
|---|---|
| POST `/projects/{project_id}/text-documents` | JSON `{"text":"원문"}`으로 불변 텍스트 버전 등록. 201 |
| POST `/projects/{project_id}/text-documents/{document_id}/versions?previous_version_id={id}` | 이전 버전을 지정해 새 텍스트 버전 등록. 201 |
| GET `/projects/{project_id}/document-versions/{version_id}/content` | 원본을 그대로 조회. 텍스트는 text/plain, PDF는 application/pdf |
| POST `/projects/{project_id}/document-versions/{version_id}/extractions` | 텍스트·PDF 공통 추출 접수. 빈 본문, 새 요청 키. 202 |
| GET `/runs/{run_id}` | `waiting_criteria`와 미승인 초안·출처·경고 조회 |
| 기존 `/runs/{run_id}/criteria-versions`, `/criteria-approvals`, `/criteria-approval` | 보완·명시적 승인·승인 결과 재조회. 기존 불변 버전/해시 계약 유지 |

수정된 텍스트가 새 버전으로 등록되면 이전 버전을 새로 승인할 수 없다. 미정·수동 조건은 보완/제외 근거가 필요하며 승인 이후 `waiting_asset`로 멈춘다. 형식이 맞는 초안이 실제 승인이나 포스터 통과를 뜻하지 않는다. 새 details·정규화/매체 필드를 받는 팀원은 갱신한 공유 JSON Schema와 OpenAPI를 사용해야 한다. `details` 없는 기존 JSON과 PDF trace의 직렬화 형태는 유지한다.

### 이번 검증

초기 진단에서는 실제 RunPod Qwen 자유 입력 5개 조건과 기록된 PDF 응답의 조건 13개·미정 1개를 검증했다. 이후 사용자가 새 이미지와 AF004를 기존 DB에 명시적으로 적용하고 API·worker를 재실행했다. 실제 Qwen 호출로 자유 입력 5개·미정 0개, PDF 13개·미정 1개가 기존 PostgreSQL에 저장되어 `waiting_criteria`로 재조회됐다. 두 응답은 `synthetic=false`, 정책은 `a02-semantic-v3`, 반환 항목은 모두 `model_structured`였다. 기준 승인 목록은 비어 있다. 상세 실행 ID·해시·보존 범위는 [실제 연결 검증 기록](A02_실제연결_검증기록_20261104.md)을 따른다.

PDF의 `c013`은 관람시간 값이 없고 확인 중이라는 안내가 있는 미정 항목이다. 원문과 미정 기록을 유지해 사람에게 확인 필요를 알린다. 앞서 안내한 ‘12개 보완 버전 저장’은 작성자의 제안이며 사용자의 제외 결정이나 기획서의 지시가 아니다. 원본 초안 13개는 유지하며 제외 버전과 승인은 접수하지 않았다. 표시 문단 12개와 미정 안내 1개로 나누는 것은 기준 변경·제외·승인이 아니다. 수정·제외는 사람의 명시적 결정 후에만 사유·출처와 함께 새 버전에 기록하고 문서에 없는 필수 조건을 임의 추가하지 않는다. 또한 `파일 1점`, `제목과 안내정보 구분`은 이번 응답에 독립 항목으로 반환되지 않아 원문 대조가 필요하다. 연결·저장 확인과 모든 요구사항의 완전한 추출은 구분한다.

회귀 635개·하위 검사 8개, 격리 PostgreSQL 75개를 통과했다. DB 시험은 가짜 모델 응답·시험용 승인 입력을 사용했으며 실제 Qwen 진단과 구분한다. Mac의 Docker 이미지 빌드도 확인했고 Windows 실기기 실행은 별도 확인 대상이다.

코드 위치: `a02_semantic.py`가 모델의 의미 출력·근거 검증, `requirement_text.py`가 UTF-8 입력 검증, `documents.py`·`AF004.sql`이 기존 저장소 확장이다. 기존 `a02_requirements.py` 값 분리는 명시적 legacy 프로필에서만 실행한다. 검증 명령은 기존 회귀 명령과 `tests/agent_framework/test_a02_semantic.py`, `tests/agent_framework/test_semantic_postgres_integration.py`를 포함한다. DB 테스트는 명시적인 테스트 전용 env와 새 격리 DB에서만 실행한다.

## 이전 정책 — 비교값·대상·미정 항목 구조화

이전 구간 선택 정책은 출처를 검증했지만 의뢰 문장 전체를 비교값으로 고르고, 가로·세로를 구분하지 못하며 미정 관람시간을 빠뜨렸다. 이제 **원문 선택은 Qwen, 명확한 리터럴 분리는 검증 가능한 컴파일 규칙**으로 나눈다. 정책은 `a02-source-compile-v2`, 컴파일러는 `literal-requirements-v1`이다. 원래 모델 응답의 JSON·출처·값 검증을 먼저 통과해야 하며 잘못된 응답을 보정해 성공으로 바꾸지 않는다. 추가 모델 호출이나 OCR fallback도 없다.

| 항목 | 현재 초안에 저장하는 내용 |
|---|---|
| 제목의 두 필수 구절 | `수원의 영화`, `수원의 극장`을 각각 분리. 공백·줄바꿈 허용 원문을 보존하고 수동 검토 |
| 연도·개막일·요일·장소 | `2026`, `2026년 5월 14일`, `목요일`, `열린문화공간 후소 전시실`처럼 원문 값 분리. 허용 범위는 자동으로 단순화하지 않음 |
| 가로·세로 | `file_metadata / pixel_width`, `file_metadata / pixel_height`로 구분하고 숫자와 단위 분리 |
| 파일 형식·색상 모드 | `file_format=JPEG`, `color_mode=RGB`. 포스터에 이 문자가 인쇄됐는지 검사하는 조건으로 취급하지 않음 |
| 납품 파일 수 | `delivery / quantity`. 이미지 속 사물 개수와 구분하고 수동 검토 |
| 시각 구성·일반 서술 | 완전한 원문을 보존하고 수동 검토. 지시문 일부를 임의의 contains 기대값으로 사용하지 않음 |
| 원문의 명시적 미정 표현 | 모델이 빠뜨려도 원문 구간을 빈 기대값의 수동 검토 항목으로 유지. `origin=retained_unresolved_source`로 규칙 기반 보존임을 표시 |

`Criterion.details`는 선택적 확장이다. 검사 대상(`target`), 항목명(`field`), 값의 PDF 출처(`expected_source`), 허용 범위 출처(`qualifiers`), 생성 근거(`origin`)를 보존한다. `response_sha256`은 컴파일된 JSON이 아니라 원 Qwen 응답 문자열의 해시를 계속 기록한다. 같은 출처의 동일 선택은 중복 생성하지 않으며 필수/미정 상태가 충돌하는 반복 선택은 거부한다. 알려진 미정 구간을 결과에서 제거하면 공통 역할 검증에서도 거부한다.

기존 `details` 없는 JSON은 같은 형태로 직렬화한다. **새 `details`를 받는 팀원은 갱신한 JSON Schema·OpenAPI를 함께 사용해야 한다.** 기존 PostgreSQL JSON 저장소를 재사용하며 새 스키마 마이그레이션은 필요하지 않다. 사람이 값을 보완하면 새 값의 출처는 기존 보완 기록에 저장하고, 원래 PDF 값의 낡은 `expected_source`는 해제한다. 원문 허용 범위는 보존한다.

**후속 검사와 승인 경계:** 현재 A06 ReferenceValidator에는 파일 메타데이터·납품 대상과 허용 범위를 완전히 평가하는 기능이 없다. 이 경우 `typed_attribute_review_required` 또는 `qualifier_interpretation_required`와 함께 `review`로 처리한다. 형식·색상 모드·크기는 원본 포스터 버전의 파일 메타데이터를 읽는 A04·A05 연결부가 필요하며 UI 미리보기나 모델용 축소 이미지의 값을 사용하면 안 된다. 수동·미정 조건은 보완/제외 근거 없이 승인할 수 없다. 규칙 기반 미정 보존도 전체 의미·누락 탐지를 보장하지 않으며 실제 관람시간을 만들어 넣지 않는다.

**현재 검증:** 실제 Qwen의 새 호출 1회에서 약 71.8초 후 15개 조건·미정 1개가 생성되고 공통 출처 검증을 통과했다. 사용자 DB에는 이 진단 결과를 쓰지 않았다. 별도 PostgreSQL에서 저장·재시작 재조회·미정 기준 승인 거부·기존 포스터 흐름 40개, 회귀 테스트 610개·하위 검사 8개가 통과했다. 기록된 모델 응답을 재사용한 회귀 예제는 가상 PDF의 프로토콜 표본이며 정답·사람 승인·일반 추출 정확도 자료가 아니다. 기존 사용자 실행의 13개 초안과 승인 이력은 보존한다. 새 이미지로 API·worker를 재시작한 다음 새 요청 키로 접수해야 이 정책이 적용된다.

## 이전 실서버 점검 — 원문 구간 선택

2026-11-03 RunPod Qwen의 일반 응답과 실제 PDF 추출 호출을 확인했다. 최초 120초 실행은 결과 불명으로 보존했고, 600초 설정의 새 실행에서는 응답을 받았으나 `A02_UNIT_UNGROUNDED`로 초안 저장을 거부했다. 별도 진단 호출 1회에서 후보 51개의 `unit`이 모두 단위가 아닌 `"text"`인 것을 재현했다. 제목·표 머리글 같은 비요구사항도 후보에 섞여 있었다. 진단 응답은 승인·업무 결과로 저장하지 않았다.

단위 규칙을 보완한 다음 실행은 `A02_SOURCE_MISMATCH`로 보존했다. 인용문을 모델이 다시 작성하는 대신, **Qwen이 원문 줄·부분 구간 ID를 선택하고 서버가 정확한 원문을 복사**하는 내부 응답 규약으로 바꿨다. 공백·줄바꿈·날짜 표기를 유사 일치로 보정하지 않으며 기존 출처 검증을 그대로 적용한다.

- `start_line`·`end_line`은 같은 페이지·블록의 앞뒤 순서가 맞는 줄이다. 뒤에 이어지는 허용 범위·예외를 포함해 인용할 수 있다.
- `expected`·`unit`은 원문 부분의 시작·끝 ID 또는 JSON null이다. **선택한 첫 줄에 속하는 순서가 맞는 구간만 출력 스키마에서 허용**하고 서버가 다시 검사한다. 다른 문장·페이지의 값을 가져오거나 단위를 별칭으로 바꾸면 거부한다.
- 비교 값 null은 공통 계약의 빈 기대값으로, 단위 null은 공통 계약의 null로 옮긴다. 모델이 명시적으로 선택한 수동 검토·미정 상태이며 잘못된 응답을 몰래 빈 값으로 고치는 동작이 아니다. 여러 줄에 걸친 값이나 복합 허용 조건은 현재 규약에서 수동 검토 대상이다.
- 미정 조건과 수동 검토는 기대값·단위를 null로 선택해야 한다. 숫자 비교는 단위 없는 숫자 구간을, 단위는 별도의 원문 단어·기호 구간을 선택한다. 종류·연산자·미정 여부의 조합도 출력 스키마와 서버 양쪽에서 검사한다. 예를 들어 ‘3000픽셀’ 전체를 숫자 값으로 넣거나 확인 중인 항목에 값을 붙이면 실패한다.
- 본문 최대 문자 수 외에 비어 있지 않은 줄 2,048개·부분 구간 8,192개·출력 스키마 약 2MiB 상한을 둔다. 선택 가능한 인용문은 최대 4,000자다. 한도를 넘으면 호출 전에 실패하며 임의로 자르거나 후보를 버리지 않는다.
- 모델이 선택한 종류·연산자·필수 여부를 유지한다. 파일 형식·색상 모드·수치 규격·시각 조건을 구분하도록 안내하며, 의미·누락·허용 범위를 해석했는지는 사람이 원문과 비교해야 한다.

실제 Qwen 요청은 전송한 전체 프롬프트의 SHA-256과 **모델 원응답 문자열의 SHA-256**을 trace에 기록한다. 서버가 구간을 복사해 만든 JSON의 해시로 원응답 해시를 대체하지 않는다. 기존 mock 정책 지문과 과거 기록도 보존한다. 실제 응답을 사용한 별도 검증과 격리 PostgreSQL의 가짜 HTTP 검증을 구분하며, 이 과정에서 사용자 DB의 실행·승인 기록을 바꾸지 않는다.

최종 구간 선택 규약을 실제 RunPod Qwen에 적용한 별도 1회 검증에서는 약 73.3초 후 전시 의뢰서의 **후보 13개가 공통 역할 경계의 출처·값·단위 검증을 통과**했다. 이는 사용자 worker가 DB에 저장한 결과가 아니라 비공개 로컬 진단 초안이다. 중간 개발 검증에서 발견한 기대값 범위 불일치·미정 기대값 오류도 성공으로 덮어쓰지 않았다. 격리 PostgreSQL에서는 가짜 HTTP 응답의 원응답 해시·정확한 숫자/단위 저장·재시작 조회를 포함한 11개 테스트, 프레임워크·서버 준비·데스크톱 실행기 회귀 테스트 594개와 하위 검사 8개가 통과했다.

**품질 제한:** 실제 응답 13개에는 의뢰 문장 전체를 비교 값으로 선택한 사례, 반복된 규격 후보, 미정인 관람시간을 빠뜨린 문제가 남았다. 원문에 미정 표현이 있는데 미정 후보가 하나도 없으면 `unresolved_source_not_extracted`와 `missing_values_require_client_clarification` 경고를 남긴다. 이 경고는 완전한 누락 탐지나 자동 보완이 아니며, 일부 미정 후보만 누락한 경우까지 보증하지 않는다. 누락을 자동으로 채우거나 기준 승인으로 바꾸지 않는다. 원문과 대조해 종류·비교 값·허용 범위·미정 항목을 보완하기 전에는 이 초안을 승인 기준으로 사용하지 않는다.

코드 변경 후 이미지를 빌드하고 API·worker를 같은 설정으로 재시작한 뒤 **새 Idempotency-Key의 새 실행**으로 확인한다. 실패/결과 불명 실행은 다시 열거나 성공으로 덮어쓰지 않는다. 구조·출처 검증 통과는 추출 품질·누락 없음·사람 승인 완료를 뜻하지 않는다.

**기존 프로젝트의 PDF 등록 → PDF-only 추출 접수 → 별도 A02 worker → 원문 출처 검증 → 같은 PostgreSQL에 초안·단계·출처 저장 → 새 API 인스턴스에서 재조회**를 연결했다. 포스터 참조를 만들어 넣지 않으며 `asset_version_id`와 저장된 `asset`은 null이다. 초안 저장 뒤 `waiting_criteria`에서 멈춘다. 이번 단계는 보완 답변·기준 승인·포스터 검수를 실행하지 않는다.

기존 AF001의 `runs`, `jobs`, `steps`와 4단계 AF002 PDF 등록 테이블을 재사용한다. 새로운 public 테이블이나 AF003은 추가하지 않았다. 기존 PDF+포스터 검수·승인·재검수 경로는 회귀 테스트로 함께 확인했다. `front-v2` 화면과 운영 DB는 변경하지 않았다.

Qwen 서버 주소가 아직 없으므로 실제 모델 호출·정확도 측정은 하지 않았다. **DB 흐름은 명시적인 mock 설정**, HTTP 프로토콜은 가짜 HTTP transport로 시험했다. 이 결과를 Qwen 추론 성공으로 해석하지 않는다.

## 02. mock과 Qwen의 차이

| 설정 | 동작 | 결과 표시 |
|---|---|---|
| `team_config.pdf-mock.json` | 실제 PDF의 일부 요청 문장을 고르는 개발용 선별 규칙. 모델·네트워크·검토표·정답 파일을 사용하지 않음 | `synthetic=true`, `extraction.mode=mock`, 수동 검토 후보 |
| `team_config.pdf-qwen.example.json` | 명시한 Qwen3.5-4B 호환 endpoint에 한 번 요청. 서버가 준비된 뒤 복사·수정하여 사용 | `extraction.mode=qwen`, 모델 필드는 요청한 모델명 |

mock은 완성된 조건 추출기가 아니다. 문장 일부가 줄바꿈으로 나뉘거나 표·예외·권장 수준이 있으면 정확하게 해석하지 못할 수 있다. 따라서 기대값은 비우고 `unsupported/manual` 후보를 만든다. 기존 검토표의 36개 조건과 일치하는 추출 성능을 주장하지 않는다. 실제 모델이 반환한 문자·숫자·시각 조건도 원문 인용을 대조한 **미승인 초안**이며 의미 정확도·누락 여부는 사람이 확인해야 한다.

Qwen 실패 때 mock으로 바꾸거나 JSON 보정 호출을 하지 않는다. 호출 결과가 불명확하면 `outcome_unknown`으로 닫고 자동 재호출하지 않는다. 예시 URL `127.0.0.1:8001`은 실제 구축된 서버 주소가 아니다. 이 작업은 GPU 생성·모델 다운로드·서빙 설치를 수행하지 않았다.

## 03. PDF 입력과 출처 검증

1. worker가 활성 사용자·프로젝트·editor/owner 권한을 다시 확인하고, 등록된 PDF 버전·파일·해시를 조회한다. 기존 작업은 로그인 세션보다 오래 실행될 수 있으므로 새 세션을 만들어 대신하지 않는다.
2. 기존 LocalStorage에서 실제 원본 바이트를 읽고 크기·SHA-256·페이지 수를 확인한다. 이때 DB 트랜잭션을 닫은 뒤 파일을 읽는다.
3. PyMuPDF **1.28.2**로 페이지별 텍스트를 원래 추출 순서와 공백 그대로 준비한다. 페이지 한 개를 `p1-text` 같은 블록 한 개로 다룬다. 등록 상한 20MiB·50쪽 외에 모델 입력은 기본 **32,000자**, 설정 최대 60,000자로 제한한다. 초과하면 자르거나 분할 호출하지 않고 실패한다.
4. 텍스트가 없는 페이지와 읽기 불가능한 문자는 첫 텍스트 경로에서 거부한다. 텍스트와 이미지가 함께 있는 페이지는 거부하지 않고 텍스트층만 읽으며, 초안 경고에 `page_{쪽}_embedded_images_not_read`를 남겨 기준 확인 화면과 문서 입력 안내에서 사람이 이미지를 직접 확인하게 한다(2026-11-11 변경, 이전에는 `PDF_IMAGE_PAGE_UNSUPPORTED`로 거부). 이미지 안 내용을 읽는 것은 아니므로 스캔·혼합 이미지 PDF 지원을 완료한 것이 아니며 별도 OCR fallback을 사용하지 않는다. 본문 문자열 확인만으로 표의 시각적 열 관계를 검증했다고 보지 않는다.
5. 공급자는 actor/project/run/criteria ID나 승인 여부를 반환할 수 없다. Qwen은 서버가 제시한 원문 줄·부분 구간 ID를 선택하며 서버가 원문을 복사하고 고정한 문맥으로 Criterion·SourceRef를 만든다. 복사한 페이지·블록·인용문이 실제 본문과 일치해야 한다.
6. 조건 문장은 인용문과 같아야 하며 비어 있지 않은 기대값과 지정한 단위는 그 인용문의 문자 부분이어야 한다. 문서에 없는 값·인용문·다른 페이지 출처·모호한 값을 임의로 채우면 실패한다. 문자 포함 검증은 조건의 의미·그룹·예외 해석을 보증하지 않는다.
7. 초안의 `extraction`에 원문 PDF 해시, 페이지 본문과 해시, parser·정책·prompt hash·응답 hash, 요청 모델, 모의/실제 모드, 미정 조건 ID를 보존한다. 공급자 원시 HTTP 응답·추론 과정·API 키는 저장하지 않는다.
8. 공통 역할 경계와 DB 저장 직전에도 출처 구조·해시·문맥·설정 모드를 검증한다. 초안·단계 결과·해시·작업 완료는 같은 짧은 DB 트랜잭션으로 확정한다. HTTP 호출 동안 DB 연결이나 실행 행 잠금을 유지하지 않는다.

`CriteriaDraft.extraction`과 `TeamConfiguration.pdf_extraction`은 선택적 확장이다. 기존 어댑터에는 필수로 요구하지 않고 설정/trace가 없는 기존 JSON에는 새 null 필드를 추가하지 않는다. 최신 공통 JSON Schema를 재생성했다. 새 PDF 기능을 사용하는 팀원은 갱신한 계약을 사용해야 한다.

## 04. API와 worker 실행

먼저 [4단계 등록 가이드](PDF_등록_버전저장_가이드.html)에 따라 M008+AF002와 전용 PDF root를 준비한다. 기존 app-only 설정의 허용 host/origin을 실행 주소와 맞춘다. owner 설정은 서버·worker에 넘기지 않는다. 이미 초기화한 root를 다시 초기화하지 않는다.

터미널 A — API:

```bash
.venv/bin/python -m backend.agent_framework postgres-serve --env-file .runtime/framework-app.env --config examples/agent_framework/team_config.pdf-mock.json --pdf-storage-root "$PWD/.runtime/framework-pdf" --port 8012
```

터미널 B — worker:

```bash
.venv/bin/python -m backend.agent_framework worker --env-file .runtime/framework-app.env --config examples/agent_framework/team_config.pdf-mock.json --pdf-storage-root "$PWD/.runtime/framework-pdf"
```

`--once`를 붙이면 복구 검사 후 접수된 작업을 최대 한 건 처리하고 종료한다. API와 worker는 같은 신뢰한 설정을 사용한다. 설정·공통 코드 해시가 바뀐 이전 실행은 자동으로 새 설정에서 재개하지 않는다. 기존 기록을 보존하고 변경된 설정으로 새 요청 키·새 실행을 만든다.

| 경로 (`/api/framework/v1` 아래) | 용도 |
|---|---|
| POST `/projects/{project_id}/document-versions/{version_id}/extractions` | 등록된 PDF로 A02-only 실행 접수. `202 queued` |
| GET `/runs/{run_id}` | 상태·CriteriaDraft·출처 trace·오류 재조회 |
| GET `/runs/{run_id}/steps` | A02 시작·완료·실패·결과 불명 단계 기록 |
| GET `/runs/{run_id}/approvals` | 이번 단계의 새 PDF 실행에는 빈 승인 목록 |

접수에는 기존 로그인 세션 쿠키, `X-CSRFToken`, `Origin`, `Idempotency-Key` UUID를 사용한다. **본문은 비운다.** 클라이언트 정답·모델 주소·actor/run/criteria ID를 받지 않는다. 서버가 run/criteria ID와 DocumentRef를 만든다. 같은 프로젝트·키·사용자·문서·설정의 재전송은 같은 실행을 돌려준다. 같은 키에 다른 문서·사용자·설정을 넣으면 409다.

기존 이메일 계정 로그인 후 등록된 문서로 접수하는 Python 요청 부분:

```python
from uuid import uuid4
# client는 기존 세션 쿠키와 허용 Origin을 보유한 httpx.Client다.
token = client.get("/api/v1/auth/csrf").json()["csrf_token"]
request_key = str(uuid4())  # 응답을 못 받으면 같은 키를 보존하여 확인
response = client.post(
    f"/api/framework/v1/projects/{project_id}/document-versions/{version_id}/extractions",
    headers={"X-CSRFToken": token, "Idempotency-Key": request_key},
)
response.raise_for_status()
run_id = response.json()["context"]["run_id"]
```

기존 로그인 예제는 [PostgreSQL 가이드](에이전트_프레임워크_PostgreSQL_실행가이드.html)를 따른다. 현재 PDF 전용 초안에 승인 명령을 보내면 409다. 보완·기준 확정·승인 버전 조회는 6단계에서 구현한다. 포스터 없는 상태에서 검수 job을 생성하지 않는다.

## 05. 실제 Qwen 연결 준비

실제 서버가 생기면 Qwen 예시 설정을 로컬 신뢰한 파일로 복사하고 `endpoint`, 요청 모델명, 입력·출력 제한을 맞춘다. 필요한 API 키는 별도 app-only env 파일의 `A02_QWEN_API_KEY`에 두고 Git·채팅·JSON 설정에 넣지 않는다. endpoint는 사용자 업로드에서 받지 않으며 URL에 비밀번호·query·fragment를 넣을 수 없다.

클라이언트는 HTTP redirect·환경 proxy·재시도·형식 보정·대체 모델을 사용하지 않는다. read/write timeout 또는 5xx는 보수적으로 결과 불명으로 기록한다. 완성되지 않은 출력, 과대한 JSON, 중복 키, 스키마·출처 불일치는 실패로 닫는다. 실패 뒤에는 후속 역할을 실행하지 않는다.

요청 경계는 Qwen의 [공식 vLLM API 설명](https://qwen.readthedocs.io/en/latest/deployment/vllm.html)에 맞춘 chat completions 형태다. HTTP 호출과 fake transport 검증에는 [HTTPX 공식 transport 문서](https://www.python-httpx.org/advanced/transports/)를 참고했다. 실제 Qwen3.5-4B 서버의 structured output 지원, 모델 가중치/revision, 시간·정확도는 해당 서버가 준비된 뒤 별도로 확인해야 한다. 응답의 모델명만으로 실제 가중치를 검증했다고 보지 않는다.
