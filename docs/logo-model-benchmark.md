# 로고 검수 모델 성능 비교

「로고검수 모델 성능검토 계획」(2026-10-23)에 따라 후보 모델을 **조합 A 테스트와 같은 동영상·쿼리 로고**로 돌린 결과입니다.
`scripts/bench_logo_models.py` 로 측정하고 `scripts/report_logo_bench.py` 로 생성했습니다.

- 모든 매처는 같은 탐지 후보(OWLv2 텍스트 탐지, 프레임당 상위 `max_boxes`개)를 공유합니다. 차이는 **동일성 대조(매처)** 에서만 나옵니다.
- 조합 A(owlv2+dinov2)도 같은 하네스로 다시 쟀고, 예전 단독 실행 결과를 「기존 A 실행」 열에 나란히 두었습니다.

   (제목 자막 "마약이 온다", "공연봄날" 타이틀, `slw`·`Ai` 마크, "저작물이 무료?" 자막, 공공누리 OPEN 로고),

   (`lg__전남광주통합특별시__동구`, 0.8375)가 영상 속 진짜 KCISA 로고(최고 0.8118)보다 더 닮았다고 나와 변별이 안 됩니다.
2. **SigLIP2가 가장 잘 찾습니다.** 흰색 단색 변형(주황·파랑 배경의 SEOUL MY SOUL), 작고 어두운 로고까지 찾았고
   오탐은 "SEOUL SOUL" 글자 간판 1건입니다. 대신 매처 비용이 DINOv2의 약 6배입니다.
3. **CLIP은 비용 대비 균형형**입니다. 오탐 0건, SigLIP2의 1/3 비용. 흰색 단색 변형 2건(seoul1 t58, seoul6 t2)을 놓쳤습니다.
4. **고정 코사인 기준은 모델 간에 옮길 수 없습니다.** 같은 0.55로 DINOv2는 9장, SigLIP2는 83장, CLIP은 127장을 "발견"합니다.
   매처를 바꾸면 기준도 다시 정해야 하며, 이번에 쓴 **보정 기준(쿼리와 정답이 아닌 기준 로고 사이의 최대 코사인)** 은
   별도 학습 없이 쿼리마다 자동으로 정해져 서비스에 그대로 쓸 수 있습니다.
5. **기준셋 문제 발견:** `lg__서울특별시/logo.png` 는 **심볼만(♡ ! U)** 있는 버전이라, 영상에 실제로 나오는
   SEOUL MY SOUL 워드마크(`seoul_city.png`)를 넣으면 세 매처 모두 서울특별시를 Top-1로 찾지 못합니다
   (DINOv2 47위, SigLIP2 72위, CLIP 6위). 같은 기관의 **로고 변형(워드마크·단색)을 기준셋에 추가**해야 식별이 됩니다.
   심볼만 쓰는 쿼리로는 영상에서 거의 아무것도 찾지 못했습니다(DINOv2 보정 발견 1건 — 워드마크 속 "!" 조각).

**권장:** 매처는 **SigLIP2(정확도 우선) 또는 CLIP(비용 우선)** + **쿼리별 보정 기준**으로 바꾸고, 조합 A의 DINOv2 고정 기준은 쓰지 않습니다.
다음으로는 ① 더 가벼운 `siglip2-base-384`(Pod `/workspace/models` 에 이미 있음)로 비용 재측정, ② HF_TOKEN으로 DINOv3 측정,
③ 기준셋에 로고 변형 추가 후 식별 재측정, ④ 정답 프레임을 사람이 전수 라벨링해 절대 재현율 측정을 권합니다.
