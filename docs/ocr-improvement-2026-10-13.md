# 여러 줄 결합·영역 재인식 구현 및 전후 비교

여러 줄 제목·날짜 결합과 제한된 EasyOCR 재인식을 구현했다. 동일한 비교용 5장에서 필드 일치가 **1/19 → 6/19**로 늘었다. 재인식까지 적용한 경로에서는 관찰된 오통과 1건과 오불충족 2건이 모두 확인 대상으로 바뀌었다. 다만 핵심 문자 오류율은 **22.1%로 같았고**, 재인식이 항상 더 정확한 문구를 주지는 않았다.

라벨은 여전히 사람 확인 전 초안이다. 이 결과를 일반 정확도 향상이나 오판정 완전 해결로 해석하지 않는다. 최종 확인용 3장은 이번에도 추론하지 않았다. 새 경로는 `OCR_PIPELINE`으로 선택하며 기본 `baseline`을 유지한다.

## 실행 방법

기존 EasyOCR 설치·모델 캐시를 그대로 사용한다. 새 패키지나 모델 다운로드는 필요하지 않다. 서버를 중지한 뒤 저장소 루트에서 실행한다.

macOS / Linux:

```bash
OCR_PIPELINE=adaptive ./run.sh
```

Windows PowerShell:

```powershell
$env:OCR_PIPELINE = "adaptive"
.\run.cmd
```

| 설정 | 동작 |
|---|---|
| `baseline` 또는 미설정 | 기존 EasyOCR·한 줄 추출 |
| `multiline` | 기존 OCR 결과에서 제목·날짜 결합 |
| `adaptive` | 전체 OCR → 제한된 재인식 → 제목·날짜 결합 |

`adaptive`는 현재 `RUN_TARGET=local`에서만 지원한다. RunPod 설정이 있으면 명시적 오류로 중단하며 로컬 실패를 원격으로 보내지 않는다. 기본 경로로 돌아가려면 `OCR_PIPELINE=baseline`으로 실행한다. Windows에서 설정을 제거하려면 `Remove-Item Env:OCR_PIPELINE`을 사용한다.

결과 화면은 후보가 충돌한 근거에 **처음 읽기 / 다시 읽기**를 함께 표시한다. ‘위치 보기’는 정규화 원본 좌표를 사용한다. JSON 내보내기에는 결합 필드, 구성 OCR ID·박스, 원래 문구·후보·검토 플래그가 포함된다. 전체 시도·crop·모델 해시·원시 결과는 해당 `.runtime/reviews/<id>/`의 비공개 파일에 보존된다.

## 구현 동작

### 제목과 날짜 결합

`backend/app/event_layout.py`가 글자 높이 비율, 수평 겹침, 줄 간격으로 이웃을 찾는다. 제목이 상단에 있다는 전제나 고객별 좌표·정답 치환을 사용하지 않는다.

- 축제/페스티벌로 끝나는 제목 후보에서 앞쪽 조각을 최대 네 줄까지 연결한다. 한 줄의 선행 연도 제거도 유지한다.
- 서로 다른 완전한 행사명, 두 개의 앞줄 후보, 다른 열, 중간 OCR 줄을 건너뛰는 결합은 확정하지 않는다.
- 독립된 연도와 `5.24 - 5.31` 같은 기간, `2026.1.23 ~ 25`처럼 종료 월이 생략된 표현을 처리한다.
- 인쇄된 연도·월만 상속한다. 없는 구분 기호·연도·월 넘김을 추측하지 않으며 실제 날짜, 시작·종료 순서, 관찰된 요일을 검증한다.
- 결합 결과에 구성 OCR ID, 개별 박스, 합집합 박스를 남긴다. OCR 영역 수와 후보 탐색 횟수에도 제한을 둔다.

현재 제목 끝말과 날짜 표현은 여전히 제한된 규칙이다. 모든 행사명, 세로 읽기 순서, 혼합 언어, 임의의 레이아웃을 처리하는 일반 모델은 아니다. 장소의 여러 줄 결합은 이번 변경 대상에 포함하지 않았다.

### 재인식과 후보 선택

`backend/app/adaptive_ocr.py`는 다음 제한으로 동작한다.

| 대상 | 제한과 방식 |
|---|---|
| 전체 이미지 재검토 | 필수 필드 미추출·후보 충돌 시 최대 1회. beamsearch와 완화된 탐지 설정 사용 |
| 영역 재인식 | 최초 OCR 근거에서 선택한 최대 8개. 낮은 점수뿐 아니라 높은 점수의 핵심 정보도 재확인 |
| crop | 글자 높이의 12% 여백, 확대·회색조·대비 조정. 고객 라벨 박스를 사용하지 않음 |
| 시간 | 재시도 시작 전 25초 예산 확인. 로드·기준선·재시도를 포함한 작업 프로세스 전체는 최대 60초 |
| 실패 | 개별 재인식 실패는 기록 후 다음 대상 처리. 시간 초과 시 실제 자식 프로세스를 종료 |

25초는 새 시도를 시작하는 예산이다. 진행 중인 단일 추론을 그 시점에 즉시 끊는 것은 아니며, 프로세스의 60초 제한이 최종 상한이다. 기준선까지 저장되었다면 중단 시 그 결과를 복구하되 모든 근거에 검토 필요를 표시한다. 기준선도 없으면 실행 실패로 반환한다. 실패·미실행을 통과로 대체하지 않는다.

원문과 후보가 같아도 confidence를 올리지 않는다. 서로 다르면 충돌로 보존하고 자동 확정에 사용하지 않는다. 원래 confidence가 0.6 미만이고 새 후보가 0.75 이상인 경우에는 새 문구를 **미확정 후보**로 선택할 수 있지만 검토 필요 상태는 유지한다. 이 점수 조건은 진실 판정이나 확률 보정이 아니다. 실제로 더 높은 점수의 후보가 틀린 사례도 아래 비교에서 확인됐다.

crop 해시, 크기, 확대·이동 역변환 행렬, 원시 출력, 실제 장치와 fallback 이력, 소요 시간, 모델 이름·버전·가중치 해시를 남긴다. API의 근거 박스·후보 박스는 입력 2배 좌표에서 정규화 원본으로 한 번만 변환한다. 기대 문구·라벨·파일명 정답은 추론에 전달하지 않는다.

재인식 설정은 [EasyOCR 공식 API 문서](https://jaided.ai/easyocr/documentation/)와 설치된 1.7.2 구현을 확인했다. 이번 단계에는 PaddleOCR·Qwen 설치 또는 모델 교체가 포함되지 않았다.

## 동일 입력 전후 실측

같은 `posters-v1` 비교용 5장, RGB 2배 입력, 동일 라벨 스냅샷, 각 조합 1회로 측정했다. 입력·원본·라벨 해시와 분할·반복 수를 비교 도구로 검증했다. 모델 선택용 초안 19개 필드, 199개 핵심 문자, 정상 기준 14개·위반 기준 1개·시각 확인 기준 2개를 사용했다.

| 처리 경로 | 추론 성공 | 필드 일치 | 필드 누락 | 문자 오류율 | 오통과 / 위반 기준 | 오불충족 / 정상 기준 | 추론 중앙값 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 기존 `baseline` | 5/5 | 1/19 | 14 | 22.1% | 1/1 | 2/14 | 0.543초 |
| 줄 결합 `multiline` | 5/5 | 6/19 | 11 | 22.1% | 1/1 | 0/14 | 0.521초 |
| 결합+재인식 `adaptive` | 5/5 | 6/19 | 10 | 22.1% | 0/1 | 0/14 | 1.320초 |

실행 완료는 사람 승인을 의미하지 않는다. 추론 시간은 모델 import·로드와 벤치마크의 사후 평가를 제외한다. `baseline`과 `multiline`의 OCR 호출은 같으므로 위 두 시간 차이는 줄 결합 비용으로 해석할 수 없다. 조합별 한 번의 실행과 시스템 변동이 포함되며 서버 지연의 안정적인 평균·p95가 아니다.

| 포스터 | 기존 필드 일치 | 개선 필드 일치 | 실제 변화 |
|---|---:|---:|---|
| 김천 | 0/4 | 0/4 | 행사명·날짜 복원 실패. 틀린 장소 문구를 요구한 기준은 후보 충돌로 review 전환 |
| 춘천 | 0/3 | 2/3 | 분리된 연도와 기간 결합 성공. 행사명은 아직 복원 실패 |
| 구미 | 1/4 | 1/4 | 장소만 일치. `축체` → `축제` 후보가 생겼지만 전체 제목은 오인식 |
| 단양 | 0/4 | 3/4 | 두 줄 행사명, 종료 월 생략 날짜의 시작·종료일 추출 성공 |
| 안동 | 0/4 | 0/4 | 장식 글꼴 오인식과 날짜 구분 기호 누락이 남음 |

필드 일치의 증가는 이번 사례에서는 **줄 결합·날짜 해석**에서 발생했다. 재인식은 일치 필드를 더 늘리지 못했다. 초안과 다른 필드도 생길 수 있으므로 단순히 null이 줄었다고 정확도가 좋아졌다고 해석하지 않는다.

재인식의 오통과 감소는 틀린 원문을 정확하게 고친 결과가 아니라, **서로 다른 후보를 발견해 확인 대상으로 전환한 결과**다. 전체 확인 필요는 13/17 → 16/17로 늘었고 올바른 통과는 1/14 → 1/14였다. 줄 결합만 적용했을 때 올바른 통과는 2/14였으므로 재인식은 정상 항목 한 개도 추가로 보류했다. 춘천의 `춘천`이 높은 점수의 `초천` 후보로 바뀌는 등 개별 인식 악화도 있었다. 기본 OCR을 새 경로로 교체하지 않은 이유다.

실측 환경은 macOS 26.3.1 ARM64, Python 3.12.14, EasyOCR 1.7.2, torch 2.10.0, torchvision 0.25.0이며 최종 비교 실행 15건 모두 MPS에서 성공했다. 각 adaptive 실행은 전체 1회·crop 8회, 다섯 장에서 총 45회의 추가 재인식을 수행했고 실패·시간 초과는 없었다. 비교 실행 당시의 코드 해시 8개도 현재 소스와 일치한다. CPU/CUDA/Windows/RunPod의 실제 추론 성능은 이번에 측정하지 않았다.

실행별 폴더:

- 기존: `artifacts/ocr-benchmarks/20261013T075615Z-fe46549a/`
- 줄 결합: `artifacts/ocr-benchmarks/20261013T075633Z-5145be1f/`
- 결합+재인식: `artifacts/ocr-benchmarks/20261013T075650Z-2c3d3426/`
- 초기 개발 실측: `artifacts/ocr-benchmarks/20261013T074157Z-04eeca13/` — 최종 비교에서는 제외

## 재측정 명령

```bash
.venv/bin/python -m scripts.benchmark_ocr --pipeline baseline --variants rgb_2x
.venv/bin/python -m scripts.benchmark_ocr --pipeline multiline --variants rgb_2x
.venv/bin/python -m scripts.benchmark_ocr --pipeline adaptive --variants rgb_2x
```

세 명령이 출력한 실행 폴더의 `report.json`을 비교한다. 아래는 이번 최종 실측 경로다.

```bash
.venv/bin/python -m scripts.compare_benchmarks artifacts/ocr-benchmarks/20261013T075615Z-fe46549a/report.json artifacts/ocr-benchmarks/20261013T075633Z-5145be1f/report.json artifacts/ocr-benchmarks/20261013T075650Z-2c3d3426/report.json
```

동일 라벨 스냅샷·입력·분할·반복 수가 아니면 비교를 거절한다. 새 실행은 별도 폴더를 만들고 과거 결과를 덮어쓰지 않는다. 결과 이미지와 모델은 Git 제외를 유지한다.

## 검증 및 변경 파일

- Python **164개 + 하위 테스트 7개** 통과. 위치·배율이 달라진 제목, 분리된 날짜, 잘못된 날짜·요일, 다른 열·복수 후보, crop 역변환, 재시도 상한·실패·timeout 복구, 오통과 방지, API 좌표·근거 보존, 비교 입력 일치 검증을 포함한다.
- 프런트엔드 단위 테스트 **18개**, 모의 응답 기반 브라우저 테스트 **16개** 통과. 원문·후보 표시와 근거 위치를 실제 Chrome에서 확인했다.
- React 빌드 성공. 새 `frontend/dist`도 함께 갱신했다.
- 실제 MPS 비교 실행 15건과 adaptive의 추가 재인식 45회는 위 모의 테스트와 별도로 실행했다. 새 함수와 주요 처리에 간단한 한국어 주석을 추가했다.

| 파일 | 변경 |
|---|---|
| `backend/app/event_layout.py` | 제목·날짜의 좌표 기반 결합 |
| `backend/app/adaptive_ocr.py` | 영역/전체 재인식, 시간 제한, 후보·모델 근거 보존 |
| `backend/app/api.py` | 경로 선택, 후보 좌표 복원, 원시 결과·결합 필드 저장 |
| `backend/app/review_rules.py` | 결합 필드 비교와 미확정 후보의 자동 확정 방지 |
| `scripts/benchmark_ocr.py`, `scripts/ocr_metrics.py` | 처리 경로별 측정과 오불충족 집계 |
| `scripts/compare_benchmarks.py` | 같은 조건의 전후 보고서 검증·비교 |
| `frontend/src/pages/review/ResultsPage.jsx` | 처음 읽기·다시 읽기 비교 표시 |
| `backend/tests/test_adaptive_ocr.py`, `tests/test_ocr_benchmark.py`, `frontend/tests/e2e/login.spec.mjs` | 계약·회귀·화면 검증 |

로고·잘림은 계속 사람 확인 대상으로 남는다. 다음 모델 비교에서는 문자 오류율, 올바른 통과율, 추가 보류율을 함께 확인해야 한다. 라벨의 사람 확인과 더 다양한 회귀 사례 보강, PaddleOCR/Qwen 비교는 남은 작업이다.
