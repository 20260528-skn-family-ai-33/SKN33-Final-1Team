Creative Checker 실험 총정리

포스터와 영상의 글자를 읽는 능력은 충분히 올라왔습니다. 이제 성능을 가르는 곳은 읽은 값을 항목에 담고 기준과 맞춰 판단하는 단계입니다.

파란 글씨는 그대로 말해도 되는 발표 멘트입니다. 막대와 행에 마우스를 올리면 세부 수치가 보입니다.

핵심 인사이트서비스 구성문서포스터 글자시각 요소판정자막로고한계표현예상 질문전체 목록

실험에서 얻은 다섯 가지

  1. 포스터는 모델이 직접 보게 하는 편이 낫다같은 모델의 8요소 F1이 OCR 경유 64.1에서 이미지 직접 입력 74.6로 올랐습니다.
  2. 병목은 읽기가 아니라 골라 담기다가장 좋은 Gemma도 글자 받아쓰기 97.1와 8요소 83.6 사이에 13.5p 차이가 납니다.
  3. 재학습보다 출력 통제가 잘 들었다형식 고정과 1회 재요청으로 조건 일치가 65%에서 95%로 올랐고, LoRA 학습은 정보 추출을 바꾸지 못했습니다.
  4. 약점이 다른 모델은 이어 붙인다객체 탐지 재현율 53.3 → 81.5, 자막 판독 실패 27장 → 0장.
  5. 체감 품질은 판정 규칙이 좌우한다확인 필요 17개 → 7개는 코드 판정의 효과이고, 로고 정상 통과 40/88의 다음 과제도 규칙입니다.

문서에서 검수 기준 뽑기

PDF 의뢰서를 믿을 수 있는 검수 기준으로 바꿀 수 있는가?

무엇을 했나

  • 합성 요구 문장으로 Qwen3.5-4B의 출력 형식을 네 번 바꾸고, 검증 실패 시 한 번 재요청하도록 했습니다.
  • 새 72문장에서 라벨 추출과 조건 전체 일치를 따로 쟀습니다.
  • 실제 PDF를 테스트 서버에서 돌려 처리 시간과 실패 지점을 확인했습니다.

알게 된 것

  • 라벨 정확도는 99.10%였지만 조건까지 모두 맞은 문장은 74.63%(50/67)입니다. 무엇을 요구하는지 아는 것과 값까지 정확한 것은 다릅니다.
  • 2쪽 PDF는 3건을 동시에 넣어도 건당 약 114초에 기준 초안 13개가 나왔습니다.
  • 7쪽 계약서는 594초 뒤 출력 한도 16,384토큰에 걸려 실패했습니다. 아직 남은 한계입니다.
  • 8개 문서 시험에서 6개 문서의 문구 후보 38개가 검증 규칙 때문에 버려졌습니다. 규칙을 고친 뒤 재현 응답에서 남는 기준이 0개에서 28개로 늘었습니다.

2단계

포스터의 글자와 정보 읽기

OCR로 읽어 넘기는 방식과 모델이 이미지를 직접 보는 방식 중 무엇이 나은가?

무엇을 했나

  • EasyOCR과 PaddleOCR을 비교한 뒤(5장), 축제 포스터 111장에서 OCR 글자만 넣는 경우와 이미지를 함께 넣는 경우를 비교했습니다.
  • 같은 187장으로 PaddleOCR, Kanana, Qwen3.5-4B, Qwen 27B·35B, Gemma 31B를 차례로 시험했습니다.
  • 글자 전체 받아쓰기와 행사명·날짜 등 8요소 추출을 나눠 채점했습니다.
  • Qwen3.5-4B에 글자 읽기 LoRA 학습도 시도했습니다.

알게 된 것

  • 같은 Qwen3.5-4B라도 이미지를 직접 보면 8요소 F1이 74.6, OCR 글자를 넘기면 64.1입니다. 축제 4칸 모두 정답 비율도 규칙 25.5%, Qwen3-VL-8B+이미지 54.7%였습니다.
  • 글자 받아쓰기는 94.6~97.6로 모델 차이가 작고, 8요소는 74.6~83.6로 벌어집니다. 8요소 1위는 Gemma 4 31B입니다.
  • 같은 문장을 되풀이하는 출력을 끊는 규칙만으로 Qwen3.5-4B 글자 F1이 88.3에서 94.6로 올랐습니다.
  • LoRA 학습 뒤 줄 읽기 완전 일치는 52.8%에서 82.0%로 올랐지만, 행사 정보 4칸 정답은 46.0%에서 45.6%로 그대로였습니다.
  • 속도만 보면 PaddleOCR이 장당 0.41초로 Qwen3.5-4B(7.2초)보다 약 17배 빠릅니다.

포스터의 시각 요소 찾기

사람, 건물, 로고 같은 시각 요소를 모델이 찾아낼 수 있는가?

무엇을 했나

  • ResNet, DINOv2, EmbeddingGemma, SigLIP2 등 18개 구성으로 8개 라벨 분류를 비교했습니다.
  • SigLIP2는 부분 학습, LoRA, 자료 보강까지 시도했습니다.
  • 포스터 50장의 객체 정답을 새로 만들고 Qwen3.5-4B, OWLv2, Grounding DINO를 비교했습니다.

알게 된 것

  • 분류 최고값은 85.46%였지만 개발셋 조건을 통과하지 못해 84.40% 모델을 유지했습니다. 목표 90%에는 닿지 못했습니다.
  • Qwen은 틀린 상자가 적고(정밀도 81.8) OWLv2는 많이 찾습니다(재현율 68.6). 겹치지 않는 OWLv2 상자만 더하면 재현율이 53.3에서 81.5로 오릅니다.
  • 로고는 결합해도 재현율이 49%입니다. 작은 기관 로고는 이 방식만으로 부족합니다.

기준과 대조해 판정하기

읽은 값을 기준과 비교해 충족, 불충족, 확인 필요로 제대로 나누는가?

무엇을 했나

  • ‘확인 필요’가 많다는 문제의 원인을 추적했습니다.
  • 날짜·요일·시각은 표기가 아니라 뜻하는 값으로, 파일 형식·크기는 업로드 원본에서 잰 값으로 판정하도록 바꿨습니다.
  • 실제 PDF와 포스터 쌍으로 끝까지 돌려 보았습니다.

알게 된 것

  • 원인은 모델이 아니라 판정 규칙이었습니다. 모델 답과 무관하게 날짜와 파일 규격을 사람에게 넘기고 있었습니다.
  • 재생 시험은 모델이 포스터를 완벽히 읽었다고 가정한 값입니다. 실제 포스터 정확도가 아닙니다.
  • 공연 의뢰서 시험에서 4/8에 머문 이유 중 하나는 검사 모델 응답에 관측값이 없던 것입니다. 끝까지 잰 표본은 아직 작습니다.

영상 자막 읽기

영상 프레임의 글자를 어떤 구성으로 읽어야 가장 안정적인가?

무엇을 했나

  • 합성 광고 영상 62편으로 검수 파이프라인 시제품을 만들어 게이트별로 채점했습니다.
  • 실제 홍보 영상 19편에서 Qwen3-VL-8B, OpenAI, 둘을 잇는 구성을 같은 정답으로 비교했습니다.
  • 보안 자료용으로 Qwen 요청 설정 네 가지를 시험했습니다.

알게 된 것

  • 둘 다 읽은 1,236장에서는 Qwen이 재현율 93.0 대 92.1로 앞섭니다. Qwen의 약점은 반복 출력이나 글자가 많은 화면에서 응답이 끊기는 2.1%입니다.
  • 실패 프레임만 OpenAI가 채우면 실패가 0장이 됩니다.
  • 보안 자료는 외부 전송을 못 하므로, 출력 한도 4096과 presence_penalty 1.0으로 실패를 27장에서 6장으로 줄였습니다. 이 설정은 아직 앱 코드에 넣지 않았습니다.
  • 합성 영상 시험에서는 OCR이 띄어쓰기를 잃어 문구 완전일치가 0.435였고, 공백을 무시하면 0.966이었습니다.

영상 로고 대조

지정한 로고가 영상에 정확히 나오는지 자동으로 가려낼 수 있는가?

무엇을 했나

  • 탐지기와 매처 조합을 비교한 뒤, 후보 탐지부터 정렬까지 다섯 역할에서 22개 모델을 한 단계씩 바꿔 시험했습니다.
  • 정상 로고 88장과 다른 로고 28장으로 정밀 대조를 채점했습니다.

알게 된 것

  • 탐지, 순위, 배경 분리, 글자 비교 모두 지금 쓰는 모델이 1위였습니다. 모델을 바꿀 이유는 찾지 못했습니다.
  • 다른 로고는 모두 잡았지만 정상 로고도 절반 이상 통과하지 못했습니다. 다음 개선 대상은 판정 규칙입니다.
  • 순위 1위가 정답인 경우는 47%입니다. 자동 결과는 근거로 쓰고, 위치 수정과 최종 결정은 사람이 합니다.
