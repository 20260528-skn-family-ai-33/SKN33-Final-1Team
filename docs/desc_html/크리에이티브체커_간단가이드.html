02

서비스 명세 한눈에 보기

포스터 이미지에서 글자를 읽고, 사용자가 확정한 요구사항과 비교해 판정과 근거를 함께 저장하는 서비스입니다.

  1. 01로그인발급된 이메일 또는 허용된 개발 계정
  2. 02자료 등록프로젝트 선택 · 포스터 업로드
  3. 03기준 확정요구사항 편집 · 불변 버전 저장
  4. 04검수 실행DB 접수 → worker OCR·판정
  5. 05결과 확인근거 박스 · 이력 · JSON 내보내기
기능사용자가 할 수 있는 일
계정·프로젝트발급받은 이메일 계정으로 로그인하고 프로젝트를 선택·생성합니다.
입력·기준PNG/JPEG/WEBP 1개와 요구사항을 등록하고 기준 버전을 확정합니다.
검수·결과충족 / 위반 / 확인 필요, OCR 근거, 행사 정보와 JSON 결과를 확인합니다.
이력·복구저장한 초안·기준·실행을 다시 열고, 필요하면 새 실행으로 재검수합니다.
완료와 승인 구분
검수의 completed는 자동 처리가 끝났다는 뜻입니다. 사람의 최종 승인이나 학습 라벨 확정을 뜻하지 않습니다.
03

실행 경로 먼저 선택하기

항목기존 시제품 · 기본 실행새 v1 · 별도 실행
진입점./run.sh / .\run.cmdpython -m scripts.run_v1 --env-file .env.v1
로그인로컬 개발 계정 admin/admin이메일/비밀번호 + 조건부 개발 계정
데이터.runtime/reviews/의 JSON·이미지PostgreSQL M008 + 전용 파일 저장소
검수 실행웹 프로세스의 BackgroundTasks별도 PostgreSQL 큐 worker 프로필
화면 빌드frontend/distfrontend/dist-v1
현재 사용 조건기존 패키지·모델·화면 빌드 준비추가로 스키마·계정·저장소·worker 설정 준비
admin/admin은 유지됩니다
기존 시제품의 개발 로그인을 유지합니다. 새 v1에서는 개발 모드·loopback·개발 계정/프로젝트 초기화가 모두 준비되어야 사용할 수 있습니다. 운영에서는 사용하지 않습니다.
04

빠른 실행

아래 명령은 준비가 끝난 환경 기준입니다. 명령은 저장소 루트에서 실행합니다. 처음 설치하거나 v1을 처음 설정한다면 상세 버전의 최초 설정 ↗을 먼저 완료하세요.

A. 기존 시제품 체험

macOS / Linux · 한 줄씩 실행
./run.sh --check-only
./run.sh
Windows · PowerShell
.\run.cmd --check-only
.\run.cmd

http://127.0.0.1:8000/login을 열고 admin/admin으로 로그인합니다. 샘플 체험 또는 이미지 입력 → 기준 확정 → 검수 시작 순서입니다.

B. 새 v1 사용

M008 DB, 발급 계정, 초기화한 저장소, Paddle 모델, worker가 생성한 설정, dist-v1 빌드가 필요합니다. 웹과 worker는 같은 DB·저장소·코드/모델 구성을 사용합니다.

터미널 1 · v1 웹
.venv/bin/python -m scripts.run_v1 --env-file .env.v1 --host 127.0.0.1 --port 8000
터미널 2 · 독립 worker
.venv/bin/python -m backend.app.worker --env-file .env.worker

http://127.0.0.1:8000/login에서 발급받은 이메일/비밀번호로 로그인합니다. .env.v1의 FRONTEND_DIST는 빌드된 frontend/dist-v1의 절대 경로여야 합니다.

실행할 때 기억할 것
기존 시제품과 v1을 같은 8000번 포트에 동시에 띄우지 마세요. 터미널을 유지하고 종료는 각 터미널에서 Ctrl+C로 합니다. v1 worker는 처리 중 작업을 마무리한 뒤 종료될 수 있습니다.
05

실행 후 확인하기

  • 이메일 계정으로 로그인하고 자신의 프로젝트가 표시된다.
  • 이미지를 업로드하고 초안을 저장한 뒤 기준을 확정할 수 있다.
  • 새 검수가 queued → running → completed로 진행되거나 명시적 실패 사유를 표시한다.
  • OCR 텍스트·근거·표시 이미지·JSON 내보내기를 확인할 수 있다.
  • 새로고침과 웹/worker 재시작 후에도 저장한 이력을 다시 조회할 수 있다.
화면이 열린 것만으로 OCR 준비 완료는 아닙니다
/api/v1/health의 DB·파일 상태를 확인하고 실제 검수 1회를 완료하세요. worker/model의 unknown은 추론 성공을 확인했다는 뜻이 아닙니다.

v1에 공개 회원가입·이메일 인증 메일·비밀번호 찾기 화면은 없습니다. 계정 발급과 비밀번호 재설정은 관리자 CLI를 사용합니다.
