자막 판독 Qwen·OpenAI 비교

홍보 영상 19편, 1초 간격 1,267프레임에서 화면 글자를 읽는 성능을 같은 프레임·같은 정답 라벨·같은 채점기로 비교했다. 비교한 구성은 넷이다. Qwen3-VL-8B 단독, OpenAI gpt-6-luna 단독, 둘을 잇는 현재 파이프라인, 그리고 Qwen 요청 설정을 바꾼 보강안이다.

결론

테스트 결과, 현재 자막 판독 파이프라인(Qwen3-VL-8B가 먼저 읽고, Qwen이 읽지 못한 프레임만 OpenAI가 다시 읽는 구성)이 시험한 구성 중 가장 좋다.

  • 가장 높은 정확도: 재현율 93.0%, 문자 오류율 5.32%, 판독 실패 0장으로, 시험한 구성 중 셋 다 가장 좋다. 처음 보는 영상(holdout)에서도 재현율 90.2%, 문자 오류율 7.68%로 가장 좋다.
  • Qwen을 먼저 쓰는 근거: 두 모델이 모두 읽은 프레임에서는 Qwen이 재현율·정밀도·문자 오류율 모두 OpenAI보다 낫다. 정밀도는 91.3% 대 89.2%로, 맞는 자막을 오탈자로 잘못 경보하는 일이 적다.
  • OpenAI를 보조로 붙이는 근거: Qwen의 약점은 글자가 많은 화면에서 생기는 판독 실패(2.1%)다. 이 프레임만 OpenAI가 채우면 실패가 0이 되고 전체 정확도가 단독 모델 어느 쪽보다 높아진다.
  • 보안 자료 경로 보강: 보안 자료는 OpenAI를 쓸 수 없어 Qwen만 읽는다. Qwen 요청 설정을 바꾸는 보강안으로 실패가 27장에서 6장으로 줄었다.

Qwen의 빈틈은 OpenAI가 채운다

  • Qwen 단독의 약점: 27장(2.1%)을 읽지 못했다. 같은 항목을 반복하거나 글자가 너무 많은 화면에서 2,048토큰 한도에 걸려 응답이 끊긴 경우다.
  • OpenAI 단독의 약점: 실패는 없지만, 읽은 프레임의 정밀도와 문자 오류율이 Qwen보다 떨어진다.
  • 둘을 이으면: Qwen이 잘 읽는 98%는 Qwen 결과를 쓰고, 나머지 2%만 OpenAI가 채운다. 두 모델의 강점만 남아 재현율·CER·실패가 모두 가장 좋아진다.
  • 정밀도는 Qwen 단독이 더 높아 보인다. Qwen 단독은 읽지 못한 27장이 아무 항목도 내지 않아 정밀도 분모에서 빠진다. 파이프라인에서는 그 27장(대부분 글자가 빽빽한 안내·웹페이지 화면)을 OpenAI가 읽어 장당 수십 개 항목이 분모에 들어간다. Qwen이 읽는 나머지 1,240장에서는 파이프라인 출력이 Qwen 출력과 같으므로, 정밀도 우위도 그대로 유지된다.
  • OpenAI가 앞서는 지표는 띄어쓰기 완전일치와 배경 글자다. 배경 글자(간판·현수막)는 자막 검수의 주 대상이 아니다. 띄어쓰기만 다른 문구는 판정 단계에서 '사람 확인'으로 넘기는 규칙으로 처리한다.

보안 자료 경로 보강: Qwen 요청 설정

보안 자료는 OpenAI 보조가 없어 Qwen이 읽지 못한 프레임이 '못 읽음'으로 남는다. 실패 27장은 모두 응답이 2,048토큰 한도에서 끊긴 경우였다. 같은 항목 반복이 16장, 글자가 정말 많은 화면이 10장, 빈 줄만 이어 쓴 응답이 1장이다. 실패한 27장에 요청 설정 4가지를 시험했다.

위 다섯 줄은 실패했던 27장만 다시 읽어 현행 결과에 끼워 넣고 전체로 채점한 값이다. 마지막 줄은 처음부터 전부 다시 읽은 값이다.

  • 잘 읽던 프레임에는 영향이 거의 없다. 현행과 보강안이 모두 읽은 1,239장에서 재현율 93.0 → 92.8, 정밀도 91.1 → 92.0, CER 5.25 → 5.42로 변화가 1p 안쪽이다. 1,023장(82.6%)은 출력이 완전히 같다.
  • 처리 시간도 같다. 프레임당 지연 중앙값은 6.4초에서 6.1초로 비슷하고, 전체 소요도 3,485초 대 3,472초다. 다만 끝까지 반복에 빠지는 프레임은 최대 310초가 걸린다.
  • 남은 6장: 로고 글자를 반복하는 bamicha 14초와 daejeon 7초, 그리고 글자가 매우 많은 kcisa 웹페이지 4장이다. 일반 자료라면 OpenAI가 채우고, 보안 자료라면 '사람 확인'으로 넘긴다.

수치를 읽을 때 주의할 점

  • 현재 파이프라인과 OpenAI 단독 값은 다시 채점하지 못했다. 11/16·17 측정 보고서의 집계를 옮겼다. OpenAI 원본 판독 결과가 이 작업 환경에 없어서다. Qwen 값은 RunPod 원본을 같은 채점기로 다시 채점해 일치를 확인했다.
  • Qwen 보강안을 쓴 파이프라인 점수는 계산하지 않았다. 같은 이유다. 보강안은 Qwen 단독 실패를 줄이므로, 파이프라인에 넣어도 OpenAI가 다시 읽는 프레임만 27장에서 6장으로 줄어든다.
  • 앱의 실패 처리 방식은 시험과 조금 다르다. 앱은 Qwen이 2번 시도해 실패한 프레임을 바로 OpenAI로 넘긴다. 시험의 Qwen 결과는 실패한 프레임을 한 바퀴 더 읽은 뒤의 값이다. OpenAI가 다시 읽는 프레임 수가 27장에서 30장 안팎으로 늘 뿐, 결론은 같다.
  • 정답 라벨은 silver다. 사람 최종 확인 전이므로 1p 안팎의 차이는 순위를 단정할 근거가 되지 못한다. 현재 파이프라인의 우위는 여러 지표와 holdout에서 같은 방향으로 나타난다는 점에 근거한다.
  • 요청 조건이 완전히 같지는 않다. 출력 토큰 한도가 OpenAI 8192, Qwen 2048이다. OpenAI의 한도에는 추론 토큰도 포함된다.
  • 판정 정확도는 별건이다. 이 시험은 화면 글자를 정확히 읽었는지만 본다. 오탈자를 일부러 넣은 프레임에서 그대로 읽어 내는지, 계약서 기준 통과·불합격 판정이 맞는지는 측정하지 않았다.
결론과 권고

시험한 네 구성 중 현재 파이프라인(Qwen3-VL-8B 기본 판독 + 일반 자료는 실패 프레임만 OpenAI 보조 판독)이 재현율·문자 오류율·판독 실패 모두 가장 좋다. 이 구성을 유지한다.

  1. 현재 파이프라인을 유지한다. 읽은 프레임의 품질은 Qwen이 OpenAI보다 낫고, Qwen이 놓치는 2%는 OpenAI가 채운다. 단독 모델 어느 쪽보다 정확하다.
  2. 보안 자료 경로를 보강한다. Qwen 요청을 max_tokens 4096 + presence_penalty 1.0으로 바꾸면 Qwen 단독 실패가 27장에서 6장으로 줄고, 잘 읽던 프레임과 처리 시간은 그대로다. 일반 자료 경로에서도 OpenAI 호출이 줄어든다.
  3. 남은 실패와 띄어쓰기는 판정 단계에서 처리한다. 보안 자료에서 읽지 못한 프레임과 띄어쓰기만 다른 문구는 '사람 확인'으로 넘긴다.
  4. 확정 전에 두 가지를 보완한다. OpenAI 원본으로 파이프라인 점수를 다시 채점하고, 정답 라벨을 사람이 확인해 gold로 올린다.
