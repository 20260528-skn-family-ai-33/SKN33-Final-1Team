# PDF 요구사항 입력

`run.sh` / `run.cmd`로 실행하는 현재 로컬 검수 화면에 PDF 조건 추출을 연결했습니다. 화면은 `POST /api/requirements/extract/stream`으로 진행 상태와 완료 결과를 받고, 기존 JSON 응답용 `POST /api/requirements/extract`도 유지합니다. 별도 PostgreSQL v1 화면에는 연결하지 않았습니다.

## 사용

1. 자료 입력의 **3. 검수 요구사항 → PDF 파일 추가**에서 요구사항 PDF를 선택합니다.
2. 조건을 읽는 동안 **진행률 바·퍼센트·현재 단계·분석 페이지·경과 시간**이 표시됩니다. 기존 입력은 보존되며, 완료하면 조건이 뒤에 추가됩니다.
   검수 입력에는 `행사명: 김천김밥축제`, `기간: 2026.10.23 ~ 10.25`, `장소: 직지문화공원`처럼 구체적인 값만 넣습니다. 시각 조건은 `김천시 로고가 표시되어 있어야 합니다.` 같은 짧은 문장으로 표시합니다. LLM은 행의 전체 기대 내용을 `requirement`, 짧은 입력값 목록을 `values`, 설명을 `inspection`으로 나눠 반환하고 정보 항목의 짧은 값을 검수 입력으로 만듭니다. 복합 지명·협연 출연진·파일 규격과 시각 조건의 술어는 모델이 값 목록에서 쪼개더라도 행의 전체 기대 내용으로 유지합니다. 복수의 필수 장소는 한 줄씩 나누되 OR 대안이나 한 장소의 정식 명칭은 임의로 나누지 않습니다. 모델이 쉼표로 묶어 반환한 경우에도 판단 설명에 모두·각각·전부가 명시된 장소만 분리하고, 각 항목에 같은 수준·설명·원문 근거를 연결합니다.
3. **검수 항목 확인하기**에서 항목별 유형·내용·요구사항 원문을 확인합니다. 필수·권장·선택 수준과 예외·판단 설명은 입력 문구에 붙이지 않고 **상세 기준**에서 표시합니다. 파일명·페이지와 PaddleOCR 판독문 구간도 보존합니다. OCR 판독문은 PDF 원본과 구분해서 표기합니다. 직접 수정한 입력 줄은 사용자 입력으로 취급합니다.
4. 사람이 기준을 확정한 뒤 기존 OCR 검수를 실행합니다.

지원 한도는 파일 10MiB, 12페이지, 추출 원문 16,000자입니다. 최종 입력은 기존 텍스트 포함 6,000자·100개 조건으로 제한합니다. 빈 파일, 암호화·손상 PDF, 잘못된 모델 응답과 제한 초과에는 오류를 표시하며 일부만 조용히 반영하지 않습니다. 동일 문장은 중복 추가하지 않습니다.

진행률은 예상 소요 시간이 아니라 완료한 페이지와 처리 단계의 비중입니다. 업로드 후 2%, 모델 준비 확인 5%, PDF 페이지 읽기 10~50%, 선택 페이지의 LLM 조건 분석 50~95%, 원문 근거·결과 검사 96%를 표시합니다. 한 페이지의 모델 응답을 기다리는 동안에는 같은 퍼센트에서 경과 시간이 갱신되고, 해당 분석이 끝나면 다음 비율로 올라갑니다. 100%는 최종 응답을 받고 기존 입력에 조건을 반영한 뒤에만 표시합니다. 실패·연결 중단·취소는 완료로 표시하지 않습니다.

진행 상태는 PDF 처리 격리 프로세스에서 임시 파일로 전달하고 서버가 NDJSON으로 중계합니다. 모델 호출 중에는 빈 줄 heartbeat로 연결을 유지합니다. 브라우저가 연결을 끊어도 이미 시작한 분석은 기존 제한 시간까지 계속될 수 있으며, 해당 분석이 끝나야 추론 잠금이 해제됩니다. 진행 상태·원본 PDF는 영구 저장하지 않습니다.

## 로컬 준비

기존 가상환경에서 PDF 패키지를 설치합니다.

```sh
.venv/bin/python -m pip install pypdfium2==5.14.0
```

Windows에서는 `.venv\Scripts\python.exe`를 사용합니다. 공통 설치 목록인 `requirements.txt`와 `requirements-test.txt`에도 추가되어 있습니다.

`run.sh` / `run.cmd`로 로컬 앱을 실행하면 설치된 Ollama도 자동 시작합니다. 앱이 시작한 모델 서버는 앱 종료 시 함께 종료하며, 이미 실행 중인 모델 서버는 재사용하고 종료하지 않습니다. `--check-only`, 원격 실행, 읽기 전용 모드에서는 자동 시작하지 않습니다. 설치와 모델 다운로드는 자동으로 실행하지 않습니다.

`REQUIREMENTS_LLM_AUTOSTART=0` 또는 별도 `OCR_OLLAMA_URL`을 지정한 환경에서는 직접 모델 서버를 관리합니다. 수동 시작은 별도 터미널에서 다음 명령을 실행합니다.

```sh
.venv/bin/python scripts/local_ollama.py serve
```

Ollama가 공식 설치돼 있어야 하며, 기본 모델 `qwen3.5:4b`가 없는 환경에서만 실행 중인 모델 서버를 대상으로 다른 터미널에서 준비합니다.

```sh
.venv/bin/python scripts/local_ollama.py pull
```

`OCR_OLLAMA_URL` 기본값은 `http://127.0.0.1:11435`이며 숫자 loopback 주소만 허용합니다. `REQUIREMENTS_LLM_MODEL`로 모델명을 지정할 수 있습니다. 문서의 모든 페이지를 렌더링해 PaddleOCR로 읽고, Qwen3.5-4B에 페이지 PNG 이미지와 OCR 텍스트를 함께 전달합니다. 선택한 모델은 vision 기능이 있어야 하며 `/api/show`로 사전 확인합니다. `pull`도 `REQUIREMENTS_LLM_MODEL` 설정을 따릅니다. Paddle 환경과 탐지·인식 모델은 기존 포스터 검수 환경을 재사용합니다. 환경 변수는 서버 실행 전에 지정합니다. `.env.example`은 설정 예시이며 자동 로드를 보장하지 않습니다.

프런트엔드 변경 후 `cd frontend && npm run build`, 백엔드 변경 후 기존 서버를 재시작합니다. PDF 추출과 포스터 OCR의 모델 설정은 독립적이므로 `OCR_PIPELINE`을 변경할 필요는 없습니다.

## 처리 범위와 제한

- PDF의 모든 페이지를 PDFium으로 렌더링한 뒤 기존 `paddle_ocr.recognize_paddle()`로 읽습니다. 텍스트 PDF에 삽입된 스캔·이미지 영역도 같은 경로를 사용합니다. Paddle의 탐지·한국어 인식 모델, 격리 실행 환경, 출력 검증을 그대로 재사용합니다. OCR 좌표의 세로 간격과 가로 겹침으로 문단·열을 묶고, 짧은 표 행은 한 원문 구간에 유지합니다. 이는 일반적인 표의 정보 누락을 줄이기 위한 휴리스틱이며 병합 셀이나 복잡한 배치를 완전히 복원하는 표 인식기는 아닙니다. LLM에는 한 번에 1페이지의 이미지와 같은 페이지의 OCR 문맥을 보내 조건과 원문 구간 ID를 받습니다. 이미지와 OCR은 같은 최대 1800px 렌더링을 사용하며 작은 글자·문장부호를 확인할 수 있도록 보존합니다. ID가 있는 명시적 기준표를 발견하면 그 행과 해당 페이지 이미지를 먼저 모델에 전달합니다. `ID | 항목 | 판단 기준`처럼 수준 열이 없는 표도 지원합니다. 이어 표 밖의 제작 지시·표기 기준·허용 범위가 있는 페이지를 보완 추출합니다. 보완 호출에는 같은 페이지의 표와 지시문을 함께 전달해 기대값과 예외의 근거를 연결합니다. 예를 들어 7쪽 계약서에서 기준표가 4~6쪽에 있으면 7쪽 모두 OCR로 읽고 4~6쪽 이미지를 페이지별 3회에 나눠 Qwen에 전달합니다. 3페이지 동시 입력에서 세부 요구 문구 누락이 관찰되어 1페이지씩 추출하도록 조정했습니다. 표 밖의 제작 지시는 제한된 한국어 지시문·항목명 패턴으로 선택합니다. 선택한 문단의 근거가 최종 조건에서 빠지면 성공으로 반환하지 않습니다. 이는 누락 방지 검사이며 문서의 의미적 완전성을 보증하거나 계약 조항을 법률적으로 해석하는 기능은 아닙니다. 기준표가 없으면 전체 OCR 구간을 사용합니다. 각 배치는 자신의 페이지 조건만 추출합니다. 이미지에 없는 다른 페이지 OCR을 함께 넣었을 때 페이지 인용이 섞이는 문제가 관찰되어 같은 배치의 근거만 허용합니다. 같은 항목과 기대값은 공백 차이를 정규화해 병합하고, 보완 설명과 페이지별 `source_references`를 보존합니다. 구두점·OR 대안·서로 다른 값은 임의로 같다고 간주하지 않습니다. 명시된 수준이나 유형이 실제로 다르면 오류로 남겨 확인하게 하며, 설명을 병합했다고 상충이 해소됐다는 뜻은 아닙니다. Qwen의 thinking을 끄고 JSON 스키마와 Pydantic 검사를 적용합니다. 이후 배치가 실패하면 앞선 결과도 성공으로 반환하지 않습니다. 명시적 기준표를 사용하는 경우 선택한 모든 행 ID의 추출 여부를 검사하고 누락 시 오류를 반환합니다. 모델이 머리말 ID를 반복 인용하는 문제에 대응해 label·requirement·inspection과 후보 OCR 구간의 문자 2-gram 겹침을 대조해 출처를 재연결합니다. 연결 근거가 부족하면 오류를 반환하며, `source_alignment`에 원래 모델 ID와 재연결 여부를 남깁니다. `overlap_ratio`는 문자 겹침 비율이며 정확도·신뢰도 확률이 아닙니다. 서버가 해당 OCR 판독문과 페이지를 붙이며 OCR 문구·점수·좌표도 API 응답의 `ocr.pages`에 보존합니다. 좌표는 렌더링한 페이지 이미지의 픽셀 기준입니다.
- Paddle 준비 실패·시간 초과·인식 오류는 문서 추출 실패로 반환합니다. LLM 이미지 읽기로 자동 우회하지 않습니다. 빈 문서나 판독 문구가 없는 문서도 오류로 안내합니다.
- 문서 분석 전에 요구조건 모델의 연결 및 설치 여부를 확인합니다. 모델 서버 중지·모델 미설치·vision 미지원을 구분해 안내하므로 모델이 없는 상태에서 긴 OCR 작업을 먼저 실행하지 않습니다.
- PDF 처리와 기존 포스터 검수는 같은 추론 잠금을 사용합니다. 포스터 검수 중인 PDF 요청은 재시도를 안내하고, PDF 처리 중 접수된 포스터 검수는 기존 대기열에서 기다립니다.
- 문서는 로컬 모델에만 전달합니다. PDF와 렌더링 이미지는 임시 처리하며 영구 저장하지 않습니다. 확정한 항목의 원문 출처는 기존 검수 스냅샷에 포함됩니다.
- 문서 분석은 최대 600초, 격리 프로세스는 정리 시간을 포함해 최대 610초, 각 Paddle 작업은 남은 시간 내 최대 240초 실행 제한을 두며, 이 API는 한 번에 문서 1개만 분석합니다. 화면의 **입력 반영 취소**는 응답 반영을 취소합니다. 화면의 응답 대기 제한은 630초입니다. 이미 시작한 서버 작업은 제한 시간까지 계속될 수 있으며 그동안 새 요청은 잠시 후 재시도를 안내합니다.
- 모델 출력은 초안입니다. 숫자·일정·필수/권장·예외·누락을 원본과 비교해야 합니다. 응답의 `conditions`는 표시용 `text`와 함께 `label`, `requirement`, `level`, `inspection`, `type`, `source_id`, `page`, `source`, `source_kind`, `approval_status: pending`을 보존합니다. `source_kind: pdf_page+paddleocr`는 이미지와 OCR을 함께 해석했다는 뜻이며, `source` 자체는 교정하지 않은 OCR 판독문입니다. 이미지로 교정된 조건과 OCR 문구가 다를 수 있습니다. 원문 구간 ID 검증이 추출 의미의 정확성이나 조건의 완전성을 보증하지 않습니다. 복잡한 표·혼합 스캔 문서는 특히 검토가 필요합니다.
- 날짜·시간·장소·출연진·파일 규격 등 명확한 항목명은 `information`으로 보정하고 모델의 원래 분류는 `model_type`에 남깁니다. 판단 설명에 ‘이미지’나 ‘가독성’이 있다는 이유로 해당 정보 조건 전체를 시각 조건으로 보내지 않습니다. 확인 화면에서는 사용자가 유형을 변경할 수 있습니다.
- 확정 스냅샷의 `document_condition`에는 항목명·기대값·필수 수준·판단 설명을 분리해 보존합니다. `requirements`와 조건의 `text`에는 기대값만 표시하고 `[필수]`나 `/ 판단 기준: …`를 붙이지 않습니다. 검수 및 결과 화면에서 상세 기준을 펼쳐 예외를 확인할 수 있습니다. 문구를 편집하면 이전 구조를 제거하며, 서버도 구조와 표시 문구의 불일치를 거부합니다. 설명을 포함한 이전 표시 형식의 확정 기록도 읽을 수 있습니다. 같은 짧은 조건의 빈 설명·보완 설명은 병합하고, 합친 설명은 최대 1,200자까지 확정 구조에 보존합니다. 문서에 없는 모델의 필수 수준 추정은 `명시 없음`으로 되돌리며 원래 값은 참조에 남깁니다. 날짜 예외에 섞인 캠페인 문구나 폭 조건에 섞인 비율 허용 오차는 명확히 연결되는 해당 항목으로 이동합니다. 병합한 OCR 원문 목록은 `document_condition.sources`로 확정·내보내기에 남기고 상세 기준에서 볼 수 있습니다. 이전 검수 기록은 자동 변경하지 않으므로 수정된 추출을 사용하려면 PDF를 다시 읽고 기준을 확정해 새 검수를 실행합니다.
- 문서의 기대 문구는 OCR 근거와 대조하며, 날짜별 출연진은 같은 열 위쪽의 가장 가까운 날짜를 함께 확인합니다. 가까운 박스의 공백·줄바꿈과 문서에서 명시적으로 허용한 `x/×`·대소문자 차이를 제한적으로 정규화합니다. 원본에 없는 연도를 PDF에서 가져와 채우지 않고, 낮은 인식 점수·문구 누락·추가 시각 조건은 확인 대상으로 남깁니다.
- PDF 구조 정보가 없는 `항목: 기대값` 입력도 같은 장소 조각·출연진·파일 측정값 비교를 사용합니다. 출연진의 `x/×`는 협연 구분자로 정규화하고, `18일 출연진`처럼 일자가 있으면 같은 열의 가장 가까운 날짜와 대조합니다. 같은 일이 여러 월에 있으면 보류합니다. 원문 출처 문자열이 남아 있어도 누락된 필수 수준·예외를 임의로 복원하지 않습니다. 설명·OR 대안이 붙은 문장은 기존 해석 경로에 남기며, 이미 확정된 날짜 정규화·가격 근거는 보존합니다.
- 지원하는 명시적 픽셀 규격과 정적 파일 형식·확장자·원본 색상 모드·프레임 수는 업로드 원본 측정값과 비교합니다. 단순한 복합 파일 규격은 비율·최소 폭·파일 형식·색상 모드로 나눕니다. 비율의 권장 수준과 명시된 ±픽셀 오차를 다른 속성에 전파하지 않습니다. 분리한 비율(명시 오차 포함)·최소 폭·단독 형식·색상 모드도 파일 측정값으로 비교합니다. OR·조건부·알 수 없는 추가 사양이 있는 복합 규격은 보수적으로 한 조건으로 유지합니다. 선택 제출 원본은 필수 미충족으로 처리하지 않습니다. 임의의 복합 문장·대안 조건·가격 불일치·시각 조건을 모두 자동 판정하는 기능은 아닙니다. 로컬 Qwen PDF 추출과 포스터 시각 모델 연결은 별개이며, 시각 모델이 미연결이면 로고·배경·장식·가독성은 확인 대상으로 남습니다. PDF 조건 추출 성공과 검수 통과는 별개입니다.

회귀 테스트에는 보완 설명·다중 페이지 출처의 보존, 진짜 수준 충돌, 선택 문단 누락 실패, OR/문장부호 보존, 혼합 규격 분리와 허용 오차의 적용 범위, API 확정 구조와 프런트엔드 전달을 포함합니다. 모의 추론 테스트와 실제 모델 실행 결과를 구분해야 합니다.

## 2026-10-29 카드형 명세서와 공통 규칙 수정

`document_sources.py`에서 OCR 문단을 조건, 공통 규칙, 확인 메모, 출처/작성 설명, 검토 절차와 제목으로 구분합니다. 표 행 외에 `NEW103-C01 | 행사명`과 아래 조건 문장이 분리된 카드, OCR 열 정렬 때문에 `항목명 ID 조건 문장`이 한 문단이 된 카드도 같은 조건 근거로 묶습니다. 원문은 교정하지 않고 카드 문단 사이에 줄바꿈만 넣습니다. 실제 텍스트는 기존 350자 겹침 구간으로 보존합니다.

- 절 제목의 명시적 필수·권장·선택 수준은 그 절의 카드에 연결하고 제목 원문도 별도 출처로 보존합니다. 수준 열이 없는 파일 기준에 앞 절의 필수 수준을 이어붙이지 않습니다.
- `문구 판정`/`문구 비교 원칙`은 같은 페이지의 관련 정보 조건 상세 기준과 출처에 연결합니다. 독립 조건이 없다는 이유로 전체 추출을 실패시키지 않습니다. 파일 규격이나 시각 항목에 문구 비교 규칙을 일괄 적용하지 않습니다.
- `확인 필요:` 메모는 `document_notes`로 보존합니다. 충돌 메모는 화면의 완료 안내에도 표시하며, 메모에서 다른 회차나 제목을 새 조건으로 만들지 않습니다. 실제 조건 근거보다 메모/규칙에만 연결되는 모델 출력은 해당 문맥으로 분리합니다. 어디에도 근거가 없는 출력은 계속 오류로 처리합니다.
- 출처·역작성 설명을 보완 조건으로 선택하지 않습니다. 보완 호출은 같은 페이지의 실제 조건을 함께 제공하고, 공통 규칙/메모는 조건 source ID와 구분해 전달합니다.
- 긴 조건 ID도 전체 항목 추출 여부를 검사합니다. 카드 본문 연결 실패, 실제 ID 누락, 실제 표 밖 지시 누락, 수준 충돌은 성공으로 숨기지 않습니다.
- 전시명·행사 제목·시작일·종료일·기념식/박람회 시간·참여 대상·참가비·원본 가로·세로를 정보 비교에 연결합니다. 시작/종료와 세부 행사 시간의 라벨은 표시에서도 유지합니다. 카드의 단독 JPEG와 명시적 가로/세로 픽셀 값은 파일 메타데이터 비교 형식으로 정리합니다.

실제 실패 문서의 OCR 문단은 `backend/tests/fixtures/pdf_format_ocr.json`에 회귀 사례로 보존했습니다. 이는 사람 승인 정답이나 일반 정확도 평가 데이터가 아닙니다. 원본 PDF와 기존 검수 기록은 변경하지 않습니다. 실모델 결과는 `output/pdf-format-fix-2026-10-29/`의 원시 응답·모델/코드 해시·문서별 검증 기록에서 확인합니다.
