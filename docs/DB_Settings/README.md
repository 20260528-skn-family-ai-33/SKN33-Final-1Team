# DB 설계·검증 자료 안내

설계 내용과 실행 방법은 [DB 통합 설계서](DB_통합설계서.html)에서 확인합니다. 단계별로 나뉘었던 Markdown 38개를 주제별 본문·테이블 사전·검색 가능한 원문으로 모았습니다. 원문마다 **Markdown 내려받기** 버튼이 있으며, 정리 전 파일의 SHA256과 동일한 내용을 제공합니다.

빠른 실행은 [간단 가이드](../html/크리에이티브체커_간단가이드.html), 설정·명령의 자세한 설명은 [상세 실행 가이드](../html/크리에이티브체커_상세명세_실행가이드.html)를 사용합니다.

```text
DB_Settings/
├── README.md                  # 자료 위치와 보존 기준
├── DB_통합설계서.html           # 설계·구현·검증 대응표와 원문 38개
├── contracts/                 # JSON 예제·해시·저장 계약·구현 계획
│   └── schema/                # 스키마 테스트가 읽는 설계 기준 6개
└── verification/
    ├── reports/               # 날짜별 검증 보고서 23개
    └── artifacts/             # C11~C15 화면·실측 증거 12개
```

## 정리 기준

| 자료 | 처리 | 보존 이유 |
|---|---|---|
| 단계별 Markdown 32개 | 개별 파일을 없애고 통합 HTML에 수록 | 설계·구현·검증 대응표를 한곳에서 읽기 |
| 물리 설계 Markdown 6개 | `contracts/schema/`로 이동 | 테스트가 컬럼·FK·인덱스·가드·권한의 독립 기준으로 읽음 |
| 계약 JSON 4개 | `contracts/`에 유지 | API 예제·해시 벡터·저장 사례·구현 계획의 구조화 자료 |
| 검증 보고서 JSON 23개 | `verification/reports/`로 이동 | 실행 당시의 결과·조건·소스 해시 기록 |
| 화면·실측 증거 12개 | `verification/artifacts/C11~C15/`로 이동 | 보고서와 함께 확인하는 실제 화면·실행 증거 |

테스트용 설계 기준 6개는 통합 HTML과 일부 내용이 겹쳐도 유지합니다. 구현 코드에서 기대값을 다시 만드는 대신, 별도로 검토한 설계와 실제 스키마가 일치하는지 확인하는 자료입니다. 이 파일들은 작성 당시의 설계이며, 현재 구현 상태는 통합 본문을 먼저 확인합니다.

## 과거 기록의 경로와 해시

검증 JSON·화면·실측 증거와 기존 계약 JSON은 **내용을 수정하지 않고 이동하거나 유지**했습니다. 보고서 안의 경로와 해시는 검증 당시를 가리킵니다. 문서 정리를 새 검증 실행으로 표시하지 않습니다.

- `verification/날짜별보고서.json` → `verification/reports/날짜별보고서.json`
- `verification/C11~C15/파일` → `verification/artifacts/C11~C15/파일`
- 최상위 `물리설계_*.md` 중 테스트 기준 6개 → `contracts/schema/`의 같은 이름
- 그 밖의 단계별 Markdown → 통합 HTML의 **단계별 원문** 영역

HTML의 원문 내려받기는 정리 전 바이트를 보존하므로, 내려받은 원문 안의 링크도 당시 경로입니다. 현재 위치로 연결되는 링크는 HTML 화면에서 사용합니다. 테스트 기준 6개의 링크는 이동 위치에 맞췄으며, 설계 본문과 계약 표는 유지했습니다. HTML 내 `coverage` 데이터에는 원문 해시와 파일 이동표도 포함되어 있습니다.

## 검증 범위

C01~C15의 로컬 구현·격리 검증과 배포 전환 자료를 기록합니다. C15 Linux 리허설은 합성 OCR worker를 사용했습니다. 실제 Linux Paddle 모델 실행·일상 DB 전환·운영 공개·원격 GitHub Actions 성공까지 완료했다는 의미는 아닙니다. 각 보고서의 실행 조건과 미검증 항목을 함께 확인합니다.
