## 2. 이번에 강제하는 조건

- 규격의 확보 상태와 사용 범위를 분리한다. available은 검증 파일과 SHA256이 필요하고 service_shared는 available이어야 한다. 설명 문서만으로 검증 가능 상태를 만들지 않는다. 실제 파일 존재·역할·스키마 로딩은 후속 교차 검사다.
- 인계 지문과 지문 규격은 함께 있거나 모두 NULL이다. completed는 manifest·지문·규격·로컬 검사 기록·matched를 요구한다. 지문이 없는 여러 접수는 UNIQUE로 합치지 않으며 지문 중복은 같은 프로젝트·namespace 안에서만 거부한다. 실제 파일·제공자 해시 대조 완료를 DB 행만으로 증명하지 않는다.
- 감사 주체는 user/developer/system이다. user는 실제 사용자 ID가 필요하고 system은 사용자 ID가 NULL이다. developer의 과거 미확인 매핑은 NULL을 허용한다. 감사의 추가 전용 권한은 M008에서 완성한다.
- OCR은 시도 또는 인계 출처가 필요하다. completed는 시도·입력/원문 파일·시작/종료 시각, failed는 종료 시각·오류, imported는 원문 파일과 NULL 로컬 시작/종료 시각을 요구한다. 봉인 시각이 있으면 terminal 상태여야 한다. 커밋 시 봉인 필수·봉인 후 자식 추가 금지는 M007이다.
- 문자열 ID와 정수 ID를 구분해 정수 1과 문자열 "1"을 보존한다. 정수 투영은 0 또는 부호 있는 정규 십진 문자열이며 +1·01·-0·소수·지수·공백 표현을 거부한다. 정수 범위를 BIGINT로 좁히거나 원문 ID를 잘라 저장하지 않는다.
- confidence는 NULL 또는 0~1의 DOUBLE PRECISION이며 NaN·무한대·범위 초과를 거부한다. 소수 여섯 자리로 반올림하지 않는다. requires_review의 미제공 NULL을 false로 바꾸지 않는다.
- bbox는 숫자 4개와 양의 폭·높이, 비음수 시작 좌표를 요구한다. polygon은 숫자 쌍 최소 3개다. 타입·길이를 CASE로 확인한 뒤 숫자를 비교해 잘못된 JSON을 변환 오류 대신 CHECK 위반으로 거부한다. JSON path는 strict로 배열 자동 풀림을 막는다. 실제 프레임 범위는 M007이다. [PostgreSQL JSON 함수](https://www.postgresql.org/docs/17/functions-json.html)
- 추출본은 버전·방법·투영 버전·호환/검사 상태를 검사한다. valid는 스키마 ID와 검사 기록을 요구한다. 부분 날짜는 미확인 요소를 NULL로 보존하고 DATE가 있으면 유한 날짜와 모든 구성요소의 일치를 검사한다. 종료가 시작보다 앞선 원문은 보존한다.
- 관찰의 resolved는 present와 SQL/JSON null이 아닌 값을 요구하고 absent는 SQL NULL만 허용한다. 미확인 상태를 absent로 승격하지 않는다. False·0·빈 문자열·빈 배열·객체 등 실제 값은 상태와 함께 보존한다.
- 근거는 관찰/항목 결과 중 정확히 하나를 소유자로 가진다. OCR은 OCR 실행, 이미지는 파일·프레임, 문서는 파일·위치가 필요하다. 문서 위치는 비어 있지 않은 pointer·양수 page·비어 있지 않은 locator 객체 중 하나다. 좌표가 있으면 프레임이 필요하다. 실제 토큰 연결 완결성과 소유자 입력 일치는 후속 검사다.
- 선택 JSON의 Python None은 SQL NULL로 저장한다. 객체·좌표 컬럼의 JSON null은 거부하며, 가변 normalized_value에는 JSON.NULL로 명시한 JSON null을 미확인 상태에서 보존할 수 있다. 필수 원문·payload의 SQL NULL은 거부한다. [SQLAlchemy JSON NULL 구분](https://docs.sqlalchemy.org/en/21/core/type_basics.html#sqlalchemy.types.JSON)

이 조건들은 한 행의 구조·상태를 검사한다. 실제 OCR 실행·외부 규격 검증·사람 승인·파일 내용 일치를 수행한 것으로 표시하지 않는다.

## 3. 적용과 실행 경계

M001·M002 revision 소스는 바꾸지 않았다. C03의 테스트는 M002에서 구현된 9개 metadata로 범위를 고정해 이후 head가 추가돼도 같은 회귀를 검증한다. 새 패키지와 owner/app 설정 변경은 없다.

```bash
.venv/bin/python -m alembic -c backend/migrations/alembic.ini heads

# 검토용 증분 SQL만 생성. DB 접속·적용 없음.
CC_MIGRATION_ENV_FILE=.env.owner-test .venv/bin/python -m alembic -c backend/migrations/alembic.ini upgrade M002:M003 --sql

# 명시한 격리 DB에만 적용. 일상 DB에는 아직 실행하지 않는다.
CC_MIGRATION_ENV_FILE=.env.owner-test .venv/bin/python -m alembic -c backend/migrations/alembic.ini upgrade M003
```

owner 파일과 테스트 설정은 [C02 실행 방법](구현_C02_Alembic과사용자스키마.md#3-명시적-실행-방법)·[C01 테스트 설정](구현_C01_DB연결과트랜잭션.md#4-전용-postgresql-테스트-실행)을 따른다. 위 파일명은 사용자가 준비할 명시 설정의 예시이며 저장소에 자격증명 파일을 생성하지 않았다. 일반 앱·launcher에서 자동 upgrade하지 않는다. 현재 head M003은 완성된 M008 스키마가 아니므로 v1 쓰기를 공개할 수 없다. 파괴적 downgrade와 기존 대상 객체의 자동 채택·덮어쓰기는 거부한다.

## 4. 실제 검증 결과

```bash
.venv/bin/python -m pytest -q
TEST_DB_ENV_FILE=.env.db-test .venv/bin/python -m pytest -m db_integration -q
```

- 기본 Python **413 passed**, 추가 subtest 7 passed. DB 통합 361개는 기본 실행에서 제외했다. 신규 C04 정적 사례는 5개다.
- 실제 PostgreSQL **361 passed**: 기존 C01~C03/전체 적용 회귀 111개와 신규 C04 사례 250개다. macOS Python 3.12.14·기존 PostgreSQL 17.11을 사용했다.
- 이번 실제 실행은 기존 역할 값을 명시적인 TEST_DB_* 자식 프로세스 환경으로 전달했다. 비밀은 명령행·출력·검증 JSON에 기록하지 않았고 업무 DB명을 테스트 fixture에 전달하지 않았다. fixture의 자동 일반 DB 설정 복사·기본 DB fallback은 없다.
- M002→M003의 18개 테이블·236개 컬럼을 실제 inventory와 metadata로 대조했다. 자료형·NULL/default·PK/UQ 컬럼 순서·CHECK 이름·코멘트와 신규 9개 빈 테이블을 확인했고 기존 M001 사용자·프로젝트와 M002 파일 테스트 행을 보존했다.
- 신규 CHECK 28개 묶음 모두에 대해 잘못된 행을 실제 DB가 거부했다. 완료 상태의 필수값을 하나씩 NULL로 만드는 경우도 검증했다. 원문 ID 타입, 부분 날짜·역전 날짜, float 정밀도, SQL/JSON NULL, 출처별 필수값과 중복 키를 확인했다.
- 기존 evidence_records 충돌 시 앞서 생성한 M003 테이블도 롤백되고 기존 객체/내용을 보존했다. M003 끝의 오류 주입은 M002의 객체 OID·데이터·버전·기본 ACL을 보존했다. 빈 DB→M001→M002→M003 전체 실패도 DDL·버전·기본 ACL을 함께 롤백했다.
- app의 새 테이블 권한 없음과 실제 SELECT 거부, 같은 revision 재실행, 파괴적 downgrade 거부를 확인했다. 테스트 전후 일상 DB의 public 관계·기본 ACL이 같았고 생성한 임시 DB를 모두 정리했다.
- pip check·구문 검사·과거 revision/기존 기능 소스 지문·문서 링크 검사를 통과했다. 기존 API·admin/admin·React·OCR·launcher는 변경하지 않았다.

실행 결과와 파일 지문은 [C04 검증 기록](verification/2026-10-17-implementation-C04.json)에 저장한다. Linux/Windows·실제 OCR/브라우저·네트워크 COMMIT 장애·파일 내구성·외부 규격·백업 복원 검증은 이번에 실행하지 않았다.
