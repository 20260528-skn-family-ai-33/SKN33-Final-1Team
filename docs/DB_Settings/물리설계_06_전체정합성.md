# PostgreSQL 물리 설계 6단계 — 전체 정합성

작성일: 2026-10-16

상태: **물리 설계 세부 6단계 검토 완료.** 첫 구축 범위 26개 테이블의 키·프로젝트 경계·단일 행 제약·인덱스·불변성·권한 책임을 정리한다. 이번 산출물은 문서이며 실제 SQL·ORM·마이그레이션·DB 권한·인증 코드에는 적용하지 않았다. 인증·API·화면/JSON은 7·8단계, 파일 저장과 전환은 [9단계](추가설계_09_저장과이전복구.md)에서 보강했다. 구현 구성·도구·검증 단위는 [10단계](추가설계_10_구현구조와검증명세.md)에서 확정했다.

## 1. 기준 문서와 검토 범위

영역별 컬럼은 [2단계](물리설계_02_사용자와파일.md), [3단계](물리설계_03_규격과OCR근거.md), [4단계](물리설계_04_검수기준.md), [5단계](물리설계_05_검수실행과결과.md)를 따른다. 이름이 있는 PK·UNIQUE·FK·CHECK·조회 인덱스의 목록은 [제약·인덱스 목록](물리설계_06_제약목록.md)에 모았다. 현재 구현과 목표는 [프로젝트 명세](../project-specification.md)로 구분한다.

| 항목 | 이번 설계의 기준 |
|---|---|
| 테이블 | 첫 범위 26개. 후속 21개는 추가하지 않음 |
| 컬럼 | 395개. 6단계의 access_scope·sealed_at 추가와 7단계의 users.account_kind 1개 반영 |
| PK | 26개. 단일 UUID 23개, 복합 PK 3개 |
| UNIQUE | 41개. 부분 유일 인덱스와 별도로 집계 |
| FK | 81개. 프로젝트·이미지 문맥을 포함한 최종 설계 관계 |
| 삭제·키 변경 | 모든 FK는 `ON DELETE RESTRICT`, `ON UPDATE RESTRICT`, 즉시 검사 |
| UUID·시각 | 앱 발급 UUID v4, UTC TIMESTAMPTZ. 원래 외부 ID·시각은 별도 보존 |
| 실제 적용 | 업무 테이블 생성·SQL 실행·DB 테스트를 수행한 상태가 아님 |

1단계의 81개는 **기존 ERD에서 첫 범위가 출발점인 FK 분류 수**이고, 이번 81개는 제외·추가·복합화 후의 실제 설계 수다. 우연히 수가 같을 뿐 같은 목록이 아니다. 기존 범위 내 관계 70개 중 68개는 직접/복합 FK로 유지하고, 채택→실행·기준 항목의 2개는 채택→결과의 문맥 FK와 결과의 FK를 통해 보장한다. 여기에 새 참조 13개를 추가했고 후속 대상 11개는 제외했다. 전체 47개 ERD 가져오기용 SQL을 이 문서의 운영용 스키마로 취급하지 않는다.

## 2. 관계·자료형·NULL 정책

### 프로젝트와 이미지 경계

`users`, `user_sessions`, `schema_definitions`는 전역이며 나머지 23개는 `project_id`가 필수다. 프로젝트 소속 테이블은 직접 FK 또는 상위 자료·실행의 복합 FK를 통해 프로젝트에 연결한다. 중복된 `project_id`를 단순 표시용 값으로 두지 않는다.

| 연결 | DB가 보장하는 문맥 | 추가 검사 |
|---|---|---|
| 자료 → 자료 버전 → 파일 | 자료·원본/표시 파일의 프로젝트 일치 | 실제 바이트·역할·해시·치수의 일치 |
| 좌표 프레임 → 자료 버전·파일·부모 | 프로젝트·이미지 버전 일치 | 실제 기준 파일·행렬·치수·방향의 대응 |
| OCR → 시도·프레임 | 프로젝트·이미지 버전 일치 | 같은 실행의 현재 시도인지, 좌표계 이름·파일이 맞는지 |
| 기준 버전 → 묶음·초안·이미지 | 프로젝트·묶음·대상 이미지 일치 | 확정 상태·초안 revision·복사본·해시 일치 |
| 실행 → 기준 버전 | 프로젝트·대상 이미지 일치 | 현재 권한·로컬 확정 상태·접수 설정 |
| 결과 → 실행·시도·기준 항목 | 프로젝트·이미지·실행·기준 버전·항목 일치 | OCR이 같은 시도에 속하고 추출본이 같은 OCR을 사용했는지 |
| 근거 → 관찰 또는 결과·프레임·OCR | 프로젝트·이미지 일치 | 소유 결과/관찰의 실제 입력 OCR과 출처 일치 |
| 근거 문구 연결 | 근거·토큰이 같은 프로젝트·이미지·OCR에 속함 | 실제 원문 ID·순서·누락 검증 |
| 최종 채택 → 결과 | 실행·이미지·기준 버전·항목·결과 일치 | 모든 항목 존재·채택 시도 동일·동결 상태 |

전역 규격에서 파일을 참조하는 2개 FK만 의도적인 프로젝트 경계 예외다. 범위와 사용 권한은 7절을 따른다. 사용자 UUID FK는 이력의 사용자 존재만 보장한다. 현재 프로젝트 멤버십·역할·활성 상태를 보장하지 않으며 매 요청에서 확인한다.

### 선택 FK와 유일 키

선택 FK는 기본 `MATCH SIMPLE`을 사용한다. 선택 대상 ID가 NULL이면 그 복합 FK는 검사하지 않으므로 프로젝트·이미지 등 문맥 컬럼은 항상 NOT NULL로 유지한다. 대상 ID를 제공한 경우에는 전체 문맥과 존재를 검사한다. 부모가 없는 상태를 만들기 위해 프로젝트 ID를 NULL로 바꾸지 않는다.

일반 UNIQUE는 NULL을 서로 다른 값으로 취급한다. 수입에 키가 없는 행이나 외부 항목 ID가 없는 복수 항목을 허용한다. 예외인 `record_aliases`의 외부 별칭 키에는 `NULLS NOT DISTINCT`를 사용해 인계 묶음 없는 같은 별칭의 중복도 거부한다. 기준 확정·서비스 실행의 멱등 컬럼은 출처별 CHECK로 모두 채우도록 하여 NULL로 중복 검사를 우회하지 못하게 한다. [PostgreSQL 제약 조건](https://www.postgresql.org/docs/17/ddl-constraints.html)

복합 FK의 대상에는 해당 컬럼 묶음의 UNIQUE를 실제로 둔다. UUID 단독 PK가 있다는 이유만으로 문맥 복합 UNIQUE를 삭제하지 않는다. `criteria_items.rule_code`·파일 해시·프로젝트명·이미지/기준 조합에는 UNIQUE를 추가하지 않는다.

## 3. 단일 행 CHECK의 공통 규칙

제약의 구체적인 이름·대상 컬럼은 제약 목록을 따른다. 여기서는 조건의 의미를 확정한다. CHECK가 NULL로 평가되면 통과할 수 있으므로 조건부 필수값에는 `IS NOT NULL` 검사를 명시한다. 여러 행이나 파일 내용은 CHECK에서 조회하지 않는다.

| 공통 규칙 | 조건 |
|---|---|
| 해시 | 모든 SHA256 투영 컬럼은 NULL 또는 소문자 16진수 64자리. 세션 token_hash는 NOT NULL |
| 시각 | 제공한 TIMESTAMPTZ는 유한값. updated_at ≥ created_at, 알려진 종료 ≥ 시작. 만료 여부 자체를 시간 의존 CHECK로 만들지 않음 |
| JSON 객체 | 설정·메타데이터·원문 레코드·payload·스냅샷·위치 정보는 NULL 또는 객체. 필수 JSON 컬럼의 SQL NULL은 허용하지 않음 |
| JSON 배열 | use_channels는 문자열 배열, 초안 항목·출처 문서는 배열. 항목별 필드 제한은 API/JSON 계약에서 보강 |
| 가변 JSON 값 | expected_value·normalized_value·observed_value는 스칼라·배열·객체를 허용. source_version_jsonb도 과거 버전의 원래 값·타입을 보존하므로 객체로 한정하지 않음. SQL NULL과 JSON null의 원래 차이는 원문에 보존 |
| 한계·후속 조치 | limitations_jsonb·next_action_jsonb는 NULL 또는 객체/배열. 임의 문자열은 원문에 보존하고 정규 투영은 별도 처리 |
| 좌표 | bbox는 숫자 4개, 0 ≤ x1 < x2·0 ≤ y1 < y2. polygon은 유한 수치 쌍 최소 3개. 실제 프레임 범위는 교차 행 검사 |
| confidence | NULL 또는 유한값이며 0~1. NaN·양/음의 무한대·범위 초과 거부. 미제공을 0으로 만들지 않음 |
| 부분 날짜 | 연도 1~9999, 월 1~12, 일 1~31 또는 NULL. DATE 투영은 구성요소가 모두 있고 실제 유효 날짜와 일치할 때만 제공 |
| 자기 참조 | 자기 자신의 ID를 부모·선행·재검수 원본으로 지정할 수 없음. 긴 순환은 별도 트랜잭션 검사 |

JSON 함수의 입력 타입·배열 길이를 먼저 확인하고 조건부 분기로 수치를 비교한다. 잘못된 JSON 타입에 숫자 변환부터 적용해 오류로 빠지는 구현을 피한다. JSON Schema가 없는데 전체 payload의 표준 준수까지 DB가 검증한 것으로 표현하지 않는다.

## 4. 26개 테이블별 CHECK 계약

| 테이블 | 단일 행에서 강제할 조건 |
|---|---|
| `users` | account_kind는 email/developer. email 종류는 email·password_hash 모두 IS NOT NULL·비어 있지 않음, email은 앞뒤 공백 없는 소문자. developer는 둘 다 IS NULL. display_name 비어 있지 않음. 정식 이메일의 실제 형식은 인증 계층에서도 검증 |
| `user_sessions` | expires_at > created_at. revoked_at은 NULL 또는 created_at 이후. 토큰 해시는 공통 형식 |
| `projects` | name 비어 있지 않음. business_state는 active/archived. archived일 때만 archived_at 필수. use_channels는 문자열 배열 |
| `project_members` | role은 owner/editor/viewer. 활성 owner가 적어도 하나인지는 단일 행 CHECK로 처리하지 않음 |
| `assets` | 첫 asset_kind는 poster_image. name 비어 있지 않음. parent_asset_id ≠ asset_id |
| `asset_versions` | version_no ≥ 1, 네 이미지 치수 > 0. 첫 verification_state는 unverified. 바이트 디코딩을 사람 확인으로 승격하지 않음 |
| `stored_files` | storage_backend=local. file_role은 original_image/display_image/ocr_input/source_json/import_manifest/schema_specification/validation_schema. state는 stored/missing. storage_key 비어 있지 않음, byte_size ≥ 0. 이미지 역할이면 byte_size > 0·detected_mime 필수. parent_file_id ≠ file_id |
| `image_coordinate_frames` | frame_kind는 original/display/ocr_input/crop, coordinate_space 비어 있지 않음, width/height > 0, 첫 verification_state=unverified. parent_frame_id와 transform_jsonb는 둘 다 NULL 또는 둘 다 제공. 부모는 자기 자신이 아님 |
| `record_aliases` | namespace·external_record_id 비어 있지 않음. 길이 초과를 잘라 저장하지 않음 |
| `schema_definitions` | 이름·버전 비어 있지 않음. availability_state는 metadata_only/available, access_scope는 metadata_only/service_shared. available이면 검증 파일·schema_sha256 필수. 해시가 있으면 검증 파일도 필요. service_shared이면 available 필수 |
| `import_packages` | 출처 namespace 비어 있지 않음. hash_check_state는 not_checked/matched/mismatch, import_state는 received/completed/needs_review/failed. 지문과 규격 버전은 함께 제공. completed이면 manifest·지문·규격·local_validation_jsonb 필수이고 hash_check_state=matched. replaces_import_id ≠ import_id |
| `audit_events` | actor_kind는 user/developer/system. user이면 actor_user_id 필수, system이면 NULL. developer의 미확인 과거 매핑은 NULL 가능. action·target_type 비어 있지 않음 |
| `ocr_runs` | 처리 상태는 queued/running/completed/failed/imported. attempt_id 또는 import_package_id 중 하나 이상 필요. coordinate_space 비어 있지 않음. completed는 시도·입력/원문 파일·시작/종료 시각 필수. failed는 종료 시각·오류 필수. imported는 원문 파일 필수이며 로컬 시작/종료 시각은 NULL. sealed_at은 생성 중에만 NULL이며 커밋 시 terminal 상태와 함께 필수 |
| `ocr_tokens` | external_token_type은 string/integer, external_token_id 비어 있지 않음, token_order ≥ 0. integer ID는 정수의 문자열 표현인지 검증. source_record_jsonb는 객체. 점수·좌표는 공통 규칙 |
| `poster_extractions` | version_no ≥ 1, method·projection_version 비어 있지 않음. compatibility_state는 native/legacy/pending_enrichment, validation_state는 unchecked/valid/invalid/schema_unavailable. valid이면 schema_id·checks_jsonb 필수. predecessor_id ≠ extraction_id. 날짜는 공통 규칙 |
| `poster_field_observations` | field_code·field_path·adapter_version 비어 있지 않음. presence는 present/illegible/absent/not_checked, resolution은 resolved/review_needed/unprocessed. resolved는 present이고 normalized_value가 SQL/JSON null이 아니어야 함. absent의 normalized_value는 SQL NULL |
| `evidence_records` | observation_id와 item_result_id 중 정확히 하나. source_kind는 ocr/image/document, method_code 비어 있지 않음. OCR은 source_ocr_run_id 필수, 이미지는 source_file_id·frame_id 필수, 문서는 source_file_id와 위치 정보 필수. 좌표가 있으면 frame_id 필수, page_no는 NULL 또는 ≥ 1 |
| `evidence_ocr_tokens` | token_order ≥ 0. ID들은 전부 NOT NULL이며 같은 근거·토큰 중복은 PK로 거부 |
| `criteria_sets` | name 비어 있지 않음. 과거 등록자를 모르면 created_by=NULL을 허용 |
| `criteria_drafts` | revision ≥ 1, state는 editing/archived. items_jsonb는 배열이며 처음에는 빈 배열 가능. 초안 안의 ID 유일성·선택 항목 검증은 확정 트랜잭션 책임 |
| `criteria_versions` | version_no ≥ 1, source_draft_revision은 NULL 또는 ≥ 1. hash_version 비어 있지 않음. origin·확정 상태·조건부 필수값은 아래 생성 경로 규칙 적용. source_criteria_version_id ≠ criteria_version_id |
| `criteria_items` | position ≥ 1, category는 information/visual/unknown, text 비어 있지 않음. external_item_id가 있으면 비어 있지 않음. is_required=NULL 허용. expected_value에 정답을 추정해 채우지 않음 |
| `review_runs` | origin·executor·모드·처리 상태·현재 단계·포인터·시각은 아래 수명 규칙. progress는 NULL 또는 0~100, verdict는 NULL 또는 pass/fail/review. retry_of가 있으면 retry_review, 없으면 create_review인 서비스 요청. 자기 재검수 금지 |
| `review_attempts` | attempt_no ≥ 1. 상태는 active/succeeded/failed/unknown/imported. dispatch_state는 NULL 또는 not_dispatched/dispatching/submitted/unknown. active는 시작 시각·토큰 필수, 종료 NULL. 서비스 terminal은 시작/종료·토큰 필수. lease/heartbeat는 둘 다 NULL 또는 둘 다 제공하고 lease > heartbeat. 비용·통화는 둘 다 NULL 또는 유한 비음수 비용·영문 대문자 3자리 |
| `item_results` | origin·상태는 5단계 계약. completed일 때만 pass/fail/review verdict 필수. failed/unsupported/imported는 verdict=NULL. 서비스는 reason·checker_version·input_manifest_hash 필수. 수입은 source_result_jsonb 필수 |
| `run_item_selections` | selection_kind는 pipeline_final/import_projection. 첫 범위의 selection_revision=1. 다른 채택으로 변경하려면 새 실행을 생성 |

원문에 시작일보다 이른 종료일이 있으면 구성요소·원문을 보존하고 검토 필요 사유를 남긴다. **end_date ≥ start_date를 무조건 CHECK로 강제하지 않는다.** 실제로 읽힌 모순을 숨기거나 날짜를 바꿔 저장하지 않기 위해서다. 잘못된 날짜 자체는 DATE에 넣지 않고 원문·부분값으로 남긴다.

|---|---|
| service_confirmation | confirmed. source_draft_id/revision/hash·source_requirements_text·confirmed_by/at·confirmation_key/request_hash/request_hash_version 필수 |
| imported | unconfirmed. import_package_id·source_snapshot_jsonb 필수. 로컬 확정자/시각·요청 키/해시/규격은 NULL |
| legacy_snapshot | unconfirmed. source_snapshot_jsonb·source_version_jsonb 필수. 로컬 확정자/시각·요청 키/해시/규격은 NULL |

출처의 확정 상태는 문자열 원문이며 허용 enum을 임의로 좁히지 않는다. 서비스 원문의 비어 있지 않은 요구사항·선택 항목 1~100개·항목당 현재 API 길이 제한은 확정 저장 계층에서도 검사한다. 수입 원문을 로컬 확정으로 바꾸는 UPDATE는 제공하지 않는다.

### 실행 수명과 조건부 필수값

서비스는 5단계에 열거한 요청·코드·정책·설정·입력 해시 컬럼을 모두 제공한다. orchestration_mode=single_pipeline, executor_kind는 background_tasks/postgres_worker, execution_target은 local/runpod다. 첫 conflict_policy_version은 NULL이다.

| 서비스 상태 | 행 안에서 필요한 값 |
|---|---|
| queued | current_stage=queued, available_at 필수, active/selected attempt·finished_at·sealed_at·result_manifest_hash·overall_verdict·error_jsonb는 NULL. 재대기에서는 최초 started_at 유지 가능 |
| running | 단계 preprocessing/ocr/review, active_attempt_id·started_at 필수. available_at·selected_attempt_id·finished_at·sealed_at·result_manifest_hash·overall_verdict·error_jsonb는 NULL |
| completed | 단계 completed·progress=100, selected_attempt_id·started_at·finished_at·sealed_at·result_manifest_hash·overall_verdict 필수. active_attempt_id·available_at·error_jsonb는 NULL |
| failed | 단계 failed, finished_at·error_jsonb 필수. active/selected attempt·available_at·sealed_at·result_manifest_hash·overall_verdict는 NULL. 처리 시작 전 실패는 started_at=NULL 허용 |

completed 이외의 서비스 progress는 0~99로 두어 미완료를 100으로 표시하지 않는다. 원문에는 다른 값이 있더라도 수입 원문에 보존하고 현재 로컬 진행률로 사용하지 않는다.

imported_result/legacy_result는 execution_status=imported, executor_kind/orchestration_mode=imported다. 로컬 현재 단계·진행률·처리 시작/종료·available_at·active_attempt_id·overall_verdict는 NULL이다. 서비스 요청 operation·멱등키·요청 해시/규격도 NULL이다. 실제 구조 저장의 sealed_at·result_manifest_hash·manifest_hash_version은 커밋 시 제공한다. 수입 결과를 채택했다면 selected_attempt_id는 같은 run의 imported 묶음을 가리킨다. 외부 인계는 import_package_id, 과거 JSON은 source_snapshot_jsonb가 필요하다. 원 요청자를 알면 requested_by만 실제 대응 사용자로 연결할 수 있다.

시도의 imported 행은 토큰·lease·heartbeat·로컬 시작/종료 시각이 NULL이며 source_attempt_jsonb로 실제 정보 유무를 남긴다. postgres_worker의 active 시도에 lease가 필수인 조건은 부모 executor_kind를 읽어야 하므로 CHECK가 아닌 전이 검사에 둔다.

## 5. 순환 참조·부모 체인·삽입 순서

다른 테이블끼리의 순환 묶음은 2개다. 모두 선택 연결을 뒤에 완성할 수 있으므로 DEFERRABLE FK로 미루지 않고 즉시 FK를 유지한다.

| 순환 묶음 | 생성·마감 순서 |
|---|---|
| stored_files ↔ import_packages | 매니페스트 파일을 인계 FK 없이 등록 → received 인계 생성 → 파일의 인계 연결 → 검사 후 completed. 연결·완료는 짧은 트랜잭션으로 묶음 |
| review_runs ↔ review_attempts | 포인터 NULL인 queued run 생성 → 시도 생성 → active 포인터·running 설정. 완료는 결과·채택 저장 → 시도 마감·selected 포인터·completed·active 해제를 한 트랜잭션에 반영 |

자기 참조는 assets·stored_files·image_coordinate_frames·import_packages·poster_extractions·criteria_versions·review_runs의 7개다. 직접 자기 연결은 CHECK, 여러 행을 거치는 순환은 다음 규칙으로 처리한다.

- assets의 parent 변경은 프로젝트 행 잠금 아래에서 조상 체인을 조회해 자기 자신이 나타나는지 검사한다. 동시 부모 변경도 같은 프로젝트 잠금을 사용한다.
- 파일·프레임·교체 인계·추출 선행·기준 복사 출처·재검수 원본은 생성 때 기존 행에 연결하고 나중에 부모를 바꾸지 않는다. 파일의 인계 FK 1회 연결은 파일 부모 변경과 구분한다.
- 추출 predecessor는 같은 이미지의 더 작은 version_no, 기준 복사 출처는 같은 프로젝트의 더 작은 version_no여야 한다. 이미 존재하는 선행 행과 불변 연결로 긴 순환을 막는다.
- importer는 입력 순서가 아니라 참조 그래프를 먼저 검사한다. 순환·누락 참조·중복 ID가 있으면 일부 연결만 성공으로 마감하지 않는다.

테이블은 FK 없이 먼저 생성하고 PK·UNIQUE·CHECK 및 FK를 명시적으로 추가할 수 있다. 이는 DDL 생성 순서이며 업무 삽입에서 FK 검사를 끄는 뜻이 아니다.

## 6. 불변성과 상태 전이의 강제 방식

### 앱 역할의 기본 권한

앱 역할은 테이블 소유자·superuser가 아니며 DDL·TRUNCATE·권한 변경을 허용하지 않는다. 기본 권한으로 전체 테이블 UPDATE/DELETE를 일괄 부여하지 않는다. 이미 넓게 부여한 기본 권한은 첫 마이그레이션의 명시적 REVOKE/GRANT 대상이다. 테이블 권한을 남긴 채 컬럼 권한만 좁혀도 제한됐다고 가정하지 않는다. [PostgreSQL GRANT](https://www.postgresql.org/docs/17/sql-grant.html)

| 구분 | 테이블 | 앱 역할 권한·변경 범위 |
|---|---|---|
| 추가 전용 | asset_versions, image_coordinate_frames, record_aliases, audit_events, ocr_tokens, poster_field_observations, evidence_records, evidence_ocr_tokens, criteria_items, item_results, run_item_selections | SELECT·INSERT. UPDATE·DELETE·TRUNCATE 없음 |
| 봉인만 1회 변경 | poster_extractions, criteria_versions | SELECT·INSERT와 sealed_at 컬럼 UPDATE만 허용. NULL→시각의 1회 기록 이후 수정·자식 추가 금지 |
| 제한적 변경 | users, user_sessions, projects, project_members, assets, stored_files, import_packages, ocr_runs, criteria_sets, criteria_drafts, review_runs, review_attempts | SELECT·INSERT와 아래 열거한 컬럼 UPDATE. DELETE 없음 |
| 운영 등록 | schema_definitions | 일반 앱은 SELECT만. 등록·공유 범위 변경은 소유자 역할을 쓰는 별도 관리 경로 |

| 테이블 | UPDATE 허용 컬럼 |
|---|---|
| users | email, password_hash, display_name, is_active, updated_at |
| user_sessions | revoked_at. 만료 연장은 새 세션 발급으로 처리 |
| projects | name, purpose, use_channels, due_at, business_state, archived_at, updated_at |
| project_members | role, is_active, updated_at |
| assets | name, parent_asset_id, updated_at |
| stored_files | import_package_id, state, updated_at. 인계 연결은 NULL→실제 ID의 1회만 허용 |
| import_packages | manifest_file_id, package_fingerprint, fingerprint_version, hash_check_state, import_state, local_validation_jsonb. 완결 전만 변경 |
| ocr_runs | source_file_id, execution_status, engine_name, engine_version, model_name, device, execution_target, pipeline_name, pipeline_version, reported_coordinate_space, engine_settings, runtime_metadata, error_jsonb, started_at, completed_at, sealed_at. 봉인 전 생성 트랜잭션에서만 변경 |
| poster_extractions | sealed_at. 생성 트랜잭션에서 NULL→실제 시각 1회만 허용 |
| criteria_versions | sealed_at. 생성 트랜잭션에서 NULL→실제 시각 1회만 허용 |
| criteria_sets | name, updated_at |
| criteria_drafts | revision, raw_requirements, items_jsonb, source_documents_jsonb, state, updated_by, updated_at. 대상 이미지·묶음은 변경하지 않음 |
| review_runs | execution_status, current_stage, progress, overall_verdict, available_at, active_attempt_id, selected_attempt_id, error_jsonb, result_manifest_hash, updated_at, started_at, finished_at, sealed_at |
| review_attempts | stage, execution_status, dispatch_state, lease_expires_at, heartbeat_at, request_id, remote_job_id, actual_runtime, retryable, timing_jsonb, cost_amount, currency, error_jsonb, finished_at |

관리자의 DDL 권한에 의한 변경까지 막는다고 표현하지 않는다. 운영 변경은 마이그레이션·관리 절차와 감사 기록으로 관리한다. 프로젝트별 접근 통제는 아래 7절처럼 별도이며, 앱 역할의 테이블 권한만으로 사용자를 구분하지 않는다.

### 조건부 변경과 교차 행 검사

행 안의 상태·값 변경은 `BEFORE UPDATE` 전이 검사로 보호한다. 제약 목록의 `tr_*_transition` 이름을 사용한다. terminal은 OCR completed/failed/imported, run completed/failed/imported, attempt succeeded/failed/unknown/imported, 인계 completed다. 미봉인 부모의 최초 봉인만 별도 허용하며 봉인된 행의 수정은 거부한다. 종료된 검수 실행은 재대기하지 않는다. 안전 재시도에서는 이전 시도를 마감한 뒤 아직 진행 중인 run만 queued로 돌린다. [PostgreSQL 트리거](https://www.postgresql.org/docs/17/plpgsql-trigger.html)

| 대상 | 허용 전이·불변 조건 |
|---|---|
| import_packages | received→completed/needs_review/failed, needs_review→completed/failed 또는 같은 상태에서 미완성 검사 보강. failed→received는 관리 경로의 명시적 재검증과 이전 실패 감사 기록을 동반. 이미 정한 매니페스트·지문은 고정, 다른 바이트는 새 인계. completed 변경 금지 |
| ocr_runs | 같은 생성 트랜잭션에서 queued→running/failed, running→completed/failed 또는 완결 출력 직접 INSERT 후 봉인. 커밋 시 terminal·sealed 필수. 이미지·시도·프레임·입력 파일·출처 FK 고정 |
| poster_extractions·criteria_versions | 다른 컬럼은 생성 시 고정. sealed_at의 NULL→실제 시각만 1회 허용. 봉인 후 자식 추가·봉인 해제 금지 |
| criteria_drafts | editing→editing/archived. 내용이 바뀌면 revision 정확히 +1, 기존 archived 수정 금지. API expected_revision 비교는 저장 계층 책임 |
| review_runs | queued→running/failed, running→queued/completed/failed. terminal 변경 금지. imported는 최초 수입 저장 트랜잭션에서 구조 봉인·manifest·채택 포인터만 완성 가능. 재대기는 안전 종료된 시도와 정책 확인 필요 |
| review_attempts | active→active/succeeded/failed/unknown. terminal 변경 금지, 토큰·실행·입력 설정·시도 번호 고정. dispatch 상태는 not_dispatched→dispatching→submitted/unknown, 제출 후 결과 불명은 unknown 가능 |
| stored_files | state는 stored↔missing 허용. import FK는 최초 연결만 허용하고 이후 교체·해제 금지. 바이트·해시·키·부모는 변경 금지 |
| schema_definitions | 운영 관리 경로도 schema_id·이름·버전은 고정. metadata_only→available만 허용하고 available 이후 정의 파일·해시 교체 금지. access_scope는 검토·회수에 따라 변경 가능 |

UPDATE 권한을 없애도 자식을 나중에 INSERT하면 과거 스냅샷이 달라질 수 있다. 이를 막기 위해 OCR·추출본·기준 버전에 sealed_at을 추가하고, 실행은 기존 sealed_at과 terminal 상태를 사용한다. 별도의 생성 트랜잭션 ID 컬럼이나 사용자가 바꿀 수 있는 세션 변수로 첫 생성을 추측하지 않는다.

C07b 구현에서는 프로젝트 잠금/재조회를 READ COMMITTED에서 검증하고 다른 격리 수준을 거부한다. schema/OCR/run/attempt의 전이 트리거는 INSERT도 검사한다. 실제 객체·경합·미실행 책임은 [C07b 기록](구현_C07b_봉인전이와M007.md)을 따른다.

자식의 BEFORE INSERT 검사 `tr_*_append_gate`는 아래 부모를 잠근 뒤 봉인 전인지 확인한다. 따라서 자식 추가와 봉인이 경합해도 같은 부모 잠금으로 직렬화된다. 요청 토큰·HTTP 사용자 검증은 실제 저장 계층에서 부모 잠금을 보유한 상태로 수행한다. 트리거 자체가 사용자 인증을 대신하지 않는다.

| 자식 | 잠금·봉인 검사 대상 |
|---|---|
| ocr_tokens | ocr_runs. sealed_at=NULL일 때만 삽입 |
| poster_field_observations | poster_extractions. sealed_at=NULL일 때만 삽입 |
| criteria_items | criteria_versions. sealed_at=NULL일 때만 삽입 |
| item_results·run_item_selections | review_runs. 미봉인 running 서비스의 현재 시도 또는 미봉인 imported 수입 묶음만 허용 |
| evidence_records | 소유 관찰의 추출본 또는 소유 결과의 run. 해당 루트 미봉인 필요 |
| evidence_ocr_tokens | 소유 근거를 따라 같은 추출본/run의 봉인 검사. 토큰 자체는 이미 봉인된 OCR을 참조해도 됨 |

stored_files가 인계 묶음을 처음 연결할 때는 `tr_stored_files_import_gate`로 해당 인계가 미완결 상태인지 잠금 아래 확인한다. completed 인계에 파일을 뒤늦게 추가하지 않는다. 이후 실제 파일 누락을 관찰한 stored↔missing 상태 변경은 허용하며, 과거 접수 완료라는 사실을 취소하지 않는다. 파일의 현재 가용성과 접수 당시의 완결은 다른 정보다.

부모 INSERT와 변경에 대한 **AFTER ROW·DEFERRABLE INITIALLY DEFERRED 제약 트리거**는 커밋 직전에 최종 행을 다시 조회한다. 부모 먼저 생성 → 자식 전체 저장 → 실제 sealed_at 1회 기록이라는 순서를 허용하되 미봉인 스냅샷의 커밋은 거부한다. 모든 이벤트가 발생했을 때의 중간 NEW 값으로 완료 여부를 판정하지 않는다. [PostgreSQL CREATE TRIGGER](https://www.postgresql.org/docs/17/sql-createtrigger.html)

- `ct_ocr_snapshot`: 커밋 시 OCR은 completed/failed/imported이며 sealed_at 필수. 토큰·프레임 문맥을 검증한다. queued/running은 생성 중 상태이며 별도 영속 OCR 큐로 커밋하지 않는다.
- `ct_extraction_snapshot`: 추출본 sealed_at 필수. 관찰·관찰 근거의 이미지·프레임·OCR 문맥을 검증한다. 추출 payload와 관찰 변환의 의미 일치는 저장 어댑터 책임이다.
- `ct_criteria_snapshot`: 기준 버전 sealed_at 필수, 항목 1~100개·position 1부터 연속·생성 경로 필수값 확인. 해시 직렬화와 내용 계산은 저장 계층이 수행하고 봉인 전에 검사한다.
- `ct_review_integrity`: running의 현재 active 시도 정확히 1개, queued/terminal의 active 시도 0개. completed는 selected succeeded 시도·전체 항목·동일 시도 채택·봉인/manifest 존재를 확인한다. imported는 로컬 구조 봉인과 imported 묶음 연결을 확인하고 자동 verdict를 요구하지 않는다.
- `ct_import_integrity`: 인계를 completed로 만들 때 매니페스트 파일이 같은 인계에 연결돼 있고 파일 상태가 stored인지 확인한다. 이후 파일의 missing 기록을 막는 영구 조건으로 사용하지 않는다. 실제 바이트·전달 지문 비교는 저장 계층 책임이다.
- `ct_project_owner`: 프로젝트·멤버십·사용자 활성 상태 변경 시 관련 프로젝트를 ID 순으로 잠근 뒤 활성 사용자에 연결된 활성 owner가 적어도 하나인지 재조회한다. 첫 프로젝트와 owner의 같은 트랜잭션 생성을 허용한다.
- `ct_lineage_<테이블>`: 자기 참조 7개 테이블의 최종 부모 체인을 재귀 조회하고 방문 ID가 반복되면 거부한다. 여러 행을 한 INSERT에 넣는 수입에서도 순환을 막는다. 추출·기준의 선행 version_no는 더 작아야 한다. assets의 부모 변경은 프로젝트 잠금 아래에서 수행한다.

OCR·추출·기준의 전체 검증은 루트의 INSERT/봉인 이벤트에서 수행한다. 봉인 전 루트는 커밋할 수 없고 자식 UPDATE는 금지되므로, 토큰 수만큼 같은 전체 그래프를 재검증하는 트리거를 만들지 않는다. 실행의 항목 결과·채택 이벤트는 커밋 시 부모가 completed 또는 구조 봉인된 imported인지 가볍게 확인하고, 전체 항목 집합 검증은 run 전이에서 수행한다. 시도 상태 변경은 현재 포인터 정합성을 함께 확인한다.

부모의 상태·관계만 강제하며 DB가 Python 해시 규격·실제 파일 바이트·요청자의 권한을 검증한 것으로 표현하지 않는다. 봉인 직전 저장 진입점·파일/DB 커밋·미확인 결과·수입 구조 봉인은 [9단계](추가설계_09_저장과이전복구.md)에서 구체적인 호출 순서로 연결했다.

## 7. 프로젝트 권한과 전역 규격 예외

첫 서비스는 웹 요청의 세션 사용자·활성 멤버십·역할을 FastAPI에서 검사한다. DB 앱 역할 하나를 여러 사용자가 공유하므로 그 역할의 SELECT 권한만으로 프로젝트별 격리가 생기지 않는다. 첫 구현에 RLS를 함께 추가하는 것으로 가정하지 않는다.

| 역할·상태 | 허용 범위 |
|---|---|
| viewer | 소속 프로젝트의 기준·이력·결과·권한 검사된 이미지/원문 조회 |
| editor | viewer + 활성 프로젝트의 업로드·초안·기준 확정·검수·재검수 |
| owner | editor + 이름·보관 상태 관리. 마지막 활성 owner 제거 금지 |
| archived 프로젝트 | 이력 조회 가능. 신규 자료·기준·검수 접수 금지. 이미 접수한 실행은 고정 입력으로 마감 |
| 운영 관리 경로 | 계정 발급·멤버십·전역 규격 등록. 일반 사용자 API와 분리 |
| 개발 admin/admin | localhost·LOCAL_ADMIN_LOGIN 경계를 유지하고 실제 개발 UUID·소속 프로젝트로 연결. 업무 권한 자동 우회 없음 |

프로젝트 생성과 owner 멤버십은 같은 트랜잭션이다. owner 변경·비활성화·사용자 비활성화가 마지막 활성 owner를 없애지 않는지 프로젝트 잠금 아래에서 검사한다. 실행 접수의 권한도 같은 트랜잭션 안에서 재확인한다. 목록·이미지·JSON 다운로드·샘플에서 프로젝트 권한 경로가 누락되지 않도록 후속 인증/API 사례에 포함한다.

전역 규격에는 이번에 `access_scope`를 추가했다. 기본 metadata_only는 이름·버전 설명용이다. **available은 파일 확보·로딩 가능 여부**, **service_shared는 운영 관리 경로에서 확인한 서비스 검증 사용 허용**이다. 후자만으로 원본 파일의 다운로드 권한이 생기지는 않는다.

업무 검증기는 service_shared·available 규격만 내부에서 로드한다. 일반 API는 전역 정의의 저장 키·파일 ID를 일괄 반환하지 않는다. 실제 파일 다운로드에는 원 소유 프로젝트 권한을 적용한다. 권한 없는 프로젝트 문서를 단순히 전역 메타데이터로 등록해 공유하지 않는다. 파일이 missing이면 사용 가능으로 판단하지 않고 검증을 보류하며 원래 규격 ID·실패 이유를 보존한다.

계정 발급·이메일/개발 로그인 분기·개발 UUID 초기화·8시간 DB 세션·관리 명령은 [추가 설계 7단계](추가설계_07_인증과권한.md)에서 확정했다. account_kind는 생성 뒤 변경하지 않으며 위 UPDATE 허용 목록에도 포함하지 않는다. 사용자·세션·멤버십의 잠금 순서와 폐기·마지막 owner 검사는 같은 문서의 트랜잭션 경계를 따른다.

## 8. 조회 인덱스와 중복 비용

PK·UNIQUE가 만드는 인덱스는 동일 컬럼의 일반 인덱스로 다시 만들지 않는다. 복합 키의 좌측 컬럼과 정렬 방향을 실제 조회 조건과 대조한다. 첫 조회 인덱스는 제약 목록의 명시한 목록만 도입하고, 모든 JSONB 컬럼에 GIN을 일괄 추가하지 않는다.

핵심 조회는 멤버십 기반 프로젝트 목록, 프로젝트별 실행 최신순·상태 필터, 기준 버전·항목 순서, OCR 토큰·근거 목록, 독립 worker의 인수·lease 만료다. 실행 이력 cursor는 `(created_at, run_id)` 두 값을 사용하고 동률을 UUID로 구분한다. 목록에서 대용량 OCR 원문·근거 배열을 매번 펼치지 않는다. 상세 응답·페이지 크기는 후속 API 계약에서 정한다.

run당 active 시도 최대 하나는 `uq_review_attempts_active_run` 부분 유일 인덱스로 강제한다. worker 인수 인덱스의 조건은 service_execution/postgres_worker/queued라는 고정 상태이고, 현재 시각은 인덱스 조건에 넣지 않는다. 조회 시 available_at과 DB 실제 시각을 비교한다. lease 회수 인덱스도 active·lease 존재 조건만 사용한다. [PostgreSQL 부분 인덱스](https://www.postgresql.org/docs/17/indexes-partial.html)

7단계에서 `uq_users_developer_kind`를 추가했다. account_kind=developer 행의 account_kind에 부분 유일성을 적용해 비활성 행을 포함해 하나만 허용한다. 정식 이메일 유일 제약의 NULL 예외가 개발 사용자 무제한 생성을 허용하지 않도록 한다.

FK의 참조 측 인덱스는 자동 생성되지 않는다. 제약 목록에는 각 FK가 PK/UNIQUE/일반 인덱스의 전체 좌측 접두부로 지원되는지 표시한다. 생성자·전역 규격 파일 등 역조회 빈도가 낮고 앱 DELETE가 금지된 참조에는 별도 인덱스를 무조건 추가하지 않는다. 문맥 접두부만 있는 경우를 전체 FK 컬럼이 지원되는 경우와 구분하고, 실제 PostgreSQL 쿼리 계획·데이터 규모에서 검증한다.

## 9. 문서 차이와 미확정 사항 관리

| 기존 표현·차이 | 이번 기준·처리 |
|---|---|
| 기존 ERD의 기준 묶음별 버전 번호 | 프로젝트별 version_no UNIQUE로 정리 |
| work_unit별 시도 번호 | 첫 범위는 run별 attempt_no. 후속 작업 단위 FK는 제외 |
| 프로젝트별 멱등키 | 사용자·operation·키로 정리. 기준 확정과 검수 생성/재검수의 물리 저장 위치 분리 |
| 문자열 JSON·timezone 없는 시각 | 영역별 JSONB·TIMESTAMPTZ 정의가 우선 |
| 전역 규격의 프로젝트 파일 접근 | access_scope와 원 소유 프로젝트 파일 권한을 분리 |
| FK만으로 모든 문맥 보장 | 문맥 복합 FK와 교차 행/파일/권한 검사의 책임 구분 |
| DB 연결 도구 미선정이라는 이전 명세와 도구 제안 안내 | 10단계에서 SQLAlchemy Core 2.1.5·psycopg 3.3.6 동기 Connection·Alembic 1.20.0 및 스레드/설정 경계를 선택. 패키지 설치·실제 연결은 후속 코드 작업 |
| 초안 revision이 필요한데 목표 API에 초안 경로 없음 | 8단계에서 초안 POST/GET/PUT과 expected_revision, 확정 본문을 명시적으로 결정 |
| 개발 문자열 ID와 UUID FK·필수 이메일 | 7단계에서 account_kind와 종류별 필수 CHECK·명시적 개발 초기화 확정. 임의 이메일·정식 기본 비밀번호 생성 금지 |

기존 ERD 문서는 전체 장기 구조를 가져오는 초안으로 남겨두고, 첫 마이그레이션은 이 설계와 제약 목록을 기준으로 만든다. 문서 간 모순을 발견하면 원인·적용 범위·최종 결정을 해당 영역 문서에 함께 반영한다. 실제 SQL은 별도 구현 단계의 검토 대상이다.

## 10. 검증 사례와 이번 검토의 한계

| 검증 ID | 입력·경합 | 기대 결과 |
|---|---|---|
| DB-01 | 다른 프로젝트 파일·이미지·기준·시도·결과 연결 | 대응 복합 FK 거부 |
| DB-02 | 같은 이미지의 다른 기준 버전 항목 결과 채택 | 결과/채택 문맥 FK 거부 |
| DB-03 | 같은 근거에 다른 OCR 토큰 연결 | 근거 문구 복합 FK 거부 |
| DB-04 | 선택 FK의 대상 ID만 NULL | 부모 없는 상태 허용. 필수 문맥은 계속 NOT NULL |
| DB-05 | 인계 없는 같은 별칭 중복 | NULLS NOT DISTINCT 유일 키 거부 |
| DB-06 | 같은 rule_code·동일 파일 해시·같은 프로젝트명 | 개별 ID를 유지해 저장 가능 |
| DB-07 | 조건부 필수값 누락·NaN/Infinity·잘못된 JSON·역전 bbox | CHECK/계약 검증 거부 |
| DB-08 | 요구사항·날짜·상태 미보고 수입 | 원문·NULL 보존. completed/pass/confirmed 추정 금지 |
| DB-09 | 같은 프로젝트의 기준 번호 동시 발급 | 프로젝트 잠금·유일 제약으로 다른 번호 또는 같은 멱등 리소스 |
| DB-10 | 같은 사용자·operation·키 동시 접수 | 리소스 하나. 다른 본문이면 409 |
| DB-11 | 한 run의 active 시도 두 개 생성 | 부분 유일 인덱스 거부 |
| DB-12 | 만료 heartbeat·이전 토큰·늦은 완료 | 현재 시도/토큰/실제 시각 검사로 거부 |
| DB-13 | OCR·근거·결과 중간 저장 오류 | 완료·채택 포함 전체 롤백. 원문 파일은 정리 계약으로 처리 |
| DB-14 | 완료 후 항목 추가·판정 변경·채택 교체 | 추가 전용 권한·봉인/전이 검사로 거부 |
| DB-15 | 마지막 owner 동시 제거·보관과 신규 접수 경합 | 프로젝트 잠금 아래에서 일관된 권한·상태 검사 |
| DB-16 | global metadata_only 규격을 업무 검증/파일 다운로드에 사용 | 사용 범위·프로젝트 권한 검사로 거부 |
| DB-17 | 첫 NULL 포인터·FK 연결 순서 및 두 순환 묶음 | FK 비활성화 없이 트랜잭션 완결 |
| DB-18 | 빈 DB 구축·백업 후 다른 DB 복원 | 동일한 제약·권한·행 관계·파일 연결 재현. 후속 실DB 검증 |

이번에는 문서에서 PK·UNIQUE·FK의 대상 컬럼·자료형·NULL·이름 중복과 인덱스 참조, 범위·로컬 링크를 정적으로 대조했다. 실제 PostgreSQL에서 거부·동시성·트리거·성능·백업 복원을 실행한 것은 아니다. CHECK는 조건 명세이며 SQL 구현은 후속 마이그레이션에서 문법·NULL 평가·오류 변환까지 검증한다.

6단계의 [정적 검토 기록](verification/2026-10-16-physical-design-stage6.json)은 당시 394개 컬럼의 이력으로 보존한다. 계정 종류를 반영한 [7단계 기록](verification/2026-10-16-auth-design-stage7.json), [8단계 API 기록](verification/2026-10-17-api-design-stage8.json), [9단계 기록](verification/2026-10-17-storage-design-stage9.json)도 당시 이력으로 보존한다. 구현 계획까지 반영한 최신 정적 검토는 [10단계 기록](verification/2026-10-17-implementation-design-stage10.json)에 남긴다. 현재 목록은 CHECK 77개 묶음·부분 유일 인덱스 2개·일반 조회 인덱스 25개·전이/봉인 등 검증 규칙 이름 30개다. 이름 하나를 여러 테이블의 트리거 인스턴스에 연결할 수 있으므로 규칙 이름 수와 실제 SQL 객체 수는 구분한다.
