# PostgreSQL 물리 설계 6단계 — 제약·인덱스 목록

작성일: 2026-10-16

상태: **검토한 설계 목록. SQL 실행 파일이 아니다.** 의미·조건·권한·봉인 절차는 [전체 정합성](물리설계_06_전체정합성.md)을 따른다. 컬럼 자료형은 영역별 문서가 기준이다. [추가 설계 7단계](추가설계_07_인증과권한.md)의 계정 종류·조건부 필수 CHECK·개발 주체 부분 유일 인덱스를 반영했다.

## 1. 이름·집계·인덱스 표시 규칙

- 이름은 영어 snake_case이며 63바이트 이하, 이번 목록 안에서 중복이 없다.
- 모든 FK는 DELETE/UPDATE RESTRICT, NOT DEFERRABLE이다. 봉인·교차 행 검증의 제약 트리거만 커밋 시점까지 지연한다.
- PK·UNIQUE의 지원 인덱스는 별도로 중복 생성하지 않는다. CHECK의 상세 조건은 전체 정합성 3·4절을 따른다.
- FK의 지원 표시는 참조 측 전체 컬럼이 인덱스의 좌측 접두부인 경우다. 선택 ID가 NULL이 아닌 행만의 인덱스는 실제 FK 검사 대상 행을 지원한다.
- `별도 역조회 인덱스 보류`는 FK 누락이 아니다. 참조 대상의 유일 키는 존재하며 앱의 물리 DELETE가 금지된 저빈도 역조회는 필요 시 측정 후 보강한다.

| 구분 | 개수 |
|---|---:|
| PK | 26 |
| UNIQUE 제약 | 41 |
| FK | 81 |
| CHECK 묶음 | 77 |
| 부분 유일 인덱스 | 2 |
| 일반 조회 인덱스 | 25 |

CHECK 묶음은 이름 하나에 단일 행 조건 여러 개를 담을 수 있다. 실제 SQL에서 묶음을 세분화하면 이름·목록도 함께 갱신한다. 트리거 목록의 이름은 테이블별 인스턴스 또는 여러 테이블에 적용할 검증 규칙 이름이며 실제 함수 개수와 구분한다.

C07b에서 위 30개 규칙을 실제 트리거 35개·함수 19개로 구현했다. schema/OCR/run/attempt의 INSERT 검사도 연결해 잘못된 최초 연결을 막는다. 아래 설계 이력과 별도로 [C07b 구현 기록](구현_C07b_봉인전이와M007.md)을 따른다.

각 제약 트리거는 커밋 시 현재 최종 행을 다시 조회한다. CHECK로 해시 직렬화·권한·파일 바이트까지 검증하는 것으로 구현하지 않는다. 부모 봉인·전이와 자식 INSERT 검사 모두 적용해야 하며, 구현 시 전체 정합성의 DB-01~18 사례로 실제 PostgreSQL에서 검증한다.

## 5. 정적 검토 기록

[최신 검토 결과 JSON](verification/2026-10-17-implementation-design-stage10.json)은 파일·키·자료형·NULL·그래프·이름·인덱스 참조의 정적 검사 결과다. SQL·트리거 실행·쿼리 성능·동시성 통과 증거가 아니다.
