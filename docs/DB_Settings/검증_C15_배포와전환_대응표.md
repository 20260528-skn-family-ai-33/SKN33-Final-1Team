# C15 검증 대응표

작성일: 2026-10-19. 범위는 사용자가 선택한 로컬 Linux 리허설과 전환 자료다. 실제 운영 공개·실제 Linux Paddle·암호화 원격 보관은 미실행이다.

기본 Python **686개·서브테스트 7개**, 전체 PostgreSQL core **1,327개**, Linux HTTPS **1개**, C15 Compose **2개**, 직접/Vite 브라우저 **2개**, 프런트 단위 **53개**와 v1 빌드를 통과했다. C15 신규는 기본 16개·전환 검사 5개·Compose 2개로 **23개**다. 별도 집중 실행 5개는 core에 포함되므로 중복 합산하지 않는다. 이번 DB 연계 고유 사례는 **1,332개**다.

보호 파일 105개의 시작 SHA가 일치하고 일상 DB public 관계/OID·기본 ACL이 그대로이며 임시 DB를 모두 정리했다. API/worker UID 10001·read-only root·비공개 포트, 복원 후 원 쿠키 거부·새 로그인/검수·재시작 조회를 확인했다. 실제 로컬 세트 생성 0.9743초·복원 검증 0.9717초이며 SLA 증거는 아니다.

최종 수치·실제 측정·실행 환경·보호 파일 SHA는 [증거 JSON](verification/2026-10-19-implementation-C15.json), 안전한 실제 흐름은 [Linux 리허설 요약](verification/C15/linux-rehearsal.json)에 기록한다. 집중 release 사례는 전체 core에 중복 포함하므로 두 번 합산하지 않는다.

기존 개발 시제품은 기본 쓰기 동작을 유지하며 구형 종료는 명시적 읽기 모드 또는 v1 배포의 경계다. 실제 기존 listener 중지/도메인 전환은 수행하지 않았다. Dockerfile.worker 정적 검사를 실제 Paddle 이미지 빌드/추론으로 표시하지 않으며, 재시작/복원 후 재가동을 이전 코드 버전 롤백 인증으로 표시하지 않는다.
