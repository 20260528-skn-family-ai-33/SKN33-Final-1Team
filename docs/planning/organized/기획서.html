01 · 기획 배경

사람이 놓칠 수 있는 광고의 오류,
문서의 기준부터 다시 확인합니다.

광고 납품물의 검수·수정 요청·재검수를 연결하는 MCP 기반 다중 에이전트 업무자동화 서비스입니다.

배경

광고와 창작물이 많아집니다.

숏츠·인스타그램 릴스·광고 이미지까지 다양한 채널에서 사람이 제작하거나 AI로 생성한 콘텐츠를 사용합니다. 납품물이 많아질수록 명세서·계약서·브랜드 가이드를 반복해서 확인하는 업무도 늘어납니다.

문제

작은 조건을 놓칠 수 있습니다.

상품명·할인율·브랜드 표기와 변경 사항을 사람이 꼼꼼히 보아도 누락할 수 있습니다. 기준·수정본·이력이 흩어지면 어떤 버전으로 확인했는지도 다시 찾아야 합니다.

해결책

기준과 근거를 연결합니다.

문서에서 조건을 추출하고 사람이 확정합니다. 에이전트가 문구와 시각 요소를 검사하고 근거를 검증한 뒤 보고서·수정 요청·재검수까지 연결합니다.

기대효과

읽고, 고치고, 결정하도록 돕습니다.

검수자는 원문과 오류 근거를 확인하고, 제작자는 수정할 내용을 이해하며, 승인자는 최신 결과를 보고 판단합니다.

배경과 문제는 기획 가설이며 개선 효과는 아직 미측정입니다. 수집 사례와 비교 실험으로 검증합니다. 1차 개발 대상은 광고 이미지입니다.

서비스 한눈에 보기

질문기획 기준
어떤 업무를 돕나요?광고 납품 검수, 수정 요청, 수정본 재검수와 최종 판단을 돕습니다.
누가 사용하나요?검수 담당자, 광고 제작자, 최종 승인자가 사용합니다. 승인 권한은 별도로 구분합니다.
언제 쓰나요?최초 납품, 기준 변경, 수정본 제출, 최종 승인 전입니다.
어디서 확인하나요?문서·이미지·근거·진행 이력이 모인 웹 화면입니다.
어떻게 처리하나요?문서 추출 → 사람 확정 → 전체 기준 검사 → 근거 검증 → 수정·재검수 → 사람 승인입니다.

문서를 읽는 순간부터 수정이 끝나는 순간까지.

화면의 구체적인 구성은 화면정의서, 각 기능의 완료 조건은 기능정의서에서 관리합니다.

01

문서 등록·기준 추출

검수 담당자가 명세서·계약서·가이드를 등록합니다. 문서 전체에서 기준 초안과 출처를 추출합니다.

남는 결과 · 출처가 있는 기준 초안

02

사람의 기준 확인·확정

원문과 추출값을 비교해 누락·충돌을 해소합니다. 직접 입력은 보정·변경을 위한 보조 수단입니다.

남는 결과 · 확정된 기준 버전

03

이미지 검수·근거 검증

문구·규격·시각 조건을 나눠 확인합니다. 미실행과 확인 필요 항목도 남깁니다.

남는 결과 · 항목별 결과·관찰·근거

04

보고서·수정 요청

위치와 수정 내용을 설명합니다. 사람이 수정 요청 초안을 검토하고 확정합니다.

남는 결과 · 보고서·확정된 수정 요청

05

수정본 재검수

새 이미지 버전에서 기존 지적 해결과 새 오류를 함께 확인합니다. 기준 변경이 없으면 기존 확정 기준을 재사용합니다.

남는 결과 · 새 실행 결과·해결 이력

06

사람의 최종 승인

최신 기준·이미지·실행 버전이 일치하는지 확인한 후 사람이 승인하거나 보류합니다.

남는 결과 · 승인 또는 보완 기록

딸기라떼 예시

문서 기준은 “딸기라떼 · 30% 할인 · MORNING CUP”, 납품 이미지의 할인 문구는 “20% 할인”이라면 해당 기준과 이미지 위치를 연결해 불일치 후보를 보여줍니다. 이는 설명용 사례이며 범용 모델 성능을 증명하는 수치가 아닙니다.

사용자주요 업무판단 권한
검수 담당자원본 등록, 기준 검토·확정, 검수 실행, 수정 요청 확인기준과 수정 요청을 사람이 확정합니다.
제작자이미지·증빙 제출, 수정 요청 확인, 수정본 제출자신의 납품물을 임의로 최종 승인하지 않습니다.
최종 승인자미해결 항목과 최신 버전 결과 검토권한을 가진 사람이 승인·보류합니다. 역할을 겸해도 이력은 구분합니다.

이번에 연결할 업무와 이후 확장할 범위.

1차 개발 범위

광고 이미지와 기준 문서 등록, 문서 기반 기준 추출, 사람 확인, 문구·시각 검수, 근거 보고, 수정 요청, 재검수, 사람 승인까지의 업무 연결입니다.

후속·선택 범위

영상 검수, 생성형 LoRA/QLoRA, Reranker, 객체 탐지, 외부 SaaS 연동은 필요성과 실험 결과를 확인한 후 채택합니다.

구분범위확인 수준
기존 구현 기록FastAPI 웹, 샘플 JSON 기준 확인·확정, 이미지 접수, SQLite, Mac Vision 문자 OCR, 실제 MCP 호출, 근거·이력 조회README의 이전 실행 기록 기준입니다. 이번 문서 분리에서 앱을 다시 실행하지 않았습니다.
개발 예정문서 기반 LLM 기준 추출, 학습한 요청 분류기, Hybrid RAG, 8개 에이전트 협업, 시각 모델, 수정·재검수·승인, MySQL·Qdrant·공용 GPU설계·선택안이며 현재 동작을 의미하지 않습니다.
예제 데이터동일 원본 그룹에서 파생한 딸기라떼 이미지 6종개발·시연용입니다. 독립 평가 6건으로 집계하지 않습니다.
기존 요구사항은 유지합니다.

외부 비교·제작 근거 등 기존 원범위 항목을 삭제하거나 완료 처리하지 않았습니다. 원 요구사항 69개와 원 우선순위는 기능정의서에 보존하고, 실제 구현 순서·범위 승인은 별도로 관리합니다.

기대효과를 실제 업무 변화로 확인합니다.

아래 지표는 측정 계획입니다. 속도·정확도 개선 수치나 효과 달성을 주장하지 않습니다.

기대하는 변화확인 지표비교 방법상태
검수자가 기준을 확인하기 쉬워진다기준 준비 시간·누락률·원문 대조 정확도같은 문서의 수동 처리와 AI 초안+사람 검토 비교. 총 경과 시간과 사람 작업 시간 분리미측정
제작자가 수정할 내용을 이해한다요청 작성 시간·누락·재질문 횟수같은 오류 사례의 수동 요청과 근거 포함 요청 비교미측정
담당자가 오류와 미검사를 구분한다오통과율·위반 재현율·확인필요율독립 원본 사례의 정답과 항목별 결과 비교미측정
승인자가 최신 결과로 판단한다버전 혼용·중복 처리·승인 차단 테스트기준 변경/수정본/재시작 시나리오로 검증미측정

모델별 정확도, 검색 지표, Ragas와 서비스 시험의 역할은 기술스펙정의서에서 상세히 정의합니다. 사람 작업 시간과 전체 경과 시간은 구분해서 기록합니다.
