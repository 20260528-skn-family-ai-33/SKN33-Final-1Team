02 · 기획 배경

콘텐츠가 많아질수록,
기준을 다시 읽는 일도 반복됩니다.

배경

사람과 AI가 다양한 창작물을 만듭니다.

숏츠·인스타그램 릴스·광고 이미지 등 여러 채널에 사용할 콘텐츠를 제작합니다. 이번 프로젝트는 그중 광고 이미지 납품 검수부터 다룹니다.

문제

이미지만 보아서는 계약 조건을 확인하기 어렵습니다.

상품명·할인율·브랜드·구성 조건이 명세서와 계약서에 흩어져 있습니다. 사람이 꼼꼼히 확인해도 작은 조건이나 변경 사항을 놓칠 수 있고, 수정본이 쌓이면 적용한 버전도 다시 찾아야 합니다.

해결

원문 조건과 이미지 근거를 함께 보여줍니다.

문서에서 검사 가능한 조건을 추출하고 사람이 확정합니다. 문구·시각 검수 결과에 근거를 연결하고, 수정 요청과 재검수에 같은 기준·버전 이력을 이어갑니다.

기대효과

검수자는 확인하고, 제작자는 고치고, 승인자는 결정합니다.

누락을 줄이고 수정할 내용을 이해하기 쉽게 만드는 것이 목표입니다. 사람의 검토·판단 과정은 유지하며, 효과는 수동 처리와 AI 보조 처리의 비교로 측정합니다.

효과를 확인할 지표

업무 변화확인할 지표측정 방법
기준 준비를 돕는다준비 시간·조건 누락률·출처 정확성같은 문서의 수동 처리와 AI 초안+사람 검토 비교
수정 요청을 명확하게 만든다요청 작성 시간·재질문·누락같은 오류 사례에서 근거 포함 요청과 수동 요청 비교
놓친 오류를 확인한다위반 탐지 재현율·오통과율·확인 필요 비율독립 원본과 사람이 검토한 항목별 정답으로 평가
최신 결과로 승인한다구버전 혼용·중복 처리·잘못된 승인기준 변경·수정본·재시작·권한 시나리오 시험

배경은 기획 가설이며, 정확도·시간 절감 효과는 아직 측정하지 않았습니다. 사람 작업 시간과 전체 처리 시간은 따로 기록합니다.

설명 포인트

검수자가 이미 잘하고 있는 일을 보조하는 관점입니다. 광고량 증가나 시간 절감률을 수치로 단정하지 않고, 프로젝트에서 검증할 문제와 지표로 설명합니다.

04 · 사용 장면

딸기라떼 광고 한 건으로
처음부터 끝까지 설명합니다.

문서의 확정 조건이 “딸기라떼 · 30% 할인 · MORNING CUP”인데 이미지에는 “20% 할인”으로 적혀 있는 사례입니다. 아래는 목표 업무 흐름의 설명 예시입니다.

  1. 01

    문서와 납품물을 등록합니다.

    발주와 제출 권한을 확인하고 원본·파일 해시·문서 및 이미지 버전을 보존합니다. 접수 완료와 문서 판독 완료를 별도로 표시합니다.

    남는 결과 · 발주에 연결된 원본 자료
  2. 02

    기준 초안을 추출하고 사람이 확정합니다.

    상품명·할인율·브랜드와 출처 페이지·조항을 추출합니다. 누락·충돌·미판독 구간을 확인하고 검수 담당자가 기준을 확정합니다.

    남는 결과 · 출처가 있는 확정 기준 버전
  3. 03

    확정 기준 전체를 검사합니다.

    문구는 OCR로 읽고, 시각 조건은 검증한 이미지 이해 모델로 관찰합니다. 기준 30%와 관찰 20%를 대조해 해당 위치와 함께 불일치 후보를 기록합니다.

    남는 결과 · 항목별 관찰·실행 상태·판정·근거
  4. 04

    근거를 검증하고 보고서를 만듭니다.

    문서의 30% 조건과 이미지의 20% 관찰이 실제 출처로 뒷받침되는지 확인합니다. 판독이 불분명하면 제한된 재검사 또는 사람 확인으로 넘깁니다.

    남는 결과 · 검증된 결과와 확인 필요 목록
  5. 05

    사람이 수정 요청을 확정합니다.

    “할인 문구를 20%에서 30%로 수정”이라는 요청 초안을 근거와 함께 제시합니다. 담당자가 대상·내용·수신 범위를 확인합니다.

    남는 결과 · 보고서와 확정된 보완 요청
  6. 06

    수정본에서 해결 여부와 새 오류를 검사합니다.

    수정본은 새 이미지 버전과 새 실행으로 연결합니다. 기존 할인율 지적이 해결됐는지와 다른 조건에 새 문제가 생겼는지를 함께 확인합니다.

    남는 결과 · 새 검수 결과·보완 해결 이력
  7. 07

    권한 있는 사람이 최종 승인하거나 보류합니다.

    최신 기준·이미지·실행 버전과 미해결 항목을 확인합니다. 검사 실행 완료, 보완 작업 해결, 최종 승인을 별도 기록합니다.

    남는 결과 · 사람의 승인 또는 보류 기록
기준을 만드는 원칙

서비스 입력은 원본 문서와 사람이 확정한 기준입니다. 검사할 이미지·파일명·샘플 정답에서 기대값을 만들지 않습니다. 검색은 해석 근거를 돕고, 전체 검사 기준을 일부 검색 결과로 줄이지 않습니다.

Dense와 BM25를 함께 쓰는 이유

Dense는 의미가 비슷한 표현, BM25는 정확한 상품명·문구처럼 단어가 중요한 경우를 고려합니다. 순위를 RRF로 결합하고 Dense 단독과 같은 조건에서 비교합니다.

검색은 관련 조항을 찾는 수단입니다. 검색된 일부 조항만 검사하고 나머지 확정 조건을 생략하지 않습니다.

LoRA·Reranker는 선택 실험

생성형 LoRA/QLoRA는 기본 LLM 평가 뒤 업무 적합성 개선이 필요할 때 검토합니다. Reranker와 BGE sparse도 품질·지연 개선 근거가 있으면 채택합니다.

직접 학습의 기본 대상은 요청 분류기입니다. 학습 기술을 많이 넣는 것 자체를 완료 목표로 삼지 않습니다.

팀 공통 환경과 모델 확정 조건

Windows·Mac에서 업무 코드를 개발하고 공용 Linux·NVIDIA CUDA 서버의 모델 API를 호출하는 설계입니다. RunPod 또는 팀 GPU 자원을 검토합니다. Mac MLX는 팀 공통 스펙에서 제외했습니다.

로컬 OCR은 실제 CUDA/MPS 사용 가능 여부에 따라 장치를 선택하고, 사용할 수 없거나 실행에 실패하면 CPU 경로와 전환 사유를 기록합니다. Windows·CUDA·Intel Mac 실기는 아직 미검증입니다.

모델 ID·revision·양자화·메모리·동시 요청·응답 지연과 패키지 호환성을 실측한 뒤 버전을 고정합니다. 이 표는 최신 기획 문서의 후보 구성이며 새 호환성 검증 결과가 아닙니다.

설명 포인트

멘토에게는 기술 이름보다 역할을 먼저 설명합니다. 예를 들어 Transformers는 모델을 불러오고 학습·추론하는 라이브러리이고, LangGraph는 업무가 어떤 단계로 이동하는지 관리하는 구성입니다.

읽지 못한 이유와
다음에 할 일을 함께 안내합니다.

접수 검증·문서 파싱·기준 추출·검색 적재를 독립된 4단계로 기록합니다. 한 단계의 완료를 사람의 기준 확정이나 검색 준비 완료로 자동 처리하지 않습니다.

사용자가 만나는 상황화면 안내와 행동다음 단계로 갈 조건
미지원 형식·스캔 문서지원 범위 안내, 텍스트 원본·변환본 재등록지원 가능한 원본에서 필수 범위 판독·출처 검증

실패를 처리하는 기준

문서 판독 실패를 납품 이미지의 미충족 판정으로 만들지 않습니다. 없는 조건을 LLM·검색·샘플로 채우지 않습니다. 전체 판독 실패를 빈 입력 폼으로 우회하지 않습니다.

읽힌 원문을 확인할 수 있는 항목만 보정하며, 원 추출값·보정값·사유·출처·확인자를 보존합니다. 수동 전사·비필수 구간 제외는 미확정 선택 정책입니다.

재처리와 담당 역할

도구 일시 오류는 추가 2회, 검사 근거 불확실성의 에이전트 재검사는 추가 1회를 초기 설계값으로 구분했습니다. 현재 자동 반복은 미구현입니다.

동일 입력 재요청·재개·역할 인계로 한도를 초기화하지 않습니다. R03가 판독·추출 재처리를 요청하고, R06는 운영 복구·인가·예산을 기록해 인계합니다.

상태·ID를 구분하는 기준

검수는 항목 판정, 항목 실행, 전체 실행, 보완 작업, 최종 승인 5개 상태 영역을 사용합니다. 문서 처리 상태는 별도입니다.

항목의 공개 ID는 rule_id, 기대값 변경은 기준 버전으로 관리합니다. 실행에는 당시 기준·이미지 버전과 근거를 연결합니다. 실행 완료는 조건 충족이나 최종 승인을 뜻하지 않습니다.

실제 조건이 없는 문서는 0개 추출 여부를 검토하고, 다른 문서의 유효 기준을 확보했는지 확인할 수 있습니다. 검토되지 않은 0개 추출이나 필수 기준 미확보가 남으면 계속 확정을 차단합니다.

14개 원인별 상세 정의부분 판독 화면 예시공통 문서 처리 계약

설명 포인트

이 항목이 오늘 받은 의견의 주요 반영 내용입니다. 오류 메시지를 보여주는 데서 끝내지 않고 누가 어떤 자료를 준비하고 무엇을 확인해야 차단이 풀리는지까지 설명합니다.
