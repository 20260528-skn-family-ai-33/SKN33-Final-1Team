항목 판정 원칙

실행 실패는 null(미판정). 근거 부족·미실행은 충족 또는 해당 없음으로 바꾸지 않는다. 해당 없음은 적용 제외 근거가 확인된 경우의 후속 지원값이다. 기존 미실행 결과의 확인 필요 표시는 읽기 호환 범위로 유지한다.

항목 실행 상태 원칙

신규 처리 결과는 succeeded로 저장한다. 도구가 반환한 completed는 호환 입력으로 받아 succeeded로 정규화한다. 과거 저장 결과는 원본을 유지하고 화면에서 completed를 실행 완료로 표시한다. run.status의 completed와 별개이며 실행 완료는 조건 충족을 의미하지 않는다.

검수 실행 상태 원칙

전체 실행 완료는 항목 실행 집계이며 최종 승인과 별개다. queued/waiting_human/cancelled는 실제 대기·중단·취소 기능을 구현할 때 추가한다. 완료 결과에 확인 필요 판정이 있다는 이유만으로 waiting_human으로 바꾸지 않는다.

보완 작업 상태 원칙

설계 계약·현재 미구현. 수정본 제출만으로 해결 처리하지 않고 새 검수 결과와 사람의 해결 확인을 기록한다.

최종 승인 상태 원칙

설계 계약·현재 미구현. 최신 기준·납품 버전 및 필수 해결 조건을 확인하고 권한 있는 사람의 결정을 기록한다. 과거 버전의 승인 기록은 보존한다.

전체 항목에서 조건 미충족이 발견돼도 검사 자체가 모두 수행됐다면 run.status는 completed입니다. 보완 작업의 resolved는 해당 작업의 해결이며 최종 approval.status와 별도로 관리합니다.

  • 현재 입력의 rules[].id는 호환 별칭으로 읽고 rule_id로 정규화한다. 두 값이 다르면 거절한다.

  • 기대값 변경은 같은 rule_id와 새 criteria_version을 사용한다. 항목 분할·병합 또는 의미 변경은 새 rule_id를 부여한다.

최초 시도는 추가 횟수에 포함하지 않는다. 도구는 총 3번 시도, 에이전트는 총 2번 검사. 재개·역할 인계 시 카운터를 초기화하지 않는다.

  • 조건 미충족·입력 오류·권한 거절·응답 스키마 오류는 단순 반복 재시도 사유가 아니다.
  • 저장·티켓 생성 등의 쓰기 도구는 멱등성 키와 처리 결과 조회가 갖춰진 뒤 재시도한다. 최종 승인은 자동 반복하지 않는다.
  • 횟수 한도와 별도로 전체 실행의 시간·비용 예산을 적용한다. 구체 운영 한도는 Q03에서 실측 후 확정한다.
  • 미해결 항목은 사람 확인으로 넘긴다. 도구 실행 실패의 판정은 null이며 관찰이 불확실한 정상 실행은 확인 필요로 남긴다.
  • 새 이미지·기준·증빙 버전으로 수정본을 제출하면 새 run을 생성하고 previous_run_id로 연결한다.
  • 하나의 검사 도구를 쓰는 항목 기준 중첩 상한은 검사 2번 × 호출 시도 3번 = 최대 6번이다. 여러 도구의 총 호출·시간·비용은 run 공통 예산을 공유한다.
  • 여러 항목을 함께 검사하는 도구 호출은 하나의 operation_id와 공통 재시도 카운터를 사용한다. rule_ids는 영향 항목 목록이며 항목 수만큼 재시도 예산을 부여하지 않는다.
  • 동시 재개에도 시도 횟수와 전체 실행 예산은 호출 전에 원자적으로 증가시키고 동일 논리 작업의 operation_id를 유지한다.

재처리와 예산

  • 문서 판독은 기준 확정·검수 run 생성 전에도 수행한다. 문서 논리 작업의 안정된 retry_budget_scope + operation_id로 도구 시도를 집계한다. 검수 run에 연결된 도구는 기존 run_id + operation_id 범위·예산을 공유하며 연결·재개로 기시도 횟수를 소거하지 않는다.
  • 도구 자동 재시도는 일시적 통신 오류·과부하·일시 타임아웃에만 추가 2회(총 3번). 문서의 미지원·손상·암호화·형식 위장·상한·권한·스키마·출처 오류는 입력/설정/근거 수정 전 자동 반복하지 않는다.
  • 항목 근거 충돌·판독 불확실성의 에이전트 재검사 추가 1회(총 2번)는 기존 run_id + rule_id 범위다. 문서 LLM 추출 수정이나 문서 재처리 자체를 이 항목 재검사와 동일 단계로 간주하지 않는다.
  • 사용자 다시 처리에는 새 processing_id와 previous_processing_id를 기록하되 같은 입력의 stable scope·operation_id·기시도 횟수·전체 예산을 승계한다. 버튼 재클릭·역할 인계·동일 바이트 재등록으로 자동 한도를 우회하지 않는다.
  • 자동 한도 소진 후 같은 입력의 추가 처리 요청은 원인 확인, 운영 인가, 추가 예산과 기존 이력 연결이 필요하며 새 자동 한도로 초기화하지 않는다. 인가자·사유·예산을 attempt_history에 기록한다.
  • 새 원본 바이트는 새 document_version·input_hash와 새 처리 요청으로 보존한다. 같은 파일명/같은 해시 재등록을 새로운 원본으로 간주하여 예산을 부여하지 않는다.
  • 동일 요청의 중복 재전송은 기존 처리 기록을 반환한다. 동시 처리의 횟수·예산은 호출 전에 원자적으로 집계하며 저장/적재 도구는 멱등성 키와 결과 조회 후 재시도한다.
  • Q03에서 파일·페이지·시간·비용 운영 한도를 실측 후 확정한다. 현재 자동 반복은 미구현이고 추가 반복 0회다.

기준 확정의 차단·해제 조건

  • 필수 문서의 판독/추출 진행 중, 미판독 범위, 구조화 출력/출처 미검증, 검토되지 않은 0개 추출, 필수 질문·충돌·모호함이 남으면 서버에서 기준 확정을 차단한다.
  • 읽힌 원문 대조에 한해 추출값·단위·출처·누락 보정을 설계한다. 원 추출값·보정값·사유·문서 버전·원문 위치·확인자·시각을 보존한다. 이 보정 UI는 현재 미구현이다.
  • 전체 판독 실패를 빈 입력 폼으로 우회하지 않는다. 모호하거나 미판독인 구간을 LLM/검색/데모 조건으로 채우지 않는다. 원문 밖 조건은 추가 근거/변경 요청으로 분리한다.
  • 차단 해제에는 표의 코드별 해소 근거와 필수 범위·출처·질문 해소를 함께 재검증한다. 완료 표시만으로 차단을 해제하지 않는다.
  • 수동 전사와 비필수 자료/구간 제외는 선택·미확정 정책이다. 기본 복구는 지원 원본의 새 버전 등록이며 팀 정책 확정 전에는 전사/제외로 필수 차단을 면제하지 않는다.
  • 검색 적재 실패 자체를 기준 파싱 실패로 바꾸지 않는다. 검증된 원문·출처로 기준 확정 요건을 충족하는지 별도로 확인하며 준비되지 않은 인덱스의 검색 사용은 차단한다.
  • 문서 처리 실패·미지원·미확정은 납품물 미충족 판정을 만들지 않는다. 기준 확정 차단과 Q08의 최종 승인·예외 승인 정책을 구분한다.

오류 레코드

code · stage · stage_status · cause · user_message · affected_units · cta · retryable · retry_conditions · confirmation_release_conditions · design_status · implemented

  • error_catalog[].stage는 오류의 대표 단계다. allowed_stages가 있으면 그 목록을 실제 검출 단계의 허용 범위로 사용하며, 없는 다른 오류는 대표 단계 하나만 허용한다.
  • 처리 레코드 errors[].stage는 해당 오류를 최초 검출한 실제 단계로 기록하고 카탈로그의 허용 단계와 검증한다. DOC_CORRUPT는 intake_validation 또는 parsing에서 검출할 수 있다.
  • allowed_stages는 오류 카탈로그의 검증값이며 개별 처리 레코드 errors[]에 복제하지 않는다. stage_status는 실제 검출 단계의 상태와 함께 기록한다.

미확정 선택 정책

  • 원문 대조 수동 전사의 허용 범위·권한·완료 증거
  • 비필수 자료/구간 제외의 허용 여부·근거·확인 권한

기능별 복구 정의 · 기존 시험 ID에 연결한 복구 시험 계획 · 역할별 처리 권한 제안

기존 기록과 현재 지원 범위를 보존합니다.

  • 기준 원본 파일의 바이트를 바꾸지 않아 기존 해시와 확정 버전을 유지합니다.
  • id와 rule_id 입력을 함께 받을 때 값이 다르면 거절하고, 동일 기준의 중복 rule_id도 거절합니다.
  • 과거 저장 결과의 completed는 원본을 보존하고 실행 완료로 표시합니다. 신규 처리 결과는 succeeded로 정규화해 저장하며 전체 run의 completed는 그대로 유지합니다.
  • 기존 미실행 결과의 확인 필요 판정은 호환 범위로 보존하고 항목 실행 상태를 함께 표시합니다.
  • 자동 반복, 사람 대기·취소, 보완 작업·최종 승인, 해당 없음 판정은 해당 기능 구현과 시험을 거친 뒤 지원합니다.
  • 과거 v1/v2 문서는 당시 기록으로 보존하고 최신 정의는 이 계약과 종류별 문서에서 확인합니다.

숫자 범위 표시

숫자 범위는 4–6개, 1–2회처럼 표시합니다. HTML 생성 이전의 원문 단계부터 이 기호를 사용해 Markdown 취소선 오변환을 피합니다.

공통 원본과 재생성

공통 계약 JSON을 원본으로 관리합니다. 원본 변경 후 관련 정의서와 공통 계약 HTML을 아래 명령으로 다시 생성합니다.

python scripts/sync_contract_docs.py
python scripts/build_contract_standard.py

문서 간 ID·상태·반복 정책이 충돌하면 공통 계약을 기준으로 개별 설명을 수정합니다. 실제 코드의 지원 범위와 설계 제안을 별도 표기합니다.
