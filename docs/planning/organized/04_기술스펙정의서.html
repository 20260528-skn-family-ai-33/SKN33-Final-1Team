목표 구성·책임

PostgreSQL은 업무 원천, Neo4j는 재구축 가능한 관계 저장소입니다. React는 FastAPI를 호출하고, worker는 기준 전체와 관계 문맥으로 검사를 수행합니다. 모델과 그래프는 사람의 승인을 대신하지 않습니다.

관계 원본·동기화

PG 업무 확정과 Neo4j 반영을 직접 이중 쓰기하지 않습니다. PG의 한 트랜잭션에서 기준/정책 원본과 outbox를 기록하고 별도 반영 worker가 순서·멱등성을 보장한 뒤 해당 투영을 ready로 표시하는 목표입니다.

단계/상황처리 규칙검증
원본·초안추출 관계는 검토 전 후보. 출처·적용 조건을 봉인 전에 저장문서 전체 조건 누락·잘못된 원문·오류 관계를 확인
업무 확정불변 기준/정책+반영 작업 원자적 기록PG 성공/관계 미준비 상태를 분리
투영원천 ID·개정·해시로 중복·역순 이벤트 처리과거 개정 덮어쓰기·중복 관계 없음
완료 기록 실패Neo4j 반영 후 PG ready 기록 실패 시 동일 작업 재처리효과 중복 없이 실제 반영 버전 대조
조회PG 현재 권한+동일 기준/정책+투영 ready 확인구버전·다른 프로젝트·미승인 관계 사용 차단
빈 결과/잘림정상 빈 예외와 오류·미준비·반환량 제한을 분리불완전 조회로 자동 통과·영향 없음 판정 금지
복원PG 관계 원본·파일·manifest로 Neo4j 재생성ID·경로·건수·해시 일치 후 ready

목표 관계는 프로젝트→기준 버전→기준 항목→원문 구간/문서 버전, 기준→매체/예외/의존 기준, 실행→사용 기준/근거입니다. 실제 추가 PG 테이블·Neo4j 라벨·인덱스 수는 아직 확정하지 않았습니다.

예외 승인 허용 자체는 팀 결정 항목입니다. 허용 시 승인자·사유·대상 버전·유효기간·취소·출처를 별도 보존하며 기계 판정을 덮어쓰지 않습니다.

상태·재시도·캐시

상황처리구분
동일 요청 재전송같은 idempotency_key·내용은 기존 실행 반환, 다른 내용은 충돌현재 일부 업무 경로의 멱등성을 전체 업로드/초안까지 확대 주장하지 않음
worker 장애 재시도같은 run의 새 attempt, lease·heartbeat·token 검증현재 v1 safe_retry=not_dispatched_only_v1. 외부 추론을 무조건 재전송하지 않음
사용자 명시 재검수새 run 생성, retry_of_run_id 연결기존 run의 단순 attempt 증가와 다름
수정본/기준 변경새 입력/기준 버전·새 run·이전 요청 연결과거 결과·승인 보존, 새 버전 자동 승계 없음
취소요청과 실제 종료 상태 분리, 늦은 결과 fencingUI 취소만으로 GPU 프로세스 종료 주장 금지
부분 실패조건별 결과·실패·미지원·미관측 보존completed와 pass/fail/review·사람 승인 분리
캐시입력/권한 범위·기준·모델·프롬프트·전처리·스키마·샘플링 버전 포함실패를 정상 캐시로 재사용하지 않음

LangGraph checkpoint는 재개 상태, PG run/attempt는 업무 실행·소유권, 승인 이력은 사람의 확정 기록입니다. 각각의 책임과 commit 경계를 정한 뒤 연결합니다. worker 설정이 바뀌면 기존 queued 작업과의 호환 또는 drain 정책이 필요합니다.

영상의 관측 프레임/시각·누락 구간을 기록하고 부분 샘플만으로 연속 노출 조건을 확정하지 않습니다. 긴 영상의 큐 독점, GPU 동시성, 재개 시 중복 유료 호출, 취소 정책은 팀 결정과 실행 검증이 필요합니다.
