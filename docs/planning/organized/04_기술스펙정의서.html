현재 시제품의 호출 흐름

React 입력·기준 편집·확정
  → FastAPI multipart 검수 요청 → 로컬 JSON·이미지 저장
  → BackgroundTasks → OCR·행사 정보 추출·규칙 판정
  → JSON 결과 저장 → React 진행 조회·문구·근거 박스 표시

기준 확정은 브라우저 상태의 정수 버전과 스냅샷입니다. 서버가 프로젝트별 불변 기준 버전을 발급하는 기능은 아직 없습니다. 재실행은 새 UUID를 만들며 이전 실행과 자동 연결하지 않습니다.

확장 구조 · 미구현 설계

React → FastAPI → PostgreSQL (계정·프로젝트·기준·작업·이력)
                   ↘ 파일 저장소 (원본·표시 이미지·근거)
독립 Python worker ↔ PostgreSQL 작업·시도 기록
  → OCR 모듈 / 후속 LLM·RAG·시각 도구
  → 결과 검증·판정·저장 → 사람 검토·수정 요청·전체 재검수·최종 승인

현재 Paddle 모델 하위 프로세스는 영속 worker가 아닙니다. 목표 worker는 작업 인수·lease·재시작 복구를 새로 구현하며, OCR 모듈이 업무 DB를 직접 갱신하지 않도록 합니다. 목표에서는 무거운 모델 로딩을 웹 프로세스와 분리합니다.

현재 API와 후속 업무 API의 경계

현재 경로 동작
GET /api/v1/auth/csrf · GET /api/v1/auth/me 임시 세션 준비·현재 로그인 상태
POST /api/v1/auth/login · POST /api/v1/auth/logout 임시 로그인·로그아웃과 CSRF 검사
GET /api/health · GET /api/sample · GET /api/sample/image 준비 상태와 김천 샘플

GET /api/reviews/{id} · GET /api/reviews/{id}/image 진행·결과와 표시 이미지 조회

프로젝트·서버 기준 버전·이력·재시도용 /api/v1/... 업무 경로는 구조 명세의 후속 계약입니다. 현재 auth 경로와 같은 접두사를 쓴다고 구현 완료로 해석하지 않습니다.

MCP 도구 영역 · 목표 설계

영역 도구 책임 주 사용 역할
Knowledge 문서·버전·원문 조회, Dense·BM25 검색, 출처 확인 A02 · A03 · A06
Inspection 문서·이미지 OCR, 영역 추출, 시각 관찰, 문자·날짜·수치 대조 A02 · A04 · A05

영역은 책임 구분이며 현재 MCP 서버 배포나 도구 실호출 완료를 뜻하지 않습니다. LangGraph는 협업 흐름, MCP는 도구 호출 규약을 담당하도록 설계합니다. 초기에는 하나의 서버에 영역별 도구를 묶는 방안도 검토합니다.

8개 역할의 입출력과 협업

A01~A08은 판단·도구 선택·근거 전달·예외 처리를 담당하는 목표 설계이며 현재 자동 협업은 미구현입니다. 개발팀 A~E 또는 사용자 권한과는 별개입니다. 역할 이름을 나열하거나 일반 함수를 순서대로 호출하는 것만으로 다중 에이전트 협업 완료를 주장하지 않습니다.

A01 업무 총괄 · A02 문서·기준 분석 · A03 근거 검색 · A04 문구 검수 · A05 시각 요소 검수 · A06 근거·결과 검증 · A07 보고서 작성 · A08 수정·재검수 관리

실행 계약 내용

판단 신규 검수·재검수·기준 변경·상태 조회·기타의 5종 요청을 구분합니다. 정보가 모자라거나 여러 의도가 섞였으면 먼저 확인합니다.
출력 업무 유형, 실행할 단계, 담당 에이전트, 추가 확인 질문
전달·다음 단계 신규 작업은 A02로, 확정 기준이 있는 재검수는 A04·A05로 연결합니다. 위임·상태 전이는 LangGraph가 수행합니다.
예외·경계 분류 결과만으로 승인·기준 변경을 실행하지 않습니다. 불명확한 요청은 사람 확인으로 보냅니다.

실행 전 준비 상태 검사

run.sh·run.cmd는 공통 start.py에서 프로젝트 Python 3.12 가상환경, 선택 경로의 import·모델, React 빌드와 참조 파일을 검사합니다. 누락 항목과 설치 명령을 모아 안내하고 서버 실행을 중단합니다. 설치·다운로드는 자동 수행하지 않습니다. 정상 빌드가 있으면 Node.js·npm 없이 실행할 수 있습니다. 

OCR_PIPELINE=paddle-only ./run.sh --check-only
OCR_PIPELINE=paddle-only ./run.sh

--check-only는 준비 완료 0, 준비 부족 1을 반환합니다. pip만 없고 실행은 준비됐으면 복구 안내 후 실행하며, 패키지 설치가 필요하면 ensurepip 복구부터 안내합니다. Windows 설정·모델 준비는 실행가이드와 Paddle 단독 보고서를 따릅니다.

항목 ID와 API 호환

현재 시제품은 요청의 기준 id와 결과 criterion_id를 사용합니다. 과거 문서의 rule_id는 목표 논리 항목 키로 해석하며, 기존 API가 이미 이 이름으로 통일됐다고 가정하지 않습니다. 같은 기준의 값만 바뀌면 논리 키를 유지하고 새 기준 버전을 만들며, 항목을 분할·병합하거나 의미를 바꾸면 새 키를 부여하는 방안을 검증합니다.

API 필드 개편 시에는 React·FastAPI·worker의 스키마와 변환 테스트를 함께 변경합니다. 실제 서버 UUID·숫자 버전과 사람이 표시하는 v1을 구분하고, 서로 다른 프로젝트의 같은 항목 키를 전역 고유 키로 사용하지 않습니다.

원본·표시 이미지·OCR 좌표

  1. 현재 업로드는 실제 JPEG·PNG·WEBP 정지 이미지, 20MiB 이하, 1,000만 픽셀 이하, 한 변 8,192px 이하를 검사합니다.
  2. 원본 바이트·해시는 보존하고 EXIF 방향 적용·투명 영역 흰색 합성·RGB 변환한 표시 이미지를 분리합니다.
  3. OCR 입력 RGB 2배의 좌표는 표시 이미지 좌표로 한 번만 복원합니다. API·React에서 중복 보정하지 않습니다.
  4. 목표 저장 구조에서는 원본·표시 해시, 크기, 전처리·엔진·추출 버전을 실행에 연결합니다.

검색과 전체 기준 검사

  • 문서 전체에서 조건을 추출하고 사람이 누락·모호함을 확인해 확정합니다. 현재 직접 입력·줄 단위 정리와 별개의 후속 구현입니다.
  • 확정된 적용 조건 전체를 검사합니다. 검색 top-k를 전체 체크리스트로 대체하지 않습니다.
  • RAG는 조건의 원문·예외·업무 근거를 찾습니다. 프로젝트·권한·적용 문서 버전으로 먼저 범위를 제한합니다.
  • BAAI/bge-m3 Dense와 한국어 BM25를 RRF로 결합하고 Recall@5·MRR·Ragas를 측정합니다. 정답키·평가 답·이 기획서를 서비스 RAG 입력에 넣지 않습니다.
  • PostgreSQL에 인덱싱 작업·버전·청크를 기록하고 완료한 버전만 검색에 노출합니다. PostgreSQL과 Qdrant가 동시에 원자적으로 갱신된다고 가정하지 않습니다.
  • 작업 키·원문·설정 버전으로 재시도·재구축하고 중복 청크·미완료 버전·다른 프로젝트 근거 혼입을 시험합니다.

현재 실패·재실행·판정 정책

  • 서버가 재시작되면 남아 있는 queued/running JSON은 중단 사유와 함께 failed로 변경됩니다. 자동 복구 큐가 아닙니다.
  • “같은 기준으로 재시도”는 새 검수 ID를 생성합니다. 과거 결과와 자동 이력 관계를 연결하는 기능은 후속 구현입니다.
  • 검수 완료 결과의 review는 근거가 부족해 자동 판단을 보류한 상태이며 실행 실패와 다릅니다.
  • 현재 김천시 로고 조건은 OCR의 “김천시” 문구를 근거로 충족시키는 임시 logo_text_proxy 정책입니다. 심벌의 동일성·색상·배치는 검사하지 않습니다.
  • 잘림은 자동 시각 판정 미구현으로 확인 필요입니다. 후속 평가 범위는 문구·필수 요소이며 장식의 의도적인 잘림은 허용합니다.

영속 worker와 멱등성 · 목표

  • FastAPI는 작업·첫 이벤트를 짧은 DB 트랜잭션으로 저장하고 반환합니다. 별도 worker가 queued 행을 인수하며 attempt와 lease를 기록합니다.
  • SELECT ... FOR UPDATE SKIP LOCKED 방식의 인수를 검토합니다. OCR·원격 응답 대기 중에 DB 잠금·트랜잭션을 계속 유지하지 않습니다.
  • lease 만료·프로세스 중단·부분 저장 후 재개를 시험하고 같은 입력·멱등키에는 기존 결과를 반환합니다. 같은 키·다른 입력은 충돌로 거절합니다.
  • 입력·기준 버전 변경은 새 실행이며, 같은 입력의 일시적 오류 재시도와 구분합니다. 목표 연결 필드의 retry_of / previous_run_id 표기는 API 확장 시 하나로 확정합니다.
  • 과거 JSON 이력 이전은 별도 dry-run으로 형식·해시·귀속 프로젝트를 확인한 후 수행합니다. 시작 시 자동 이전하거나 삭제하지 않습니다.

인증·권한·승인 · 단계별 적용

현재 localhost용 admin 로그인은 실제 계정 시스템이나 검수 API 접근 통제를 대신하지 않습니다. 운영 인증은 FastAPI의 쿠키 세션 + CSRF를 목표로 하며 비밀번호 해시·DB 세션·만료·폐기·멤버십·권한을 별도로 구현합니다.

  • 로그인 자체를 포함한 변경 요청에 CSRF 검사를 적용하고 운영 HTTPS에서는 Secure·HttpOnly·적절한 SameSite 설정을 검증합니다.
  • 최종 승인 직전에 권한·최신 기준·파일 해시·검수 실행·보고서와 미해결 필수 항목을 서버에서 확인합니다. 오래된 버전 요청은 거절하고 승인·이력을 원자적으로 기록합니다.
  • 기준 확정·수정 요청·수정 확인·최종 승인은 사람의 명시적 조치로 남깁니다. A01~A08이 승인 권한을 가지는 구조가 아닙니다.
  • 자료 속 지시문은 기준·권한·외부 전송·승인 변경 지시로 처리하지 않습니다. 실제 문서·RAG 도입 시 입력 격리와 허용 도구 범위를 검증합니다.
  • 외부 모델 전송은 승인 범위·파일 해시·제공자·철회를 확인하는 후속 계약입니다. API 키·비밀번호·세션 비밀·불필요한 원문과 비공개 이미지는 화면·로그·저장소에 노출하지 않습니다.

현재 입력 제한·진행·실패 표시와 후속 취소·비용 예산·운영 보존 정책을 혼동하지 않습니다. 외부 연동·LLM 배포·최종 승인 기능의 완료 기준은 실제 통합 테스트와 권한·버전 충돌 증거로 확인합니다.

현재 결과는 사람 미승인 라벨로 조정용 5장을 각 1회 실행한 개발 실험입니다. holdout 3장은 미평가이고 위반 기준도 1개뿐입니다. 오통과 0/1을 일반적인 안전성·위반 탐지 보장으로 해석하지 않습니다. 18장 가상 광고·200파일 수집량·자동 테스트 수는 이 평가 분모와 별도입니다.
