R01 상세 권한·시험 보기 · R01 원 요구사항 찾기

목적: 광고 제작 요구사항과 실제 사용 계획을 전달하고, 발주 진행 상태와 검수 결과를 확인한다.

기능 사용자 행동 결과 기존 기능
발주 생성·조회 제목, 담당자, 납기, 목적을 입력하고 본인에게 허용된 발주를 조회한다 고유 발주 ID, 상세 정보, 진행 상태 F-01
기준 문서 등록·추출 요청 계약·요구사항 문서를 발주에 등록한다 원문 위치가 연결된 기준 초안과 확인 질문 F-02, F-04

기준·보고서 확인 확정 기준, 검사 결과, 근거, 미검사·미해결 항목을 확인한다 현재 버전의 검수 결과와 보고서 F-03 조회, F-09
보고서 다운로드 내보내기 권한이 있는 경우 현재 보고서를 내려받는다 대상 버전과 생성 시각이 포함된 Markdown F-16

배정 제안: 원문에서 검수 담당자에게 배정된 발주 등록·기준 문서 제공·사용 계획 입력을 발주자에게도 부여한다. 보고서 내보내기 역시 권한 기반으로 확대하는 제안이다.

판독 실패 원본은 R01이 읽을 수 있는 파일로 재등록한다. 허용된 자료를 맡은 R02·R03도 해당 제출 권한 범위에서 재등록한다. 상세 차단·복구 조건은 02 문서 판독 복구 정의를 따른다.

권한: 배정된 발주의 제출·수정본 등록과 허용된 결과 조회. 기준 확정, 본인이 처리한 작업의 검수상 해결 확인, 최종 승인은 해당 역할 권한이 별도로 있어야 한다.

4. R03 — 검수 담당자

R03 상세 권한·시험 보기 · R03 원 요구사항 찾기

기능 사용자 행동 결과 기존 기능

기준 초안 검토·확정 추출값과 원문을 대조하고 보정값·사유를 기록한 뒤 확정한다 확정자·시각·버전이 있는 기준 F-03
검수 실행·재시도 확정 기준과 납품 버전을 선택해 검사한다. 재개·자동 반복은 설계 범위이며 현재 미구현이다 실행 상태, 검사 결과, 오류·시도 기록 F-05, F-06, F-08, F-15, S-01
제품 원본 비교 제공 제품 원본과 납품 이미지의 차이를 확인한다 변화 후보, 비교 영역과 한계 F-17

결과·보고서 검토 항목 판정, 실행 상태, 원문·이미지 영역·근거를 확인한다 검토한 보고서와 미해결 항목 F-09, F-16
보완 요청 확정 AI 초안을 수정하고 담당자·기한·완료 조건을 확정한다 내부 작업함의 보완 작업 F-10
재검수·해결 확인 변경 영향에 따른 검사와 신규 문제 검사를 진행하고 해결 여부를 확인한다 새 실행 결과, 지적별 해결 기록 F-11

입력: 기준 초안, 원문, 납품 묶음, 증빙, 사용 계획, 이전 결과·보완 요청.
출력: 확정 기준, 검수 보고서, 보완 작업, 재검수 결과와 해결 기록.
권한: 담당 발주의 기준 확정·검수 실행·보완 요청 확정·재검수. 최종 승인은 R05 권한을 별도로 부여받은 경우에만 가능하다.

완료 기준: 필수 충돌이 남으면 기준 확정을 차단한다. 확정된 적용 기준 전체를 검사 대상에 포함하며, 검색 상위 결과만으로 범위를 줄이지 않는다. 정상 실행의 판독 불확실성은 확인 필요, 도구 오류는 항목 실행 실패(execution_status=failed)·미판정(verdict=null)으로 구분한다. 보완 요청은 확인된 근거와 연결하고, 요청 확정자는 사람으로 기록한다.

추가 제안: 권리 관계·계약 해석·공식 근거 적용이 모호한 항목을 R04에게 배정하는 전문 검토 요청 기능. 원문에는 독립된 전문 검토 배정·작업함 기능이 명시되어 있지 않다.

R03의 판독 재처리, 원문 대조 보정, 기준 확정은 각각의 권한·버전·예산을 확인한다. 필수 미판독 범위가 남으면 확정을 차단하며, 전체 판독 실패를 빈 폼으로 우회하지 않는다. 원문에 없는 조건은 변경 요청·추가 근거로 분리한다. 수동 전사·비필수 제외는 선택 정책·미확정이다.

9. 역할별 요구사항·권한 명세 — 제안

10. 사용자 간 업무 흐름과 공통 기준

아래는 최종 서비스의 목표 흐름이다. 현재 가능한 범위는 상단 구현 요약과 기능별 구현 범위에서 확인한다.

  1. 발주자가 발주, 기준 문서, 사용 계획을 등록한다.
  2. 시스템이 명세서·계약서에서 출처와 연결된 기준 초안을 추출하고, 검수 담당자가 원문과 대조하여 확정한다. 직접 입력을 최초 기준 생성의 기본 경로로 두지 않는다. 현재는 미리 작성한 JSON 기준을 읽으며 문서 자동 추출은 미구현이다.
  3. 제작자가 납품 이미지·원본·작업 이력·AI 신고·소재 증빙을 제출한다.
  4. 검수 담당자가 검수를 실행하고 결과·근거·미검사 항목을 확인한다.
  5. 전문 검토가 필요한 항목은 법률·권리 검토자에게 배정한다. R04 역할과 이 배정·의견 등록 과정은 선택 확장·미구현이다.
  6. 검수 담당자가 보완 요청을 확정하고, 제작자가 수정본·추가 증빙을 제출한다.
  7. 검수 담당자가 재검수를 진행하여 해결 여부를 확인한다. 배정된 전문 검토가 있으면 해당 범위의 재검토를 연결한다.
  8. 최종 승인자가 최신 기준·납품·결과와 필수 해결 조건을 확인하여 승인 또는 보류한다.
  9. 관리자는 전 과정의 권한·실행 환경·장애·한도·보존 정책을 운영한다.

상태 표시 — 공통 실행 계약 v1

판정, 항목 실행, 전체 실행, 보완 작업, 최종 승인은 아래 5개 도메인으로 표시한다. 전체 실행 완료와 조건 충족, 사람의 최종 승인은 각각 다른 의미다.

대상·필드표준 값·표시현재 범위·해석
항목 판정
verdict		충족 (충족) / 미충족 (미충족) / 확인 필요 (확인 필요) / null (미판정)현재 지원
실행 실패는 null(미판정). 근거 부족·미실행은 충족 또는 해당 없음으로 바꾸지 않는다. 해당 없음은 적용 제외 근거가 확인된 경우의 후속 지원값이다. 기존 미실행 결과의 확인 필요 표시는 읽기 호환 범위로 유지한다.
항목 실행 상태
execution_status		succeeded (실행 완료) / failed (실행 실패) / not_run (미실행)현재 지원
신규 처리 결과는 succeeded로 저장한다. 도구가 반환한 completed는 호환 입력으로 받아 succeeded로 정규화한다. 과거 저장 결과는 원본을 유지하고 화면에서 completed를 실행 완료로 표시한다. run.status의 completed와 별개이며 실행 완료는 조건 충족을 의미하지 않는다.
검수 실행 상태
run.status		running (실행 중) / completed (전체 실행 완료) / partial (부분 실행 완료) / failed (실행 실패)현재 지원
전체 실행 완료는 항목 실행 집계이며 최종 승인과 별개다. queued/waiting_human/cancelled는 실제 대기·중단·취소 기능을 구현할 때 추가한다. 완료 결과에 확인 필요 판정이 있다는 이유만으로 waiting_human으로 바꾸지 않는다.
보완 작업 상태
task.status		draft (초안) / confirmed (요청 확정) / submitted (수정본 제출) / resolved (해결)설계·미구현
설계 계약·현재 미구현. 수정본 제출만으로 해결 처리하지 않고 새 검수 결과와 사람의 해결 확인을 기록한다.
최종 승인 상태
approval.status		pending (승인 대기) / approved (승인) / on_hold (보류)설계·미구현
설계 계약·현재 미구현. 최신 기준·납품 버전 및 필수 해결 조건을 확인하고 권한 있는 사람의 결정을 기록한다. 과거 버전의 승인 기록은 보존한다.

후속 지원값: 판정의 해당 없음, 검수 실행의 queued(실행 대기)·waiting_human(사람 확인 대기)·cancelled(취소 완료)는 현재 미지원이다. 기준 초안·확정과 L-01 전문 검토의 단계는 업무 설계이며 위 5개 실행 상태와 섞지 않는다.

표시 예: OCR이 정상 실행되어 브랜드 불일치를 찾으면 execution_status=succeeded + verdict=미충족이다. OCR 실행 오류는 failed + null(미판정)이다. 현재 개수·외관 미실행 항목의 not_run + 확인 필요 표시는 호환 범위이며, 미실행을 충족으로 처리하지 않는다. 일부 항목만 실행한 검수는 run.status=partial로 표시한다.
