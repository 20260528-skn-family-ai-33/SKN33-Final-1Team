설계 변경과 범위

  • 자체 생성형 LLM·sLLM 파인튜닝은 주제 1 필수에서 제외하고, 요청 분류 모델 직접 학습을 우선한다.
  • MySQL 이전을 실제 LLM 연결의 선행 조건에서 뺀다. 저장 계약을 먼저 고정하고 기존 SQLite로 첫 흐름을 검증한다.
  • 중간까지 검색 실험 5종 대신 Dense와 한 가지 Hybrid 비교를 우선한다. 재정렬 모델은 최종 단계 선택 항목이다.
  • v1의 제작 출처·사용 근거 검토 역할은 확장 범위로 보존한다. 초기 A03은 관찰·판정의 근거 검증을 맡는다. 기존 69개 요구사항을 삭제하거나 충족 처리하지 않는다.
  • 내부 데모 업무 티켓 서비스를 MCP로 연동해 보완 업무를 증명한다. 외부 SaaS 연동으로 표현하지 않으며 기관이 특정 외부 시스템을 요구하는지는 확인 사항이다.

기술별 역할과 데이터의 기준

GPU 학습·추론은 RunPod/로컬 CUDA, Mac은 검증된 MLX/MPS 경로를 고려한다. 메모리·동시 적재·응답시간은 실측 전이다. DB·파일·체크포인트는 지속 보관한다.

결과를 신뢰하기 위한 규칙

  • 확정 기준 버전의 적용 항목 전체를 DB에서 읽는다. 검색 top-k를 검수 체크리스트로 사용하지 않는다.
  • 기준 초안 추출은 문서 전체를 조항 단위로 순회하고 누락 검토 후 사람이 확정한다.
  • RAG는 기준·예외의 근거 조회와 설명을 지원한다. 프로젝트·문서 버전을 검색 전 필터링한다.
  • 미실행·실패·확인필요를 통과와 구분한다. 필수 항목이 남으면 자동 최종 승인하지 않는다.
  • 재검수는 새 이미지/기준 버전과 새 run으로 저장하고 과거 보고서를 보존한다.
  • 정답키·평가 문항 정답·이 기획서는 서비스 RAG 입력에 넣지 않는다.
  • 모델/프롬프트/검색 설정 버전과 실제 입력·출력을 기록한다. 생성 모델의 자기평가만으로 성능을 확정하지 않는다.
  • MCP는 도구 연결, LangGraph는 실행 흐름을 맡는다. 해시 계산·저장·숫자 비교는 일반 코드 단계다.
