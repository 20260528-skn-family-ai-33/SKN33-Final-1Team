01. 기준 문서와 적용 범위

정본은 프로젝트 통합문서 20261102 정리본이다. 10/30 역할 결정과 11/02 정정을 반영한다. 독립 A03 검색·근거 에이전트는 폐기하고 A04·A05는 동일 Qwen3.5-4B를 사용하는 통합 검사로 연결한다. 별도 OCR 주·보조·fallback, VectorDB·임베딩·벡터 인덱스는 포함하지 않는다.

첫 제품 연결 범위는 PDF 한 개와 포스터다. 최신 통합문서의 최종 제품 범위에는 숏폼 영상도 포함되지만 이 프레임워크 단계에서 영상·DOCX/HWPX 처리를 모두 구현하지 않는다. 데스크톱 front-v2 디자인을 유지한다. 기존 업로드·DB·사용자·프로젝트·인증·권한을 재사용한다.

이전 계획의 A03 담당·RetrieveRequest·retriever factory·A03부터 재검수 표기는 이번 문서로 대체한다. 검색 보조 기능의 유지는 폐기된 에이전트를 다시 만들라는 뜻이 아니다.

04. 근거·관계 조회와 RAG의 위치

최신 통합문서 13.2에서 채택한 조회 순서는 PostgreSQL → Neo4j → PostgreSQL → 근거 묶음 고정이다. 이를 검사 전 공통 문맥 준비 기능으로 둔다.

  1. PostgreSQL에서 현재 사용자·프로젝트 권한, 승인 기준 전체, 문서·산출물 버전과 원문을 확인한다.
  2. Neo4j에서 동일 범위의 조건·원문·승인 예외·수정 이력 관계를 탐색한다. 관계는 원본을 가리키는 연결이며 권한의 정본이 아니다.
  3. 반환된 원본 ID를 PostgreSQL에서 다시 읽어 권한·현재 버전·예외 효력·범위를 검증한다.
  4. 허용된 근거와 문맥·조회 정책·revision·한계·인용을 고정해 검사와 보고 입력으로 전달한다.

승인 조건 전체가 검사 대상이다. 검색 top-k로 조건을 제외하거나 과거 판정으로 현재 관측을 대신하지 않는다. 외부 자료 안의 명령문은 자료이며 실행 권한·시스템 규칙·승인 정책을 바꾸지 못한다.

근거는 현재 요구조건, 승인 예외, 과거 문맥을 구분한다. 다른 프로젝트·문서·산출물 버전, 만료·철회된 예외, 존재하지 않는 인용·변조 해시는 거부한다. empty·stale·unavailable과 조회 실패를 정상 검색 성공으로 숨기지 않는다. DB 장애를 창작물 위반으로 판단하지 않는다. SQL fallback과 Neo4j projection/outbox의 동등성·순서·재시도 정책은 실제 연결 시 별도로 확정하고 검증한다.

현재 구현의 freeze_approved_context는 승인 조건에 이미 포함된 출처를 복사하는 순수 함수다. PostgreSQL·Neo4j 조회를 실행하지 않는다. EvidenceBundle.status=complete와 warnings는 승인 기준 출처 묶음의 범위를 나타낸다. 실제 관계 조회·RAG가 완성됐다는 뜻이 아니다. 후속 조회 서비스는 이 고정 경계를 확장하되 독립 A03 역할·factory·worker 단계로 되살리지 않는다.

06. 영속 실행 구조

API는 기존 세션·CSRF·프로젝트 권한을 확인해 접수·조회·승인만 처리한다. 역할 factory는 독립 worker가 초기화한다. 기존 OCR leader·worker와 다른 프레임워크 실행 경로를 사용한다. 기존 front-v2를 다시 만들지 않는다.

첫 phase는 A02다. 기준 승인 시 승인 기록·기준 출처 묶음·검수 작업을 함께 저장한다. 다음 phase는 A04_A05 → A06 → A07이다. A03 작업이나 숨은 검색 역할 단계는 없다. 각 역할의 입력 해시·출력·상태·시각·소요 시간·오류와 승인 기록을 PostgreSQL에 보존한다.

완료 단계는 동일 입력·설정·코드 revision에서만 재사용한다. worker는 모델 호출 중 DB 트랜잭션을 잡지 않는다. lease·heartbeat·fencing token·현재 권한 재확인으로 중복 선점과 오래된 결과 반영을 막는다. 호출 여부가 불명확하면 outcome_unknown으로 끝내고 자동 중복 호출하지 않는다. LangGraph checkpoint와 업무 DB가 자동으로 한 트랜잭션이라고 가정하지 않는다.

승인 대기는 worker lease를 유지하지 않는다. 같은 승인·수정본 접수는 멱등 처리하고 다른 내용의 충돌은 거부한다. 최종 승인과 실행 완료·모델 pass는 서로 다른 상태다.

AF001은 기존 public M008 스키마를 보존하는 추가 스키마다. 자동 마이그레이션하지 않는다. 미배포 개발 AF001에서 A03 허용 역할을 제거했다. 이전 해시를 이미 적용한 환경은 명시적인 후속 마이그레이션과 저장 실행 처리 정책이 필요하며 readiness 검사를 우회하지 않는다.

07. 버전·권한·계약 전환

문서·기준·산출물·설정·공통 코드 revision·근거 문맥을 실행별로 고정한다. 실제 모델 담당자는 모델·프롬프트·전처리·timeout을 추가로 기록한다. 승인 대상은 해당 실행·기준·산출물 버전이다.

계약은 1.0.0에서 2.0.0으로 변경한다. A03 설정 키·RetrieveRequest·retriever port/factory를 제거했고 EvidenceBundle의 retrieval_id는 context_id로 변경한다. 이전 JSON·설정은 새 template과 fixture로 교체한다. 저장된 구버전 실행을 임의 변환하거나 새 코드로 자동 재개하지 않는다. HTTP 경로 /api/framework/v1은 별개 버전이다.

API의 actor_id가 로그인 증거를 대신하지 않는다. worker도 현재 계정·프로젝트 접근을 재확인한다. 파일 전체 SHA-256과 인용문 해시를 혼동하지 않는다. raw 공급자 응답·원문·비밀번호를 오류 로그나 공유 fixture에 넣지 않는다.

09. 검증과 아직 확인하지 않은 범위

회귀는 계약·파일 해시·인용·조건 누락·관측 불확실·다른 버전·승인 분기·재검수·중복·호출 결과 불명을 확인한다. 폐기한 역할의 설정/CLI 거부와 기준 승인 시 입력 고정을 직접 검사한다. PostgreSQL 시험은 임시 전용 DB에서 실행·단계·승인 저장과 worker 복구를 확인한다.

실제 모델 평가에서는 조건 추출 완전성·위반 탐지·잘못 통과·보류·인용 정확도·관계 근거 적합성을 구분한다. 사람이 검증하지 않은 합성/개발 데이터의 지표를 정답셋 성능으로 표시하지 않는다.

Neo4j 공통 조회, 실제 Qwen 모델, MCP 통신, 운영 DB 마이그레이션·운영 배포, front-v2 전체 연결, 실제 Windows 장치 렌더링·실행은 각각 별도 검증 대상이다. 이 문서는 해당 완료를 주장하지 않는다.
