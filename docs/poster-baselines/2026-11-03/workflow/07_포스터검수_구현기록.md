# 7단계 — 승인 기준 기반 포스터 검수·재검수

2026-11-03 · `feat/37-a02-pdf-registration`

**승인 기준 조회 → 기존 이미지 선택 → 별도 검수 실행 → 포스터별 입력 확인 → 독립 worker → 기계 판정·보고 → 사람 결정 → 새 수정본 재확인**을 연결했다. 이 기록은 개발 배선 시험이며 실제 Qwen·클라이언트 승인·front-v2·운영 DB 적용은 미수행이다.

## 연결한 부분

- 기존 M008 `Files`·`LocalStorage`·인증·프로젝트·CSRF와 AF003 기준, AF001 실행·단계·승인·job을 재사용했다. 새 마이그레이션·업로드 API·의존성은 추가하지 않았다.
- 승인 기준의 source run·버전·해시·승인 ID·PDF 해시를 `baseline`으로 고정했다. PDF-only 원본은 `waiting_asset`으로 보존하며 포스터마다 별도 실행을 만든다.
- 등록 포스터는 서버가 DB에서 실제 display PNG 참조를 조회한다. PDF와 포스터의 실제 바이트·해시·치수를 확인하고 공급자 호출 이후에도 다시 확인한다.
- 새 실행은 승인 이력 없이 `waiting_criteria`에서 대기한다. 포스터 입력 확인 뒤 A04_A05→A06→A07을 수행한다. A02는 승인 기준 재사용을 기록하며 재추론하지 않는다.
- 수정 요청 승인 뒤 새 image ID·새 실행을 만들고 입력 확인을 다시 받는다. 같은 이미지·중복 자식·구형 revisions 우회를 거부한다. 같은 키·같은 입력은 기존 실행으로 재조회한다.
- `registered_poster` 팀 callback `inspect_poster(request, poster)`를 추가했다. 기본 callback은 미연결 오류이며 실제 모델 성공을 흉내 내지 않는다. A07 기본은 검증된 결과의 결정적 보고다.
- 파일/기준 무결성, 권한 철회·오래된 PDF·CSRF, 완료 검사 단계 재사용, 별도 worker 프로세스, 새 API 인스턴스의 승인 기준·최종 상태 재조회를 시험했다.

## 시험 입력과 결과 해석

실제 PDF 3종을 등록하고 mock A02 초안으로부터 제목·날짜·필수 안내 3개만 명시적으로 보완했다. 다른 조건은 제외 사유를 기록했다. 보완과 승인은 `synthetic_test`이며 실제 클라이언트의 미정 회신이나 전체 36개 기준 승인이 아니다.

원본 포스터는 편집하지 않았다. 새 SVG/PNG 12장과 독립 sidecar 관측으로 배선을 시험했다. sidecar는 display 이미지 해시에 연결되고 기대값을 복사하지 않지만, 미리 설정한 합성 관측이므로 OCR·Qwen 정확도가 아니다.

| 입력 | 배선 시험 결과 |
|---|---|
| 정상 | pass 및 합성 최종 결정 저장 |
| 날짜 오류 | 공급자가 pass를 주장해도 A06 value_mismatch/fail, 일반 최종 승인 차단 |
| 필수 안내 누락 | 확인된 부재 관측/fail, 일반 최종 승인 차단 |
| 수정본 | 수정 요청 승인 → 새 실행/입력 확인 → 전체 재검사 → pass 및 합성 최종 결정 |

원본 전시(3,000×3,000)·축제(2,382×3,368)는 기존 저장 경로로 등록·실제 읽기·해시·치수를 확인했으며 모델 판정은 하지 않았다. 연주회(4,500×4,500)는 기존 1,000만 화소 제한에 따라 `IMAGE_LIMIT_EXCEEDED`로 거부되는 것을 확인했다. 제한과 원본 파일을 유지했다.

포스터 업로드는 기존 동작대로 새 asset/version ID와 version_no=1을 만든다. 수정본의 검수 계보는 프레임워크 parent_run_id로 연결하며 논리 asset의 버전 번호 증가 기능을 새로 만들지 않았다.

## 검증 기록

현재 명령·개수·정리 결과는 [검증 JSON](07_검증기록.json)을 따른다. 새 포스터 DB 시험은 13개이며 기존 63개 DB 시험과 함께 확인했다. 단위/공통 테스트는 529개, 8 subtests다. 기존 pytest asyncio 설정 및 PyMuPDF SWIG 경고가 있었다.

운영 DB·기존 업로드·실제 환경 파일은 이 단계에서 변경하지 않았다. 별도 환경/실행 스크립트/의존성 작업이 같은 워크스페이스에 있으며 보존했다. 프레임워크 검증이 해당 별도 변경이나 전체 제품 검증을 뜻하지 않는다. 원격 CI·Windows 백엔드·브라우저 렌더링 검증도 수행하지 않았다.
