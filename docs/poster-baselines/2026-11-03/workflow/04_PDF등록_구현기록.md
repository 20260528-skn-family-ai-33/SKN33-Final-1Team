# 4단계 — PDF 등록·PostgreSQL 연결

2026-11-03 · `feat/37-a02-pdf-registration`

샘플 전시·연주회·축제 PDF 3종을 **실제 파일 저장과 PostgreSQL 등록·재조회**로 연결했다. 원본 파일·검토표·기대값은 수정하지 않았다. PDF 외의 검토표 JSON·MD를 모델 입력으로 섞지 않았다. 이번 단계의 모델 호출은 0회다.

## 구현

- 기존 M008 사용자·프로젝트·멤버십·세션·CSRF·app Engine과 `LocalStorage` 저장 구현을 재사용한다.
- AF002를 통해 같은 DB에 `agent_framework.document_versions`를 추가한다. 기존 public M008와 AF001 SQL은 유지한다.
- PDF 원본은 이미지 GC와 분리한 전용 폴더에 보관한다. 원래 한글 이름은 메타데이터이며 물리 경로는 UUID다.
- 등록·새 버전·메타데이터·원본 다운로드·전체 버전 조회 API를 추가했다. 반환한 DocumentRef를 파일 접근 어댑터에서 읽을 수 있다.
- 서버가 문서·버전·파일 ID를 발급하며 페이지 수·크기·SHA-256·등록자·시각을 저장한다. 기존 버전 수정·삭제를 차단한다.
- 중복 키 재전송, 최신 부모 버전 확인, 동시 요청, 파일 변조 차단, 파일 공개 후 중단과 commit 응답 불명에 대한 확인 경로를 추가했다. 자동 DB 재실행·고아 파일 삭제는 하지 않는다.

## 검증

기존 운영 컨테이너와 다른 임시 PostgreSQL 17 컨테이너에 제한된 owner/app 계정을 만들고 무작위 `creative_checker_test_*` DB에서 검사했다. 테스트 종료 후 해당 DB를 제거하고 임시 컨테이너도 정리한다. 운영 DB·사용자 업로드·기존 `.env`에는 적용하지 않았다.

| 검사 | 결과 |
|---|---|
| 공통 프레임워크 기본 테스트 | 463 passed, DB 테스트 38 deselected, 8 subtests passed |
| 새 PDF + 기존 PostgreSQL 실행·승인·worker 통합 | 38 passed |
| 샘플 의뢰서 3종 | 각 2쪽, 실제 바이트 저장·해시·다운로드 일치 |
| 서버 인스턴스 재생성 | 같은 문서·버전 이력과 원본 재조회 |
| 보안·경쟁·실패 경로 | CSRF/세션/멤버 권한, 보관 프로젝트, 동일 키, 부모 버전 충돌, 변조, 권한 회수, commit 응답 불명, 파일 공개 중단 확인 |

로컬 pytest에서 기존 asyncio 설정 경고와 PyMuPDF SWIG deprecation 경고가 발생했으며 테스트는 통과했다. 새 의존성은 추가하지 않았다. Windows 네이티브 LocalStorage·브라우저 렌더링·원격 CI·실제 Qwen 추론은 검증하지 않았다.
