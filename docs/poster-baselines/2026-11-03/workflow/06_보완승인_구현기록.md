# 6단계 — 보완·기준 승인·재조회

2026-11-03 · `feat/37-a02-pdf-registration`

**미승인 A02 초안 → 보완·제외 이력 → 새 기준 버전 → 명시적 버전/해시 승인 → 포스터 대기 → 승인 기준 재조회**를 연결했다. 실제 클라이언트 회신과 사용자 기준 승인은 수행하지 않았다. 개발용 합성 입력을 격리 DB에서만 사용했다.

## 구현 결과

- 같은 PostgreSQL의 명시적 후속 AF003에 불변 `criteria_versions`·`criteria_approval_bindings`를 추가했다. public M008와 AF001·AF002 SQL은 유지한다.
- 기존 AF001 승인 ID·승인자·서버 시각·이벤트 기록을 재사용하고, 정확한 기준 버전·해시와 고정 근거를 연결한다.
- 원본 A02 초안·완료 단계·PDF 인용을 보존하며, 보완값은 별도 제출자·시각·출처 설명·인용 해시로 기록한다. 보완값을 PDF에서 추출한 값으로 표시하지 않는다.
- 최신 부모·해시로 보완 버전을 만들고, 명시적 검토 의사와 최신 버전·해시로 승인한다. 빈/공백 기대값·수동/미지원 조건·유효하지 않은 숫자가 남으면 차단한다.
- 승인 기록·대상 연결·근거·실행 상태는 같은 트랜잭션으로 확정한다. 승인 후 `waiting_asset`에서 대기하고 포스터 검수 job은 만들지 않는다.
- 동시 편집·승인 경쟁, 오래된 문서/기준, 변조 PDF, 권한·CSRF·요청 형식, rollback과 응답 불명 뒤 재전송을 검증했다.
- mock 또는 개발용 입력의 `synthetic` 표시를 계승한다. `human_review`라는 요청 목적만으로 실제 발주 확인이나 실모델 결과가 되지 않는다.

테스트에는 개발용 조건 한 개를 보완하고 나머지 조건의 제외 근거를 명시하는 사례가 있다. 원래 검토표 36개나 실제 클라이언트의 전체 검수 범위가 승인됐다는 결과가 아니다. 의뢰서의 관람시간·관람연령·우천 안내 실제 회신은 여전히 없다.

운영 DB와 다른 임시 PostgreSQL 17에서 무작위 테스트 DB를 생성했고, 종료 후 해당 DB와 임시 컨테이너를 제거했다. 이번 단계의 실제 Qwen 호출·GPU 생성·원격 CI·Windows 백엔드·브라우저 렌더링 검증은 수행하지 않았다. 기존 pytest asyncio 설정과 PyMuPDF SWIG 경고가 있었으며 검사는 통과했다.

작업 중 별도 환경 설정·실행 스크립트·의존성 변경이 같은 워크스페이스에 추가된 것을 확인했다. 해당 변경은 보존했고, 이번 검증은 프레임워크 범위다. 이 단계가 프로젝트 전체 환경 정리나 다른 변경의 검증을 완료했다는 뜻은 아니다.
