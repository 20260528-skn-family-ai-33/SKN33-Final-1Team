# 5단계 — A02 조건 추출 연결

2026-11-03 · `feat/37-a02-pdf-registration`

**등록 PDF → PDF-only 접수 → 별도 A02 worker → 원문 출처 검증 → PostgreSQL 미승인 초안·단계·페이지 본문 trace 저장 → 재조회**를 연결했다. 실제 Qwen 서버가 없어 DB 관통 시험은 mock 공급자를, HTTP 경계는 가짜 transport를 사용했다. 실제 모델 호출은 0회이며 기준 승인은 만들지 않았다.

## 구현 결과

- 서버가 run/criteria ID를 발급하고 등록 PDF 버전·실제 해시를 고정한다. 포스터 placeholder는 사용하지 않는다.
- 기존 AF001 실행·작업·단계 저장과 AF002 PDF 기록을 재사용했다. 새 public 스키마·AF003·의존성을 추가하지 않았다.
- 원문 페이지·블록·인용·해시와 모델 JSON의 출처를 대조한다. 문서에 없는 기대값이나 미정 값을 임의로 채운 응답을 거부한다.
- `CriteriaDraft.extraction`에 모드·요청 모델·parser·원문/응답/prompt 해시·실제 페이지 본문을 저장한다. 키·공급자 원시 HTTP 응답·추론 과정은 저장하지 않는다.
- Qwen 설정·단일 HTTP 호출 경로를 추가했다. redirect·자동 재시도·응답 보정·대체 모델은 사용하지 않는다.
- 같은 접수 키의 재전송, 설정 변경 차단, 출처 오류/파일 변조 시 초안 저장 차단, 결과 불명 후 자동 재호출 차단을 확인했다.
- 기존 PDF+포스터 승인 흐름을 유지한다. 새 PDF-only 실행의 보완·기준 승인은 6단계까지 막혀 있고 `waiting_criteria`에서 대기한다.

## 검증

| 범위 | 결과 |
|---|---|
| 공통 프레임워크 기본 테스트 | 500 passed, DB 47 deselected, 8 subtests passed |
| A02·PDF 등록·기존 PostgreSQL worker 통합 | 47 passed |
| 실제 샘플 PDF 3종 | 파일 등록→독립 worker 실행→미승인 초안 저장→새 API 인스턴스에서 원문 trace 재조회 |
| 별도 프로세스 | 실제 `worker --once` CLI 프로세스에서 mock A02 완료 |
| HTTP 경계 | 가짜 HTTP transport로 JSON 요청·응답, 오류·timeout·단일 호출 확인 |

모든 DB 검사는 운영 DB와 다른 임시 PostgreSQL 17에서 수행했고, 무작위 테스트 DB와 해당 임시 컨테이너는 제거했다. 운영 DB·기존 `.env`·원본 포스터·PDF/MD 입력·front-v2는 보존했다. 기존 pytest asyncio 설정 및 PyMuPDF SWIG 경고가 있었으며 테스트는 통과했다.
