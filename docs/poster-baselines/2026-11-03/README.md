# 포스터 검수 기준문서 기본 세트 v0.1

[3종 비교 열기](index.html) · [공통 양식 PDF](common/공통_기준문서_양식_v0.1.pdf) · [수정용 공통 MD](common/공통_기준문서_양식_v0.1.md)

새로 진행하는 A02·DB 작업: [1단계 시나리오 열람](workflow/index.html) · [시나리오 설정](workflow/01_시나리오_설계.md) · [7단계 작업 순서](workflow/작업순서.md) · [진행 기록](workflow/진행현황.json). 기존 샘플은 보존하고 후속 단계에서 새 가상 클라이언트 제출용 PDF를 작성한다.

2단계에서 작성한 [가상 클라이언트 제출용 문서 3종](workflow/client-inputs/index.html)은 각 2쪽의 PDF와 수정용 MD로 구성된다. 이후 A02 입력에는 이 제출용 PDF를 사용하며, 아래의 v0.1 기준문서는 이전 개발 자료로 보존한다.

3단계의 [추출 결과 검토표](workflow/reviewer/index.html)는 조건 후보·기대값·실제 PDF 페이지·원문 인용을 연결한 검토자용 초안이다. 검토표와 페이지 텍스트 사본은 A02 입력에서 제외한다. 사람 검토·기준 승인·실제 모델 추출 결과는 아직 없다.

## 왜 이 자료를 만들었는가

사용자가 제공한 디자인 용역 표준계약서의 **제5조: 용역의 범위 및 결과물**은 첨부 개발 세부내역 및 견적서로 용역의 내용·범위를 정하는 구조다. 표준계약서 자체에 개별 포스터의 행사명·날짜·색상·파일 규격이 들어 있는 것은 아니다.

따라서 공통 계약/과업 개요와 **포스터별 별첨 요구사항**을 연결하는 기본 문서를 만들었다. A02 PDF 조건 추출, 사람의 기준 확인, 이후 포스터 검수에 사용할 입력 초안이다. API·DB·Qwen 모델 실행을 완료한 자료가 아니다.

## 문서의 성격과 미정 사항

**완성 포스터를 AI가 관찰하여 역작성한 개발용 가상 요구사항**이다. 실제 발주처가 사전에 작성한 요구서·체결된 계약·사람이 확정한 정답이 아니다.

- `source_kind: poster_derived_synthetic`
- `human_verified: false`
- `approval_status: unapproved`
- `gold_verdict: null`

계약 당사자·대금·지급 조건·납기·시안 수·수정 횟수·권리 증빙은 미정으로 유지했다. 포스터에 적힌 행사일을 계약 납기로 사용하지 않았다. 파일 치수·형식·색상 모드는 비교 이미지에서 확인한 사실이며, 이를 기준문서에서 **개발용 규격 후보**로 제안했다. 원래 발주 조건을 확보한 것으로 취급하지 않는다.

날짜·허용 표기·시각 요소 등 별첨의 요구 수준 자체도 가상 제안이다. 원 포스터의 실제 디자인 권리자나 제작자의 의사를 대변하지 않는다. 명확하지 않은 기관 표장·세부 프로그램·가격·권리 조건을 임의로 확정하지 않았다.

## A02 입력과 이미지 검수 입력을 구분하는 방법

1. **A02 입력:** 각 `cases/<ID>/기준문서_v0.1.pdf`만 사용한다. 포스터 이미지·열람 HTML·JSON·통합 캡처를 조건 추출 입력에 추가하지 않는다.
2. **원문 대조:** 추출된 조건의 기대값·페이지·인용을 기준 PDF와 비교하고 미정·정성 항목이 자동 충족으로 바뀌지 않았는지 확인한다.
3. **사람의 기준 승인:** 초안을 보완하고 승인 대상 PDF·기준 버전·해시를 고정한다. 이 자료에는 실제 승인이 없다.
4. **포스터 검수 입력:** 승인된 기준과 `poster.jpg` 원본을 함께 사용한다. `previews/`는 열람 전용 축소본이다.
5. **재검수 준비:** 이후 문구 오타·누락·일정 변경 사례를 별도 파일로 만들고 사람이 기대 판정을 확정한다. 원본은 보존한다.

여기에는 독립적인 위반 사례나 판정 정답이 없다. 초안과 원 포스터가 일치하는 비율을 일반화 정확도·실서비스 성능으로 보고하지 않는다.

## 원본 PDF와 조항 연결

[제공된 표준계약서의 바이트 동일 사본](sources/standard-contract-2025-033.pdf)을 함께 보관했다. 제목을 정정하거나 양식을 수정하지 않았다.

| 원본 PDF 위치 | 이 세트에 참고한 구조 |
|---|---|
| 2~3쪽 전문 | 계약 개요, 시각디자인 분야, 시안·결과물·첨부 문서 |
| 6쪽 제5조① | 별첨 개발 세부내역에 용역 범위·결과물 작성 |
| 7쪽 제6조 | 변경 내용을 문서·버전으로 관리 |
| 7쪽 제7조 | 완료검사 요청, 수정·보완 및 재검사 |
| 2쪽·7~8쪽 | 제3자 창작물·지식재산권 관련 증빙을 별도 확인 |
| 11쪽 제19조② | 계약과 관련 첨부 문서를 함께 관리 |

표준계약서의 구체적인 법률 효력을 새로 판단하거나 원문을 개정한 문서가 아니다. 원본 제7조②의 검사 통지 기간 관련 문구를 개발 시스템의 자동 승인으로 구현하지 않았다. 사람의 승인·서면 합의는 별도 기록 대상이다.

## 파일 구성과 재생성

- `index.html`: 인터넷 연결 없이 볼 수 있는 3종 열람 페이지
- `common/`: 공통 양식 PDF·수정용 MD
- `cases/<ID>/`: 기준문서 PDF·수정용 MD·바이트 동일 포스터
- `sources/`: 제공된 표준계약서 사본
- `previews/`: 열람용 축소 이미지
- `baseline_data.json`: 문서 재생성용 관찰·요구사항 후보 데이터. 모델 입력이나 확정 정답이 아님
- `manifest.json`: PDF/이미지 상대 경로, 페이지 수, 해시, 미승인 상태
- `verification.json`: 파일 보존·텍스트·페이지·링크 점검 기록. 모델 성능 평가가 아님
- `tools/build.py`: PDF·MD·열람 페이지 재생성 도구

Mac·Windows 모두 폴더 구조를 유지하고 `index.html`을 열면 된다. 링크에 Mac 절대경로·외부 CDN·온라인 글꼴을 사용하지 않는다. PDF는 한글 글꼴을 포함한 텍스트 문서다.

재생성할 때는 `reportlab`, `pypdf`, `Pillow`가 설치된 Python과 한글 TrueType 글꼴이 필요하다. 열람에는 설치가 필요 없다.

```bash
python tools/build.py --font "한글글꼴의 실제 경로.ttf"
```

위 명령은 이 README가 있는 폴더에서 실행한다. 기본 글꼴 경로를 사용할 수 있으면 `--font`를 생략할 수 있다. 원본 PDF와 포스터가 이미 포함돼 있어 재생성 시 외부 파일 경로는 필요 없다.
