# Qwen 4B 구조물·복합 조건 개발 비교

B-4 프롬프트와 형식 검증 실패 시 최대 1회 재요청을 유지한다. 별도의
`4b-compact-structure-v1` 후보는 건물·구조물과 탈것을 개별 분류하고,
모호한 다리는 검토 대상으로 두며, 매체 이름만으로 위치 조건을 만들지 않는다.
모델 가중치나 기존 결과는 변경하지 않는다.

`requirements_structure_dev_v1.json`은 노출된 72건의 오류 분석에 기반해 작성한
사람 미승인 합성 개발 초안이다. `items`의 각 배열은 필드, 대상, 연산자, 값 순서다.
필요한 라벨 판단과 조건을 사람이 확인해야 한다. 원문이 모호한 경우에는
`review`가 있으며 관련 라벨 부재를 정답으로 단정하지 않는다.

실행기는 B-4와 후보를 같은 4B 모델과 같은 입력에 대해 순서대로 추론한다.
원문만 모델에 제공하고 정답은 제공하지 않는다. 각 후보에서 JSON·스키마·출처 검증
실패에만 최대 한 번 재요청한다. 처리 시간에는 재요청이 포함되며 모델 로딩과
웜업은 제외한다. 재학습·패키지 설치는 없다. 결과는 별도 디렉터리에 생성한다.

`preflight`는 데이터 구조와 기존 40건·72건과의 정규화된 **완전 일치**만 확인한다.
의미가 유사한 문장, 원문 분포, 정답 품질의 독립성은 보장하지 않는다. 이미 72건의
오류를 보고 기준을 수정했으므로 72건 재평가는 개발 확인이다. 최종 목표 달성은
별도의 미노출 실제 요구사항과 사람이 승인한 정답으로 확인해야 한다.

`comparison.csv`는 8개 요구 라벨의 판정 정확도·Macro F1과 구조물 FP/FN 및 p95,
금지·수량의 정확한 조건 재현율을 함께 표시한다. 금지·허용도 해당 라벨 요구가
존재하는 것으로 계산한다. 이는 실제 이미지에 대상이 존재하는지의 성능이 아니다.
`per_label.csv`, `per_case_label.csv`, `predictions.json`으로 상세 오류를 확인한다.
미판정은 정확도에서 오류로 계산하고 양성 미판정은 F1 계산에서 누락으로 처리한다.
모호한 정답의 불확실한 라벨은 제외한다. 기본 RunPod 명령:

```bash
bash run_structure_dev.sh preflight
bash run_structure_dev.sh run --ram-policy clean-unmapped-file --confirm-draft --resume
bash run_structure_dev.sh show-results
```
