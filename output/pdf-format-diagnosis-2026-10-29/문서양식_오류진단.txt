결론
네 파일 모두 PDF 열기·렌더링·OCR·LLM의 페이지별 응답 생성은 진행됐다. 현재 코드로 네 파일 모두 실패가 재현됐다. NEW 카드형 문서 지원 부족 외에, 앞선 브리프 대응에서 추가한 본문 누락 검사가 수원 계약서의 문구 비교 원칙에도 적용되는 회귀가 있다. 이번 요청에서는 원본 PDF와 앱 코드를 변경하지 않고 재현·진단했다.

실제 실행
기존 .venv, PaddleOCR, 로컬 qwen3.5:4b, 페이지 이미지와 OCR 텍스트 동시 입력. 네 파일을 같은 코드로 순차 1회씩 실행했다. 직접 추출 함수의 DocumentError 상태를 기록했으며 브라우저 재현이나 수정 후 검증 결과와 구분한다.

양식의 차이
수원 계약서: R01~R07, V01~V06, T01~T03의 짧은 ID, 수준, 검수 항목, 요구 내용, 판단 기준을 같은 표 행에서 읽는다. 행별 ID와 수준이 명시된다.
NEW 명세서: NEW103-C01 같은 긴 ID·항목명 줄과 실제 조건 문장이 아래 줄에 있는 카드형이다. 필수 문구/필수 시각 요소는 절 제목에 있고 각 카드에 수준 열이 없다. NEW103은 9개, NEW114와 NEW052는 각각 8개 카드다. 세 파일은 같은 카드 양식을 사용한다.

직접적인 원인 1: 긴 ID 및 카드 헤더/본문 묶음 미지원
backend/app/requirements_pdf.py의 _sources()는 짧은 알파벳+숫자 ID 뒤에 수준 또는 표 열 구분자가 오는 형태를 기대한다. NEW103-C01을 조건 ID로 인식하지 않는다. 실제 OCR에서도 NEW103-C01 | 행사명과 행사명에 다음 문구를 포함해야 합니다: ...가 서로 다른 source로 나뉘었다. 세 NEW 문서의 기본 호출에서 requirement_id가 지정된 source는 0개였다. 따라서 기준표 전용 추출/행 완전성 검사 경로를 쓰지 못한다.

직접적인 원인 2: 보완 추출의 입력 근거에서 실제 카드 조건이 빠짐
_supplement_source()의 단어·문장 패턴은 사용합니다 또는 포함하지 않... 같은 설명·부정 문장도 제작 지시로 고른다. NEW 문서의 제작 목적/작성 근거 문단이 선택된다. 반대로 2페이지 카드의 시각 요소가 있어야 합니다와 JPEG여야 합니다 같은 표현은 해당 패턴에 걸리지 않는다.
NEW103의 2페이지 보완 호출에는 p2-s17 작성 근거/자료 구분 문단 1개만 전달됐다. 페이지 이미지에는 QR 코드, 인물, JPEG, 원본 크기가 보이므로 모델은 그 조건을 다시 출력했으나, 허용된 source ID에는 실제 카드 본문이 없다. 모델이 출처 설명 ID를 인용하고 _link_source()가 실제 내용과 맞지 않음을 감지해 502로 끝난다.
NEW114·NEW052도 같은 유형이다. NEW103에서는 앞선 1페이지 보완 호출이 문구 판정이라는 검토 규칙을 새 조건으로 출력하면서, 허용되지 않은 실제 원문 대신 제작 목적 문단 ID를 붙인 오류가 먼저 발생했다.
모든 페이지의 OCR이 실패한 것이 아니다. 이미 만들어진 기본 후보가 있어도 뒤의 잘못 구성된 보완 호출이 전체 성공을 막는다. 점수 기준을 낮추거나 출처 검사를 제거하면 잘못된 근거 연결을 숨기므로 적절한 해결이 아니다.

직접적인 원인 3: 수원 계약서에도 발생하는 본문 누락 검사 회귀
수원 기본 호출은 16개 조건 후보를 생성했다. 이후 문구 비교 원칙 문단(p2-s12)이 별도 제작 지시로 선택됐다. 모델은 실제 표 조건을 다시 출력했지만 이 비교 원칙을 독립 조건으로 만들거나 별도 source로 연결하지 않았다. 최종 uncovered_sources 검사에서 1개 문단 미반영으로 전체 502 오류가 났다.
이 문단은 표의 문구를 비교할 때 적용할 공통 규칙이다. 독립된 납품물 항목과 같은 방식으로 완전성을 검사하면 안 된다. 앞선 브리프 대응에서 추가한 검사에 다른 기존 문서를 다시 대조하지 못한 회귀다. 수원 형식은 항상 정상이고 NEW 형식만 문제라고 볼 수 없다.

추가 확인 사항
- NEW114에는 제목 제45회와 세부 문구 제44회 충돌 메모가 실제로 있다. 이번 응답은 그 메모에서 상단 제목 제45회를 추가 조건 후보로 만들었다. 명세 카드 8개 대비 기본 후보가 9개다. 이 메모는 문서 확인 사항으로 보존하고 독립된 필수 조건으로 늘리지 않는 처리가 필요하다.
- NEW114의 원본 가로·세로 항목을 모델이 visual로 반환했다. 현재 항목명 매핑은 이 새 표현을 지원하지 않아 정보 조건으로 보정하지 못한다. 파일 형식도 JPEG라는 짧은 값 대신 형식이어야 합니다 문장으로 남는 응답이 있다. 이는 PDF 로딩 오류와 별도로 이후 파일 메타데이터 비교에 영향을 줄 수 있다.
- 페이지·용량 제한, 암호화, PDF 손상 문제는 아니다. NEW 파일은 각 약 74~76KB, 2페이지이며 수원 파일은 약 3.4MB, 3페이지로 현재 10MiB/12페이지 제한 안에 있다. 네 파일 모두 네이티브 텍스트 추출과 페이지 렌더링도 확인했다.
- 후보 개수는 중복·메모가 섞일 수 있어 정확도나 추출 성공 수치가 아니다. 이번 결과는 단일 실행의 오류 재현이며 수정 후 성능이나 전체 고해상도 문서 묶음의 결과가 아니다.

수정 지점 (이번 진단에서는 미구현)
1. 긴 복합 ID를 지원하고 같은 카드의 ID·항목명·아래 조건 문장을 묶는다. 절 제목의 필수/권장 수준도 명시된 범위에서만 연결한다.
2. 실제 요구조건, 공통 판정/허용 규칙, 출처·역작성 설명, 확인 메모를 구분해 보완 입력과 완전성 검사를 구성한다. 일반 단어 포함만으로 요구조건을 정하지 않는다.
3. 보완 호출에는 같은 페이지의 실제 카드 본문과 관련 규칙을 함께 준다. 페이지 이미지에는 보이지만 허용 OCR source에는 없는 조건을 출력하도록 강제하지 않는다.
4. 공통 비교 규칙은 관련 조건의 상세 기준/공통 규칙으로 보존하고 독립 조건이 없다는 이유로 전체 실패시키지 않는다. 실제 조건이 빠진 경우의 누락 검사는 유지한다.
5. 행사 제목/전시명, 전시 시작일·종료일, 기념식·박람회 시간, 참여 대상/참가비, 원본 가로·세로 같은 항목명을 검수 의미에 맞게 연결한다. 세부 시간/시작·종료 구분을 임의로 없애지 않는다.
6. 이번 네 파일과 기존 creative_brief.pdf를 함께 회귀 사례로 고정한다. 카드 조건 9/8/8개, 수원 표 조건 16개 및 예외·확인 메모·출처 제외 여부를 대조한다.
