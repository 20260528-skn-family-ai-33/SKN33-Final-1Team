# 크리에이티브체커

## Platform
한국어 Web 업무 앱. 1차 대상은 데스크톱이며 기존 front-v2 디자인을 유지한다. 모바일·태블릿 전용 화면은 이번 범위에서 제외한다.

## Users and workflow
승인자·작업자·조회자가 PDF 조건 승인 → 포스터 검사 → 수정 요청 승인 → 재제출·전체 재검수 → 최종 승인을 수행한다. 운영자가 계정을 발급한다. 한 프로젝트에 현재 기준 문서 한 개와 여러 산출물·버전을 관리한다. 기존 영상·연구 코드는 보존하며 이번 공통 프레임워크의 대상에는 포함하지 않는다.

## Stack
사용자 확정: 기존 React·Vite front-v2, FastAPI, PostgreSQL, LangGraph, MCP 도구, Qwen3.5-4B, Neo4j. PostgreSQL을 업무 원본으로 두고 Neo4j는 재구축 가능한 outbox 기반 관계 조회에 사용한다. 벡터DB·임베딩 없이 PostgreSQL·Neo4j 근거 검색과 RAG를 유지한다. 배포·실모델 연결은 후속 구현이며 개발용 프레임워크의 완료 증거와 구분한다.

## Product truth
- A03 근거 검색과 RAG를 포함한다. VectorDB·임베딩과 연구용 /modeltest는 이번 흐름에서 제외한다. A04·A05는 통합 검사 역할이다.
- A02·통합 검사·A07은 모델을 사용한다. A01 조정·A06 결과 검증·A08 재검수 연결은 코드 책임이다.
- 사람의 승인, 기계 판정, 실행 상태는 별도로 기록한다. 예외 승인은 사유·대상 조건과 원판정을 보존한다.
- 필수 조건에 확실한 위반이 있으면 fail, 남은 불확실·미지원·실패는 review, 모두 검사해 충족하면 pass. 권장 조건은 별도 표시한다.
- 새 기준·산출물 버전에 기존 승인을 자동 승계하지 않는다. 실제 모델·데이터가 없으면 준비 필요/실패를 표시한다.
- PDF와 PNG/JPEG/WEBP 포스터만 1차 연결한다. PDF 전체 페이지 처리와 출처를 기록하며 스캔 페이지도 Qwen으로 읽는다. PaddleOCR는 기본·보조·실패 시 대체 경로 모두 제외한다. 파일·페이지 제한은 실제 어댑터 연결 시 기존 제품 제한과 실측을 바탕으로 확정한다.
- 음성·정확한 연속 노출시간·미적 판단·추가 모델 학습은 초기 범위에서 제외한다.
- 보고 화면과 브라우저 인쇄/PDF 저장을 제공한다. 업로드 자료를 학습에 재사용하지 않는다.

## Experience
프로젝트 안에서 문서·조건·산출물·검수·관계·이력을 조회한다. 실제 상태와 근거를 중심으로 조작한다. 빈 상태·진행·오류·권한 부족을 구분하고 추정 진행률·정확도를 만들지 않는다. 제품 화면에 개발용 모델 선택이나 내부 구현 설명을 노출하지 않는다.

## Delivery
2026-11-02 사용자 결정과 [PDF·Qwen·RAG 계획](docs/planning/pdf-qwen-rag-workflow-plan-2026-11-02.md)을 기준으로 한다. 이 문서는 구현 기준이며 완료 증거가 아니다. 기존 작업 폴더·DB·연구 자료는 보존한다.

[공통 개발 프레임워크](docs/agent-framework/README.md)는 역할별 계약·어댑터·합성 응답·메모리 실행을 제공한다. 실제 모델·검색·M008 영속 실행·제품 인증·front-v2 연결은 담당자별 후속 작업이며 개발용 API를 제품 API로 사용하지 않는다.
