    SOURCE OF TRUTH

    PostgreSQL

    문서·기준·산출물 버전과 사람 승인 기록의 원본 저장 목표입니다. 현재 런타임은 메모리 저장입니다.

    RELATION RETRIEVAL

    Neo4j + RAG

    관계로 근거를 찾아 PostgreSQL 원문·권한·버전을 확인합니다. 벡터 검색 없이 RAG를 유지합니다.

    TOOL CONTRACT

    MCP · 일반 코드

    MCP는 도구 호출 계약입니다. 모델 자체와 다르며, 스키마·해시·상태 검증은 일반 코드가 담당합니다. 실제 MCP 연결은 후속 범위입니다.

    Graphify는 현재 코드의 함수·클래스 관계를 보여줍니다. 이 업무 흐름도 및 실제 실행 모니터와 구분해서 읽어주세요. Graphify 코드 지도 열기 ↗

    실행, 판정, 승인을 따로 읽습니다.

    모델 실행 오류는 창작물의 불합격이 아니고, 자동 검사 통과는 사람의 최종 승인이 아닙니다. 아래는 공유 폴더의 공통 런타임이 사용하는 세 축입니다.

    EXECUTION STATUS

    어디까지 진행됐나요?

    waiting_criteriawaiting_reviewwaiting_revisioncompletedfailedoutcome_unknown

    현재 개발 런타임은 사람의 대기 상태까지 표현합니다. 문서의 queued/running·영속 worker·재시도 attempt는 제품 실행기 연결 목표입니다.

    MACHINE VERDICT

    조건을 충족했나요?

    passfailreview

    근거 부족·미지원·미관측을 통과로 바꾸지 않습니다. 실행 실패는 별도로 남기며, 일부 단계 결과가 있어도 전체 검사 완료로 읽지 않습니다.

    HUMAN DECISION

    사람이 무엇을 결정했나요?

    unreviewedchanges_approvedfinal_approvedexception_approved

    최종 승인은 특정 기준·산출물 버전에만 적용합니다. 예외 승인에도 사유와 대상 조건이 필요하며 기계 판정을 바꾸지 않습니다.

    수정본은 새로운 실행입니다.

    run #1기준 vN
    산출물 v1
    →
    수정 요청사람 확정
    새 버전 제출
    →
    run #2기준 vN
    산출물 v2

    부모 실행·수정 요청과 연결하고 조건 전체를 다시 검사합니다. 현재 프레임워크는 초안을 재사용한 새 실행에서 기준 승인을 다시 받습니다. 문서의 ‘같은 승인 기준으로 검사부터 반복’과 차이가 있어 정책을 명시해야 합니다.

    실패와 확인 필요도 다릅니다.

    근거 검색 unavailable: 정상 계약으로 반환되면 확인 필요(review) 보고와 사람 검토로 이어질 수 있습니다.

    호출 예외·결과 불명: failed/outcome_unknown으로 남깁니다. 현재 코드에는 자동 재시도가 없고, 문서의 재시도 횟수·취소·복구 정책은 확정된 운영 구현이 아닙니다.

    비교 화면: 새 검수 결과를 이전 결과와 비교해야 합니다. ‘수정 완료’ 클릭 자체가 요청 해결이나 최종 승인의 증거가 되지 않습니다.

    승인 권한·영속 이력·원문 파일 검증은 제품 통합 대상입니다. 지금 보이는 설명 그래프나 합성 demo가 이를 구현·배포했다는 뜻은 아닙니다.

    문서의 맥락을 반영하고, 변경된 범위를 구분합니다.
